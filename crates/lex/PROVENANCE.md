# Provenance of `purrdf-lex`'s Unicode data and frozen vectors

The code under `src/` and `examples/` is first-party, written from the Unicode
specifications: UAX 15 (Unicode Normalization Forms), the Unicode core
specification chapter 3 (§3.11 normalization forms, §3.12 conjoining jamo
behavior) and UAX 44 (the file formats). What the crate carries from elsewhere
is data, recorded here.

## `src/unicode_tables.rs` — generated from the Unicode Character Database

- Generated by `cargo run -p purrdf-lex --example gen_unicode_tables --
  normalization` from the Unicode 17.0.0 files vendored under
  `crates/iri/unicode/17.0.0/` (`UnicodeData.txt`, `CompositionExclusions.txt`,
  `DerivedNormalizationProps.txt`); see `crates/iri/unicode/PROVENANCE.md` for
  where those files come from. The same generator writes every other Unicode
  table in the workspace, at the same version.
- License: the data is Unicode's, under Unicode-3.0, and the file carries both
  licences in its SPDX header.
- Held to the generator by `scripts/check-generated.sh`.

## Conformance data read by the tests

`tests/unicode_normalization.rs` reads `NormalizationTest.txt`,
`DerivedNormalizationProps.txt` and `UnicodeData.txt` from the same vendored
directory.

## `tests/vectors/` — frozen answers

Answers only, no code; each file's header names what it was recorded from, and
carries a SHA-256 of its body.

- `unicode_normalization_vectors.txt` — NFD, NFC, NFKD, NFKC, the combining
  class and the NFC verdict of every scalar value that is not a starter and
  its own form under all four, of the source column of every
  `NormalizationTest.txt` 17.0.0 line, and of 20,000 SplitMix64-drawn mixed
  strings, recorded from the normalization pipeline over the Unicode 17.0.0
  tables.
- `normalization_differential_vectors.txt` — NFD, NFC, NFKD and NFKC of every
  scalar value that is not its own form under all four, as the
  `unicode-normalization` 0.1.25 crate answered them (Unicode 17.0.0).

Both are replayed by `tests/unicode_normalization.rs`.
