# Text implementation and data provenance

Implementation code is first-party and offered under
`MIT OR Apache-2.0 OR MulanPSL-2.0`. The Unicode tables are generated data with
additional Unicode-3.0 terms. No third-party implementation code or new external
crate supplies the analyzer, dictionary lattice, stemming, pronunciation,
edit-distance, character retrieval or auxiliary indexes. This does not claim
that the workspace's existing dependency graph is empty.

The Unicode algorithms follow UAX 29 (word and extended-grapheme boundaries),
the Unicode core specification chapter 3 (default case algorithms), UAX 44
(property-file formats) and the published emoji sequence data. Normalization
and explicit HTML character-reference decoding use the workspace's single
lexical-layer implementations; see `../lex/PROVENANCE.md` and
`../lex/data/html/PROVENANCE.md`. Source contributors remain distinct from
normalized offsets and enclosing highlights.

## Generated Unicode data

`src/unicode_tables.rs` is generated by the first-party
`crates/lex/examples/gen_unicode_tables.rs` from pinned Unicode 17.0.0 data
under `crates/iri/unicode/17.0.0/`. Its header records both the first-party grant
and Unicode-3.0. The source data, versions, original notices and acquisition
record are documented in `../iri/unicode/PROVENANCE.md`.
`scripts/check-generated.sh` verifies the generated projection and
`scripts/check-corpus-frozen.py` freezes the upstream inputs.

## Dictionaries and artifacts

The lattice and compact radix/minimal-acyclic structures are independent
implementations from the specified graph objective and finite-language
properties. The five full ICU 78.3 dictionaries are **data**, with distinct
terms documented in `lexicons/PROVENANCE.md`, `lexicons/REUSE.toml` and the root
`license-inventory.toml`. They are excluded from this Cargo package and shipped
in a separate reproducible, fully noticed archive. The library contains only
expected artifact identities and accepts bytes from its caller; it performs no
runtime file or network access. Generated canonical dictionaries are checked
against every pinned source row and preserve minimum-cost normalization
collisions in explicit reports.

## Stemming and phonetic rules

English stemming is independently implemented from Snowball 3.1.0's prose
algorithm. The complete pinned official English input/output corpus retains its
BSD-3-Clause notice under `tests/stemming_vectors/LICENSES/`; those terms cover
the fixture data, not the implementation. Exact release identities, corpus
counts and the explicit Latin-domain divergence are recorded in
`tests/stemming_vectors/PROVENANCE.md`.

Pronunciation rules are independently implemented from Philips' Double
Metaphone description and declarative correspondence rules, with no imported,
adapted or translated implementation. The first-party synthetic probes and
selected words in `tests/phonetic_vectors/` contain frozen answers obtained
from the published Apache Commons Codec binary oracle. The reference program
is neither linked nor redistributed. Oracle identities, every-row accounting,
the declared input domain, output bounds and the algorithmic sources for the
independent scalar edit-distance kernels are documented in that directory's
`PROVENANCE.md`. Both fixture roots are frozen by the corpus gate.

## Earlier Unicode differential answers

`tests/case_fold_differential_vectors.txt` and
`tests/word_differential_vectors.txt` contain answers recorded before the
third-party Unicode crates were replaced. Their headers identify the reference
crate/version and body hashes. They contain no implementation code. The
differential tests record deliberate differences caused by Unicode version or
the explicit analysis profile. Current conformance also reads the vendored
Unicode word, grapheme, case and emoji corpora in native Rust. Focused
WebAssembly probes cover i128 scoring and decimal rendering on that target.
