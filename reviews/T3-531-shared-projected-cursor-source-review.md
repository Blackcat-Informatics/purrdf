# Owner-backed copied cursor source review — 2026-10-13

VERDICT: PASS for the bounded ownership and projection design in the current uncompiled source. This does not qualify the new code, copied-depth cost, optimized WASM floors or the complete #531 driver.

The prior native `NonNull` cursor was correctly rejected by `purrdf-sparql-eval`'s `forbid(unsafe_code)`. The revised `SharedView<T,U>` places the sole raw-pointer dereference in the existing `purrdf-lex::allocation::shared` owner home. Its public constructors project from `&T` or `&U` using a higher-ranked reference-returning closure. Safe callers cannot return a reference to a temporary outside that input lifetime; the owner retained in the resulting view keeps the immutable allocation live. `Shared::get_mut` requires a sole strong owner and therefore cannot mutate the payload while any view owns another strong reference. Moving or cloning `Shared` does not move its payload. The view drops its `Shared` owner after the projected pointer, and `SharedWorkspacePayload` drops the `CorrelatedPattern` value before its admission grant. No independent allocation or release is introduced by a projection.

`PreparedPatternCursor` selects its root from the original boxed `CorrelatedPattern`, then selects a child only from `NodeRef::for_each_child` of its current pattern. `OrdinaryPosition::Copied` owns that cursor; the active position and every suspended frame therefore retain the matching AST owner without a self-borrow. Dynamic EXISTS and LATERAL child entries use `child.owner().into_cursor()` after admitted frame construction. On completion and `OrdinaryRunner::drop`, child scope/boundary cleanup runs while the corresponding cursor and pending state still hold their immutable owners. Parent positions are retained by the frames; no root path or index is reused. The default `Borrowed` route remains a plain reference and introduces no view allocation. A copied descendant causes shallow strong-owner clones per frame/projection; quantify that control cost, but it is not another AST copy.

The generic `SharedView` intentionally has no `Send`/`Sync` implementation in this diff, because its `NonNull<U>` prevents auto-trait propagation. That is conservative and sound for the current local runner. If a compiler or worker route later requires transfer, the author must prove and narrowly implement the correct `T`/`U` bounds at the shared owner home; do not weaken safety by marking the evaluator cursor itself sendable. `Shared::clone` panics on reference-count overflow as the existing owner does; this patch adds bounded shallow clones on copied nodes and needs the original allocation/first-error controls rather than claiming a new typed overflow behavior.

The temporary `COPIED_CHILD_VISITS` probe now counts immediate child visits; the measured predecessor 20/40/80 root-prefix steps were 400/1600/6400. Require the same actual dynamic LATERAL-right and nested EXISTS inputs on compiled new source, clone/last-owner/unwind and resident-footprint checks, then original optimized package depth floors. Remove the diagnostic probe before commit. No build or source edit was made by this review.
