# #531 first-witness / streaming driver source trace (2026-10-13)

Read-only source assessment of the current dirty N checkout. This is implementation guidance, not a compiled driver or a depth result.

The ordinary `FILTER (NOT) EXISTS` definition route is `expr.rs::exists_prepared` -> `witness_wrapped` (`Slice { start: 0, length: Some(1) }`, except evidence mode) -> `binop.rs::eval_correlated` -> `eval_substituted_with::<false, false>` -> `eval_substituted_delivered` with inactive `RowDelivery=()`. The distinct `FIRST=true` specialization is the declared application's optional retry; it installs `first_pushdown` around `eval_evaluated` and restores `cap_pushdown`/`cap_at`. Do not conflate these two first-row mechanisms. The ordinary EXISTS copied Slice gets its local cap from `eval.rs::NodeBoundary::enter` / `install_local_slice_pushdown` before entering its child. Inactive `modifier.rs::eval_slice` evaluates its child and then slices a genuine admitted prefix; the child's producer must honor the cap pushdown. Completing the child without the cap or advancing past the first admitted witness before returning to Slice changes work and first-error behavior.

The active delivery route is separate. `eval.rs::RowDelivery` and `RowConsumer::deliver` check prior stop, expression barrier and `ctx.stop_check()` before callback. `eval_yielding` wraps `eval_delivered_node` in `eval_evaluated_with`; `eval_node_with` knows which operators stream. `modifier.rs::eval_slice_yielding` has an immediate zero-length result, otherwise passes each selected row to `delivery.deliver`, then returns `ControlFlow::Break` on delivery stop or length. Candidate scope deliberately uses the materializing Slice path to retain later undecided rows. `eval.rs::yield_transform` keeps admitted output blocks, transforms each *delivered child block* under its node cursor, absorbs evidence/truncation, passes its output to `delivery.deliver`, and propagates Break before requesting another child block. `expr.rs::eval_filter_with` uses that shared path when delivery is active. `eval_filter_sequence` admits schema/program/link and row checkpoint in its established order; its sequential loop charges `checkpoint.pass(ctx)` before predicate and uses `FilterRowFrame::step`/`resume`. The existing `FilterRowFrame::run` still invokes recursive `resolve`, so it is not the driver.

Smallest coherent continuation boundary: keep the existing `NodeBoundary` for each entered algebra node, a parent frame for the existing Slice/transform/application state, and one admitted suspended `FilterRowFrame` containing Linked, retained row and VM PC. At `FilterRowStep::Exists(frame, site)`, admit the parent slot **before** entering the child, retain the copied `PreparedPattern`/site owner and relevant `ScopeRestore` tokens, resolve the site to either an immediate cached/folded answer or an owned child task, and push that task. The uncached probe's `eval_evaluated(normalized)` is also a child task, not an immediate recursive escape. On child completion, run the existing EXISTS definition/probe completion and `frame.resume(value, evidence, ctx)`; resume the same row's VM before advancing the input iterator. On keep, run `with_optional_evidence`, then publish the finished block through the existing `Lift`/`delivery.deliver` boundary. Propagate `stopped()` / Break back through transform and Slice immediately; do not materialize the remaining child or enter a sibling. Finish each `NodeBoundary` only after its operator's existing result/truncation point. On error or unwind, abort entered node boundaries and discard pending row/result state, but keep every copied AST/site/source owner alive while restoring its `ScopeRestore`/ledger tokens and active-owner link in LIFO order; only then release that owner. This follows `SubstitutionFrames::unwind`.

The driver frame must retain Slice's `index`, `kept`, output `RowsBuilder`, optional schema and `Lift`; a transform frame retains its blocks and `Lift` plus the pending child block. An application frame retains the current left driver row, right-source schema/policy, emitted count, block start, and `RowDelivery` stop state; `binop.rs::eval_application_yielding` discards a truncated *entire* right block (`blocks.truncate(first_block)`) before delivery, then stops when the consumer or ceiling stops. An enum/frame-index event from child to parent is preferable to a frame borrowing another frame or storing a self-referential `RowConsumer` closure. The existing callbacks must retain their point of invocation; simply collecting child rows in a worklist and calling them after the child finishes is observably different.
