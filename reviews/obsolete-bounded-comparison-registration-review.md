# Obsolete bounded comparison registration: scoped review

**Status: FAILED for the current full gate.** Read-only assessment on `330c55f8c` of `helpers-ledger.toml`'s enforced `bigint` job, `numeric.rs`, production comparison paths, the census' test-only filtering, and the terminal `tasks/T3-470-final-make-check-corrected.log`. No source, ledger, tool, build or cache change was made.

The failure is exact: the ledger's `[[job.variant]]` at lines 904–909 names `purrdf_xsd::numeric::Decimal::cmp_exact` and says shipping XSD decimals are capped at an `i128` mantissa and 18 fractional digits. The current `numeric::Decimal` is private bounded support; its `cmp_exact` method at `numeric.rs:663–664` is `#[cfg(test)]`, and every `.cmp_exact(` call found in the crates is in the `numeric.rs` test module. Production decimal parsing returns `crate::exact::Decimal`; `XsdValue::Decimal` carries that exact type, and production ordering uses the exact comparison path (`numeric_total_cmp_using`/`exact_path::cmp_admitted`, with `exact::Decimal` implementing `Ord`). The variant's old public-bounded-value reason is false for this branch.

The unchanged census intentionally skips methods with test-only attributes (`crates/helper-census/src/source.rs::walk_impl` and `is_test_only`). `scripts/check-shared-helpers.py` requires each variant symbol to resolve and its forbidden-rule match to remain live; the terminal gate therefore correctly reports this obsolete symbol as unresolved. Moving the method out of `#[cfg(test)]`, adding a same-named shipping wrapper, or redirecting it toward an unrelated exact comparison would create a production duplicate or false exception solely to placate registration. Editing test call sites alone also leaves the ledger failure intact. No production consumer needs this bounded comparison.

**Smallest truthful correction, if ledger-data maintenance is authorized:** delete only this obsolete `[[job.variant]]` block (symbol, file, detector, criterion, anchor and false reason) from the enforced `bigint` job. Keep the job, its forbidden-name detector, other live variants and checker unchanged. The check will continue to reject a future shipping `cmp_exact` copy; removing an exemption for a nonexistent shipping symbol tightens rather than weakens that guard. Test-only comparison can remain for its existing regression cases; removing it later is optional and does not repair today's stale registration by itself.
