# #531 LATERAL shape correction

VERDICT: PRIOR LEFT-DESCENT CANDIDATE DOES NOT TARGET THE REPEATED FRAME; FINAL-MERGE EXTRACTION IS SOURCE-VALID BUT UNMEASURED.

Read-only correction to `issue-531-stack-floor-source-investigation.md`. Current checkout HEAD `838667cabf2d86a3a9b4d4e121694faeaabc127f`; no production edits, builds or budget/floor changes. The actual `crates/rdf-wasm/js/tests/query.test.mjs::nestedLateral` uses `nestedAround("?s <p> ?o LATERAL { ", depth)`: each level is a right-nested LATERAL. Its repeated descent happens after the left BGP has answered, inside `binop.rs::eval_application`'s per-row `eval_correlated` or `eval_deferred_lateral` call (roughly lines 1135–1160). The previous proposed split before `eval_evaluated(left, ctx)` would leave the large post-left finisher active over this recursive right edge, and might add another frame. It should not be used as the repair for this measured case.

The exact production state during right descent is: the admitted `Lift` for the current node; `l` and `left_schema` because each driver row and eventual output schema remain needed; a cloned optional deferred site; `right_schema` accumulated from *completed* right blocks; `per_row` of already completed `(driver, RHS bag)` pairs; `emitted` for declared application caps; and the current driver. Those are legitimately live. A truncated RHS must still be absorbed at child 1 and its in-flight driver block discarded before final output, so streaming away or discarding that state would alter the certificate and multiplicity law. Endpoint admission before the first RHS call and the property-function interception before the generic loop also stay where they are.

The final output assembly in `binop.rs` roughly lines 1185–1225 has a different lifetime: `out = left_schema.union_admitted(right_schema)`, `right_to_out_map`, `cell_row_ceiling`, `RowsBuilder`, per-pair compatibility, `merge_application_row` and final `lift.finish`. None can execute until the right-child collection loop returns. A bounded extraction is to move exactly this suffix to a separate `#[inline(never)]` helper called **after** the loop. Transfer `Lift`, `left_schema`, `right_schema` and the admitted `per_row` by value, with `M::DECLARED` supplied as the same static mode; do not clone or re-intern rows. Calculate `cell_row_ceiling` inside the suffix at the same late point. Keep the loop's `right_schema.push_admitted`, `per_row.push`, cap break, and `lift.absorb(1, truncated)` unchanged. The helper then performs the existing schema union and pair loop in source order, uses the original compatibility condition and `merge_application_row` evidence conjunction, observes the cell limit before building the next emitted row, and calls `lift.finish` once. This has a valid ownership boundary and can remove final-merge temporaries from the frame held over the right-nested call. It does not prove the compiler currently allocates those temporaries simultaneously or that enough bytes are saved.

Root's retained optimized-package control `issue-531-current-stack-byte-controls.md` measures an exact 4,080-byte LATERAL slope per written level from depth 1–32, and 7,104-byte EXISTS slopes from depth 2; it cannot attribute individual function frames. The final-merge extraction targets only the LATERAL slope. It is not a plausible repair for synchronous/job and FILTER NOT EXISTS at 134/133, whose recursive edge goes through `expr.rs::eval_filter_sequence` and `exists_prepared`. A new optimized package must show a reduced LATERAL stack-byte slope and the unchanged deepest-answer/next-refusal floor, exact rows/evidence/error/cap controls, before this candidate can be credited. No pass or completion is claimed.
