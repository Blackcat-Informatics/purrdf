## Exact recursive ownership

`crates/sparql-eval/src/eval.rs::eval_evaluated_with` checks the stack and brackets every node with local Slice, evidence and first-fault restoration. `eval_evaluated_inner_with` retains the node cursor through `evaluate(ctx)` because later output charging, certificate conversion and stop observation must occur at that same node. `eval_node_with`/`dispatch_node` route algebra variants. Those owners cannot simply be dropped before descent without changing first-fault or governor attribution. `Evaluated` is large because `SolutionSeq` carries `RowBag` metadata and `Truncation` carries both it and a certificate; replacing it with an unadmitted `Box` is not a valid shortcut.

For LATERAL, `crates/sparql-eval/src/binop.rs::eval_lateral` enters `eval_application` (around line 1050). `eval_application` constructs `Lift` and calls `eval_evaluated(left, ctx)` at its start, then in the *same function* handles property-function interception, endpoint admission, deferred-site lookup, per-row right evaluation, schema union and pair merging (roughly lines 1060–1225). The latter locals have no value before the left child returns. This is the clearest removable overlap between a recursive call and a large operator frame. `finish_left_join` around line 2162 is an existing precedent: it takes the returned `Evaluated` so OPTIONAL's post-driver state is out of the left-recursion frame. A bounded analogous change would leave the current `Lift::at_admitted` and `lift.absorb(0, eval_evaluated(left, ctx)?)`/truncation exits in a small `eval_application` entry and move the current right-side body to an out-of-line `finish_application(node, right, mode, lift, l, ctx)`. Passing `Lift` and the complete `SolutionSeq` by value preserves their ownership, original row order/multiplicity, per-row truncation discard, endpoint admission before any remote request, evidence composition and all existing charges. It does not change the right-side recursion itself. It is a source-valid candidate, **not a measured assertion** that the 47-level LATERAL shortfall disappears; wasm frame layout must verify that this split actually reduces the frame held over left descent.

FILTER NOT EXISTS has a distinct recursive route. `expr.rs::eval_filter` evaluates its data child, then calls `eval_filter_sequence`; its sequential row loop keeps `seq`, `Lift`, `RowCheckpoint`, VM `Linked` and an output `RowsBuilder` while `linked.filter` reaches `exists_recorded`/`exists_prepared`, then `binop::eval_correlated` and a substituted `eval_evaluated`. The prepared site and memo key remain live to decide/record the answer after that recursion. The expression barrier is deliberately shared and must withhold the complete filter output when an inner EXISTS trips. The `eval_filter_sequence` body is `#[inline(always)]` and includes both sequential and forked loop machinery, but source alone does not establish how much of its forked branch the optimized wasm retains in the sequential frame. Merely adding another helper or boxing `Evaluated` could add a frame or change admission while failing the floor. Splitting the sequential/forked filter bodies may be justified **only after** measuring this frame at `linked.filter` → `exists_recorded` → `eval_correlated`; preserving the current per-row charge, first-error and barrier transfer is required.

The synchronous/job equality (134/134) points to the shared evaluator recursion, not an async-only stack-region defect. The LATERAL and NOT EXISTS tests use different recursive operator paths; a LATERAL-only split cannot resolve the two EXISTS floors. The broad common `eval_evaluated_with` slot was already reduced by the earlier extraction and should not be redesigned again without a specific measured retained slot. The floor tests themselves are actual whole-package acceptance, and the retained `npm run check` remains failed even though the selected #470 numeric tests and deep async case pass.
