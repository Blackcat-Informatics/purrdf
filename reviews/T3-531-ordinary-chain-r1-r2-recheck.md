# #531 ordinary-chain R1/R2 source recheck (2026-10-13)

Scoped source review of N's ordinary-chain correction after the j1 library compile recorded in `tasks/T3-531-ordinary-worklist-compile-receipt.md`. Revised verdict: **R1 copied-Join ordering was found, then corrected on source; R2 addressed for this ordinary-chain owner on source.** The later R1 correction is uncompiled in this review. No runtime or optimized WASM floor claim.

R1: `eval_ordinary_chain` calls `precomputed_evaluated(current, runner.ctx)` after `NodeBoundary::enter/start` and before matching Filter/Slice or suspending any graph child. The same prelude is called by `eval_numbered_node` and `eval_node_with`; it performs expanded-dictionary lookup first, then `shapes::eval_shape`. This fixes the original omission for Filter/Slice, but the *copied Join* path has a new ordering defect. Published `eval_evaluated` built `Tree::build_admitted` and entered `positive_shape` before `eval_node_with` reached the precomputed lookup. Current `eval_numbered_node` runs the lookup before `dispatch_numbered_node` builds/enters the temporary shape. A custom shape provider offered on an unnumbered copied Join can execute without the former positive-shape context: `shapes/runtime.rs::NativeRuntime::input` evaluates a child via `eval_evaluated`, whose positive-region decision can read that context. Even if the provider never requests a child, the original tree admission/error preceded provider offer and can affect bounded first-error behavior. Restore the guard around the prelude and dispatch for this copied Join in the one shared home; do not duplicate the dictionary/Shapes algorithm. `NodeBoundary::enter` still installs local Slice pushdown before child entry; its finish/abort removes only the local cap. `AdmittedVec::new` creates an empty Vec without a backing allocation and the first suspended parent is held inline; nested parents use `reserve_next` before child entry. Admission timing has an additional worklist slot at deeper nesting, which needs bounded runtime controls; it is not an unpriced default buffer.

R2: `OrdinaryRunner` owns the active `NodeBoundary`, inline first parent and admitted parent stack. Its `Drop` calls `abort` for active, then `pending.pop()` down to `first.take()`, giving inner-to-outer cursor/search/local-cap restoration on panic. Normal completion moves each parent boundary to active, calls the original `finish_filter_child` or `finish_slice`, then `finish_active`; `NodeBoundary::finish` calls `abort` even when the computation returns an error and checks `dataset.read_error()` before returning that error, retaining the original source-read precedence. If a completion panics, active remains owned for Drop; if a nested reserve fails, current boundary is finished with that error before parents. Pattern/after inputs are borrowed or live in frames through boundary abort; a surrounding `SubstitutionRunner` retains any copied AST owner until this nested runner has dropped. This review does not prove the later VM EXISTS/LATERAL frame owner's unwind behavior.

Affected runtime controls to re-run after the source correction: real Shapes provider/dictionary selection for Filter and Slice; a custom shape offered on an unnumbered copied Join that requests a child input and sees original positive numbering/admission; Slice local-cap/first-witness and truncation/evidence outcomes; dataset read-error versus operator error; and a caught unwind while at least two ordinary parents are installed with nonempty search/cap state. The existing positive-numbering tests near `eval.rs:5871–5990` cover part of context restoration but do not exercise the changed custom-provider order. No blanket build requested or run here. The VM EXISTS suspension and LATERAL child route are still recursive, so the three original package depth floors remain open.
