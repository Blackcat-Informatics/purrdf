## Design disposition

The common helper should keep an inclusive row bound only when the outer `Vec<Solution<D::Id>>` allocation layout for that row count is valid. All consumers examined materialize those row records. An invalid layout prevents a valid retained bag from reaching the bound, so its next-row cell refusal is unreachable. Keep every layout-valid bound, including the exact largest valid count and zero; zero columns remain zero cells. This is a reachability rule for bookkeeping and explicit large limits alike. It adds neither a BGP shipping exception nor a separate metered engine.

Keep engaged observations, actual state limits and forecast admission unchanged. In particular, `Engine::admit_refusal` still compares a statistical estimate to the actual cell vector when engaged: a saturated estimate can be refused under the bookkeeping sentinel before evaluation. Removing that comparison would be a real behavior change. A BGP stop signal independently retains its sequential observation boundary. Existing aggregate reduction geometry, numeric charges and source-order governor replay remain unchanged.

The smallest coherent allocation repair uses the existing join reservation and fallible parallel machinery:

1. Reserve fallibly before every new output push in filtered OPTIONAL's worker and sequential-resume closure, covering keyed, wild, full-scan and unmatched-padding emissions. Keep predicate evaluation before accepted-output reservation as on the existing filtered sequential path. Retain the finite branch's before-next-row cell checks.
2. Convert eligible ordinary hash and unfiltered outer joins to the existing fallible chunk map with unit state/harvest, keeping the same match/padding loops and source-order flattening. Use the existing fallible row reservation before emission. Do not preserve bogus bookkeeping geometry merely to hide the failure-channel difference.
3. Make output concatenation in the existing fallible chunk/block homes use checked capacity arithmetic and fallible reserve. Inspect source-ordered recorded errors **before** computing/reserving the joined output, so an allocation attempt cannot mask an already-recorded operational error. Preserve the first source error and keep harvests aligned with successful source blocks/chunks. Current code allocates the joined output before `chunk_result?`/`outcome?`; this is a concrete part of the planned repair.

The allocation operation should have one home reused by the affected callers; move or generalize the existing reservation body only as its actual callers require. Do not copy a second reservation implementation or introduce configuration-dependent allocation paths. The contract concerns typed output allocation failure, not a new promise that every evaluator metadata allocation is fallible.
