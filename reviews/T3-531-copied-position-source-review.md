# #531 copied-position groundwork source review — 2026-10-13

**VERDICT: REVISE the bounded slice.** Reviewed only `sparql-algebra/src/walk.rs::NodeRef::at_path`, `sparql-eval/src/eval.rs::OrdinaryPosition`/`OrdinaryRunner`/`eval_ordinary_chain`/`finish_ordinary_active`, and `vm/mod.rs::ExpressionOwner::expression` on the main-based #531 checkout. The owner's second standard j1 library check passed; that proves these declarations compile, not child suspension/runtime or the original package floors. No build or source edit was run for this review.

The shared traversal home is correct for identity and order: `NodeRef::at_path` uses the existing `for_each_child`, whose Filter order is expression then inner pattern (ordinal 1) and Slice order is inner pattern (ordinal 0). `OrdinaryPosition::copied_child` locates the actual child by pointer within that owner and admits its ordinal before moving the active boundary into a parent frame. The retained `PreparedPattern` clone keeps an immutable root alive while those ordinals are used. `Borrowed` returns the original reference, with empty `AdmittedVec::new` path/pending buffers and inline first parent; no path backing allocation occurs on that direct route. The VM copied-expression resolver now calls this same `at_path` home rather than a second walker. `OrdinaryRunner::Drop` aborts active and then pending/inline parents inner-to-outer while its copied owner is still live. Existing `finish_ordinary_active` retains `NodeBoundary::finish`'s read-error precedence and clears `active` only after that call returns; if it unwinds, Drop can abort the still-active boundary.

Two issues remain in this precise slice:

1. After `runner.pop()` removes an entered parent, the code truncates the path and calls `position.pattern(...)?` **before** placing that parent's `boundary` into `runner.active`. If the typed path-resolution error is taken, or a panic occurs there, that boundary is dropped without `NodeBoundary::abort`; the runner can abort only its remaining frames. The current immutable root and previously validated path make this branch unreachable on valid, unchanged input, so this is **not** a demonstrated runtime failure. It is still a real hole in the defined error/unwind path. Install `active = Some(boundary)` immediately after pop/destructure, before path truncation/resolution, so Drop covers every exit. Leave the copied owner live through abort and outer `ScopeRestore` restoration.
2. `OrdinaryPosition::pattern` resolves each copied position from the root by calling `at_path` over its entire prefix on **every** descent and each parent completion. For a depth-`d` copied Filter/Slice chain, this executes Θ(`d²`) child visits even though the path itself is admitted and each node immutable; `copied_child` adds only constant child work per such node. VM copied-expression resolution also performs a full-root walk per resolved site, using the shared implementation. This is an actual computation cost of the current source, not a measured throughput regression. Before claiming scalable deep execution, add a same-input visit/growth control and remove repeated root-prefix scans at the ordinary chain's production traversal home if they dominate. A retained owner outside the movable frame plus a borrowed current-node cursor, or an admitted one-time node index, could bound lookup; either choice must preserve owner lifetime and avoid a second traversal body. No numeric byte or floor gain is inferred.

Path admission on copied descent and failure cleanup otherwise look coherent: `path.push` can fail before the current active boundary moves; the runner then owns it and Drop aborts it. A stale path's typed error is not swallowed. This review does not cover the subsequent VM EXISTS child task, correlated LATERAL, native result parity, optimized package or hosted qualification.
