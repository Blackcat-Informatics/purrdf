# #531 compact continuation design review (2026-10-13)

**Source-design verdict: conditionally coherent, unimplemented and unqualified.** I reviewed clean N source `330c55f8c` and `tasks/T3-531-compact-continuation-design.md`; no production diff, build or stack result exists for this candidate. The retained release function indices do not prove which Rust locals own the measured bytes. The design targets state that source shows remains live during the actual FILTER and right-nested LATERAL recursive calls; it still requires source, allocation and optimized-package validation.

The existing `workspace::WorkspaceBox<T>` is the right shared owner. Its `value: Box<T>` precedes `frame: LexicalFrame`, so the payload and its owned children are destroyed before the box's original admission is released. `Memory::boxed` charges `Layout<T>` before the fallible allocation and preserves a typed first refusal. The continuation's pre-existing row, schema, VM, checkpoint and buffer payloads must keep their own original grants; charging their capacities again in `WorkspaceBox` would double-count. Do not add a second generic box/grant wrapper or a bare `Box<T>` extraction route.

**Constructor boundary is material.** `WorkspaceBox::new_admitted(value, ...)` takes `value` by value; constructing a large value in a recursive caller and merely boxing it there can leave its stack slot in that caller's fixed WASM frame. The revised design correctly requires an out-of-line preparation function at each operator home that creates the large state, calls `WorkspaceBox::new_admitted`, and returns only the compact owner **before** the recursive child call. For FILTER, this function must perform existing checkpoint creation → `program_at` → `Linked::link_admitted` in that order; building `Linked` in `eval_filter_sequence` before calling the factory would miss the intended boundary. For LATERAL, build `left_schema`, `right_schema` and the admitted `per_row` capacity inside preparation after the original left evaluation, property-function early return, endpoint admission and deferred-site check. A constructor that calls `linked.filter` or evaluates a right child before returning would keep its own construction frame live across recursion and fail the design. Even a correct source boundary is only a hypothesis until the optimized package shows its actual frame.

**FILTER ownership and semantics.** Preserve the one ordinary consuming `seq.rows` loop. Store its consuming iterator, `Linked`, checkpoint, schema, `Lift` and `RowsBuilder` in the admitted owner; `checkpoint.pass` must precede `linked.filter`, and a kept original row receives exactly the same optional evidence before `push_row`. Do not clone row cells or the VM to populate the box. The native fork path retains its existing worker snapshot, deferred checkpoint, ordered commit, witness harvest/absorption, source-order resume and `RowsBuilder::from_storage`. The common expression barrier must still precede `lift.finish`. `Lift::finish` and `RowsBuilder::finish` consume their values, so a boxed field needs a single `Option::take` at finalization (or an equivalent safe move with the original grant retained), never a bare-box extraction. On a barrier or error, any untaken payload and its grants drop with the box; no partial answer is published.

**LATERAL ownership and semantics.** Keep the property-function interception before the new box, and preserve endpoint admission before any right evaluation. The owner must retain the left bag and `Lift`, left/right schema state and admitted `per_row` buffer across each right child. Select declared policy, deferred slot or `eval_correlated` in the same order; append only a complete right block, keep the current row's incomplete block out on truncation, and let the first operational error propagate. `lift.absorb(1, truncated)` must occur before the final merge, and `Lift` is taken exactly once for `finish`/`withheld`. The one existing schema union and `merge_application_row` body remain the output path; no duplicate join or compatibility loop. Do not move `per_row` into an unadmitted buffer or detach the left bag from its owner. Early returns must drop the boxed payload before its frame grant, including on typed box refusal.

**Cost and proof.** This adds at least one actual box allocation and one physical control admission per ordinary FILTER and LATERAL operator invocation, even on shallow successful queries. That is a material default cost, not free because the stack floor may improve. Measure allocation count/live bytes and fixed-work complete-query instructions on the original inputs, plus non-exclusive throughput under the user's timing constraint; state shared-host interference rather than claiming exclusive timing. Verify exact answers, multiplicity, evidence, first-error and refusal order, original low-budget pre-allocation refusal, and last-owner release. A fresh standard-directory optimized package must then satisfy the unchanged LATERAL, NOT EXISTS and synchronous SELECT depth floors and retain typed refusal at the next level. If fixed WASM frames or original floors do not improve, the candidate is not a #531 correction. No code acceptance or merge conclusion follows from this source-design review.

## Concrete two-file draft readback (2026-10-13)

I read N's uncompiled `expr.rs`/`binop.rs` diff (+123/−20 at review time). **Material FILTER boundary gap:** `FilterContinuation` stores `input: RowBag`, but the sequential `for row in std::mem::take(input)` constructs the consuming `RowBagIntoIter` in the recursively active `eval_filter_sequence` caller. The iterator's `BagIteration` state, including the shared/resident row owner, is therefore not behind the box as the design claims. `RowBag::default` itself is an empty resident bag and adds no allocation, and taking the original bag retains row/evidence order; this is a frame-ownership finding, not an observed semantic failure. A coherent full candidate would construct the sequential iterator in the no-inline preparation function, store it in the boxed state, and advance it by mutable reference while keeping the native fork path's borrowed `RowBag` in its separate state. Do this without a second sequential loop, copied row cells, or a default-path adapter allocation. Alternatively, explicitly narrow the hypothesis to boxed VM/checkpoint/builder and measure that source as such; do not claim the iterator moved.

The two no-inline factories otherwise build the intended state before their recursive calls: FILTER performs schema clone → checkpoint → program lookup → link → output-builder creation → box admission; LATERAL performs left-schema clone → right-schema default → admitted `per_row` capacity → box admission after the existing early checks. The new box refusal is necessarily an additional possible first failure at those positions; it occurs before any FILTER predicate or LATERAL right child runs, so it does not publish a half-complete row. `RowsBuilder::finish` and `Lift::finish` are reached through one `Option::take`; the LATERAL truncated-child `absorb` remains before the merge. `deferred` is still selected before the first right child and the original declared/deferred/correlated choice remains in its loop. The `SharedSchema` clone after FILTER's barrier is a shared-owner clone with no physical schema copy, but is still an added refcount operation to account for in instruction controls.

Field destruction order changes: original local scopes dropped later-created buffers before earlier `Lift`/left data; `FilterContinuation` declares `input, schema, lift, checkpoint, linked, output`, and `ApplicationContinuation` declares `left, lift, left_schema, right_schema, per_row, deferred`, so Rust drops those fields in declaration order, then `WorkspaceBox`'s `LexicalFrame`. Each carrier is separately owned/admitted, and no source borrow from an earlier-dropped field into a later one is apparent; thus this is not a demonstrated answer/error defect. It does mean an error-path live-byte/release control is required. In particular, demonstrate final box and nested payload grants reach zero after refusal, normal completion and last-owner drop, rather than inferring release solely from the struct layout. The generic `WorkspaceBox` allocator failure currently names `native trait payload`; that is typed but not operator-specific, so check its host diagnostic against #531's actionable-failure contract rather than silently adding a duplicate box owner.

**Current source-review disposition: hold build-based qualification as a complete compact-continuation candidate until the iterator claim is corrected or expressly narrowed.** The rest of the draft is internally coherent enough for focused compiler feedback after formatting; no byte, floor or overall #531 result follows from this review.

### Revised diff: iterator moved; release timing still needs correction

N revised the uncompiled FILTER state to `FilterInput::{Forked(RowBag), Sequential(RowBagIntoIter)}` and advances the sequential iterator by mutable reference. This corrects the earlier frame-placement finding without a duplicate row loop or default-path adapter allocation. Its box fields now follow the old reverse-local drop order more closely, as do LATERAL's. The `WorkspaceBox` outer box still drops before its frame grant; the revised LATERAL deferred borrow and `Lift::take` retain the old strategy and finalization order. Those source paths have no further demonstrated ownership defect.

**New material lifetime finding:** The original `for row in seq.rows` drops its consuming `RowBagIntoIter` at loop exit, including on `checkpoint.pass` break, *before* `RowsBuilder::finish` and barrier/finalization. The revised boxed `FilterInput::Sequential` remains held until `state` drops at function return. A shared input bag or unconsumed rows therefore retain their original grants through `output.take().finish()`, where new output admission may occur. Under a tight workspace budget, this can turn an original successful prefix into an earlier physical refusal, even though row order and answers otherwise match. Make the boxed sequential iterator consumable once, for example `Option<RowBagIntoIter>`, iterate through its mutable borrow, then explicitly take and drop it immediately after the loop and **before** output finish. Keep the iterator behind the box during `linked.filter`; on a hard evaluation error the whole state still drops during unwinding. Do not substitute a second row-copying loop. This is a source-level admission/first-failure concern, not an observed test failure.

Once that lifetime is restored, the revised source is coherent for focused compile and runtime feedback. It still has a new per-operator box admission, a cheap shared-schema refcount clone on FILTER completion, and no measured stack or floor improvement.

### Final current-diff readback before focused compile

N's next revision uses `FilterInput::Sequential(Some(RowBagIntoIter))`, iterates through `as_mut()` while the iterator stays in the boxed continuation, and calls `drop(input.take())` immediately after the row loop and before `output.take().finish()`. That restores the original release point of unconsumed input rows and their grants. The forked variant retains its original bag and borrowed worker/resume path. Both boxes now declare fields in an order closer to the original reverse-local cleanup. LATERAL's `deferred.as_ref()` and `Lift` take preserve the existing strategy/finish sequence. I find **no remaining material source ownership or first-error-order blocker to focused compile feedback** in the current diff. This is not a compiled or measured approval: one new box allocation/admission per operator, the extra FILTER shared-schema refcount clone, and the actual optimized stack/floor result remain open. The latter clone is avoidable with a safe one-time schema take if practical; otherwise it belongs in the fixed-work instruction control.
