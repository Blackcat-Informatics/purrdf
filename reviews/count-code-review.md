## C1: count identity and statistics can disagree

**Resolved. Original finding:** `CountReport` exposed mutable context, raw samples and estimates (original `estimates.rs:226–233`). `to_json` wrote fixed work from `estimates.iterations_per_sample`, while `compare` admitted a record by `context` equality (original `estimates.rs:269–283`). A report constructed with work 5 could have its context changed to work 1 while its samples remained normalized by 5; comparison then accepted the identity of a work-1 record. Serialization recorded a different work value from the in-memory identity.

The schema-2 reader checks raw totals against normalized samples, but not the saved median, MAD, interval or outliers (`estimates.rs:603–608`). A stored statistic can disagree with the exact samples while parsing succeeds. Relative `Change::between` recomputes its own comparison from samples; direct reported medians and the numeric median-ratio criterion still require a consistent record.

The adopted narrow repair makes all report fields private and exposes only immutable context/raw/estimates references (`estimates.rs:227–267`). Construction therefore preserves fixed-work normalization. Schema 2 requires and writes `bootstrap_seed`; its reader reconstructs through the same `from_samples` and requires complete Estimates equality (`estimates.rs:616–620`), including median, MAD, interval, confidence, resample count, fixed work, projected samples, outliers and throughput. Schema 1 retains its former member set and parsing/writing behavior. `raw/count-testkit-consistency.log` passes the round-trip and changed raw/median/MAD/CI refusal controls. No second statistical implementation was added.

## C2: signed or zero-baseline allocation values cannot use the positive-count ratio

**Resolved. Original finding:** `CountReport::from_samples` deliberately accepts negative RetainedBytes, while the original `compare` sent every unit through the existing relative-change calculation (original `estimates.rs:247,280`; `stats.rs:184–198`). Constant retained-byte samples changing from −10 to −5 produced relative point/interval −0.5 and an Improved classification, despite the actual 5-byte retention increase. A zero denominator also cannot yield a finite relative comparison. The amended contract requires every allocation increase to remain visible.

The adopted `compare` refuses any baseline raw sample at or below zero before entering bootstrap ratios (`estimates.rs:284–286`), with an actionable instruction to report signed/zero-baseline changes in absolute units. This also keeps every possible resampled denominator positive. Exact signed samples and their statistical projection remain available through immutable accessors; legacy elapsed statistics are unchanged. `raw/count-testkit-consistency.log` passes the −10→−5 and zero-baseline refusal controls. The allocation caller must retain actual values/absolute increases rather than suppress this error; that wiring belongs to the target review.

## Inspected implementation and executed evidence

The native collector starts one fresh `perf stat` invocation per sample, creates a new receipt directory, selects one `instructions:u` event with `--no-scale`, `--no-big-num`, `-v` and `--delay=-1`, and preserves CSV, verbose output and workload stdout. It hard-fails missing prerequisites or unsuccessful child execution. After the concrete output-placement correction below, the parser selects exactly one CSV event row by its third comma-separated field and requires exactly one exact tuple across both retained streams; their counts/running metadata must agree, enabled must equal running and be positive, and displayed percentage must be 100.00. It rejects unavailable/partial/rounded multiplexed records. Fresh process totals cannot be cumulative samples from the same invocation.

The shared Linux controller validates both environment paths together, provides a required-counter entry point, writes Enable/Disable and verifies all five `ack\n\0` bytes. Nonblocking I/O and its bounded five-second acknowledgement deadline produce errors for absent, short, malformed or missing acknowledgements (`counter.rs:82–139`). The old hash controller body is removed; the hash workload calls this home around its existing selected region (`scripts/hash-workloads.rs:246–261`). This preserves the hash lane's explicit non-count mode without authorizing a counter-free instruction claim. Actual governor count mode must use the required entry point.

Schema 2 names instructions, allocation calls, requested bytes, retained bytes and peak bytes explicitly. Its construction checks nonzero work/workers/nonempty samples, names fixture/boundary, preserves raw signed integers and uses the existing statistics. Comparison rejects unequal unit/work/thread/fixture/boundary contexts when those records are internally consistent. Schema 1 retains its ns member set; the two readers refuse each other's schema. The shared Store's existing path encoder and atomic write home are reused; `save_report` resolves the explicit `PURRDF_BENCH_HOME` and delegates to that writer. The later adopted `read_report` resolves the same Store/record_path and requires a present schema-2 record through the validated reader. Target namespaces and pending same-harness baseline qualification are recorded in `reviews/count-target-review.md`.
