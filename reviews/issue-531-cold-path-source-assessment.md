# #531 cold post-child paths: bounded source assessment (2026-10-13)

**Verdict: plausible frame-isolation mechanisms, but weak standalone #531 corrections. No source patch is warranted yet from the current evidence.** This is read-only against clean N source `330c55f8c`. The admitted compact-continuation candidate was rejected and reverted: its exact linked module passed the synchronous SELECT floor but failed right-nested LATERAL at 233 < 281 and FILTER NOT EXISTS at 145 < 180; its measured slopes were 4,112 and 6,560 bytes/level. Those are candidate-artifact observations, not a new source baseline. See `tasks/T3-531-compact-continuation-disposition.md`.

`eval::eval_evaluated_with` checks the workspace and stack, installs a local Slice cap, checks source errors and optionally pushes a search-evidence frame, then calls `eval_evaluated_inner_with(pattern, ctx, evaluate)`. That call is on the recursive path. Its post-call code must pop search evidence, clear a local cap, recheck the source error, and combine/propagate evidence before returning. An out-of-line *post-child* finisher would run only after recursion returns, unlike the failed `eval_filter_sequence` no-inline experiment whose out-of-line body itself still called `linked.filter` recursively. It could remove post-call temporaries from the caller's fixed WASM frame without adding an allocation or duplicating a row loop. Source alone does not show whether the release compiler currently reserves those temporaries across the child call. A single finisher called for every graph node also adds a default call/argument path and may move a large `Result<Evaluated>` value; extracting only the evidence branch while leaving cap and read-error cleanup duplicated would violate the one-home logic and risks changing the established pop → cap reset → read-error → evidence order. The common cleanup's `local_cap` and `tracking_search` flags remain necessary over the child call in any version. This is a weaker candidate until actual optimized frame/live-range evidence identifies removable bytes.

`vm::Linked::filter` calls `self.ebv`, which reaches `Linked::term` and its suspended EXISTS evaluation. Only **after** that recursive call returns does it either take the ordinary no-evidence fast return or assemble evidence. The cold work comprises `self.result_evidence()` and the existing `expr::filter_evidence` implementation. Keeping those existing bodies out of line, if the optimizer currently inlines them into `Linked::filter`, is a coherent narrow mechanism: no new ordinary allocation, no duplicate FILTER loop, and no new call on the ordinary fast path. It would preserve the existing order of EBV error, fast-return condition, evidence lock/poison, source gap and combination. But there is no verified current release inlining/live-range proof. If the cold bodies are already distinct calls, another `#[inline(never)]` has no causal basis; if the 656-byte diagnostic FILTER frame is mostly the live recursive call's own result/VM state, moving cold code will not remove it. The source owner is clear; the unnamed release frame identity and removable portion remain inferred.

These paths also do not credibly close all depth debt alone. In the instrumented release diagnostic, the corresponding recurring frame reservations are 336 bytes on the `eval_evaluated_with`-anchored region and 656 bytes on the FILTER-link region, whereas the clean optimized package's historical slopes are about 4,080 bytes/level for LATERAL and 7,104 for NOT EXISTS. Even deleting those two *entire* frames would be an upper bound, not a realistic saving; FILTER evidence work is absent from LATERAL, and the original 234→281 / 133→180 accepted-depth gaps require substantially more repeated-stack reduction. The diagnostic is instrumented and pre-link, so this comparison is only a scale check, not a computed new floor or exact source-byte attribution.

Before another implementation, inspect the exact unmodified optimized artifact's relevant call boundaries and frame/live-value ownership at the recursive edges. A justified bounded experiment must move only post-child/cold work at existing homes, leave the normal fast path's answer and first error intact, and compare original linked floors and stack slopes on the same source-bound package. Fixed-work instructions and allocation counts should guard default-path regressions without claiming exclusive timing. If measured bytes/floors do not improve, revert; do not stack more no-inline attributes or claim a partial slope reduction as #531 completion.
