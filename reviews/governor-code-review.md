## R1: scratch-only sequential continuation ignores a latched trip

Therefore a scratch-only sequential continuation is free. `RowCheckpoint::pass` returns immediately for Free, before observing `state.tripped()`.

With four workers, shared speculative scratch can stop the first source block before the ordered prefix actually exhausts scratch: another block's mints contribute to the conservative total. Ordered commit correctly admits that short prefix and requests sequential continuation. Its numeric operations eventually latch the real scratch trip, but the free continuation checkpoint still admits every later input row. The IF predicate still calls the native visit counter; `arithmetic_step` resolves its operand values before exact admission rejects the arithmetic. `xsd_of_term` memoizes each dataset Existing integer in the context's `xsd_parse_cache` (`src/expr.rs:567`), and that context retains the cache until evaluation ends. It thereby parses and retains the whole input after the arithmetic budget has stopped it.

## Recording ownership and the stabilized mutex log

The stabilized recorder has one worker-local `ChargeLog` behind the existing mutex, containing ordinary fuel/scratch counters, refusal state, the ordered Vec and the last growth mark. Every public deferred charging method delegates to that log; this does not add a second metered engine.

The single-worker assumption is supported by the production callers, rather than merely by the comment on `ExactDeferral`:

* `WorkerLedger::defer` (`src/row_checkpoint.rs:474`) installs a fresh recorder in the context initialized for one block/chunk. That context evaluates its items synchronously. Only its owning ledger calls `end_item`, then `take_charges` after the block finishes.
* `EvalCtx::may_fork_governed_loop` (`src/eval.rs:2038`) returns false whenever that context already has an exact deferral. `fork_with_scratch` and the derived function context inherit the recorder with `owns_arena=false` (`src/eval.rs:2463`, `src/eval.rs:2748`; `WorkerDeferral::inherited`, `src/row_checkpoint.rs:347`). Their different arenas defer growth as explicit bytes and do not update the owner's cached growth length.
* An engaged governor prohibits sibling whole-pattern forks (`src/eval.rs:1779`). Governed row safety also rejects expression re-entry through EXISTS; registered SPARQL-bodied and expression-bodied functions are classified unsafe for the outer row fork (`src/parallel.rs:471`, `src/parallel.rs:775`). A permitted stable native callback receives values alone, not EvalCtx or the recorder (`src/user_fn.rs:242`). Thus derived/nested evaluation does not introduce a concurrent writer to an engaged recorder.
* Across-group workers own their respective contexts/recorders. Within-group partial reductions receive already evaluated values and accumulator state, not a charging EvalCtx. Extra custom accumulator state and numeric work are admitted on the owning thread before `par_chunk_reduce_init`, and its finish callback returns to that thread (`src/modifier.rs:2083`, `src/modifier.rs:2224`–`src/modifier.rs:2271`). Parallel accumulator work therefore does not race per-item recording.

`QueryGovernors::UNBOUNDED` declines accounting; an ItemLedger can still install a deferral in that mode, but it neither records fuel nor engages scratch. The charged/recording paths above are the relevant ownership proof. Ordinary ungoverned contexts have no deferral. This distinction avoids claiming that every possible Arc clone implies accounting is engaged.

Under that ownership, `end_item` takes the log lock once, resets only the current item's counters/refusal and reads the cumulative charge Vec length under that same lock. The growth cache and cumulative log remain for later items. `take_charges` transfers the finished Vec after the worker is done. The outer fork joins before ordered commit consumes harvested logs. There is no new cross-worker accounting or exposed mutable log.

For the owner arena, `EvalCtx::charge_exact_numeric` performs the existing stop poll once before acquiring the log, then `ExactDeferral::charge_numeric` invokes **fuel → changed growth mark → transient admission** using the same implementations as separate calls. Fuel refusal returns before later entries are appended; zero bytes or disengaged scratch skips growth/transient exactly as before; the owner's computed count is unchanged between these adjacent charges because no numeric computation runs inside them. Refused fuel retains its original point/units/arena mark. Refused transient retains its entry and suppresses later charges. Derived arenas keep the separate **fuel → claimed derived-arena bytes → transient** path, with `owns_arena=false`; they never substitute the owner's computed-length cache for a different arena. No callback or stop poll occurs while the log lock is held, so the batching does not add re-entrant locking. Shared GovernorState counters, cost law and ordered replay are unchanged.

The new internal equivalence test compares batched/separate admissions and entire deferred sequences at ordinary, bookkeeping, absent-scratch, fuel-refusal and transient-refusal boundaries. The growth test checks item reset, a new mint and refused-charge marks. `raw/row-checkpoint-tests-final.log` now establishes **5 passing internal tests**: those two, shared saturating totals, bookkeeping's absence of stopping state, and the direct once-only work-report witness described below. ## Growth caching, marks and refusal

`ChargeLog::note_growth` retains the first growth mark through an initially empty `Option`, then retains each changed owner-arena count. The worker arena only appends new distinct values while it evaluates a block (`src/scratch.rs:642`); harvesting removes them only after recording is finished. An unchanged count means no additional owner-arena mint has appeared since the last checkpoint, so its repeated growth charge is zero. Keeping the cache across item boundaries is appropriate: a mint after the preceding item's last Growth changes the next checkpoint's count and still gets recorded. Derived arena charges use the explicit-byte path and never this cache.

Refused fuel and explicit scratch charges retain their own marks, original relative order and refusal state; cached growth does not suppress them. Growth after a refusal was already suppressed. `end_item` resets per-item counters/refusal while retaining the cumulative charge positions and growth cache; a locally refused item stops its ledger, and the next block gets a fresh deferral. `take_charges` transfers the finished log without being reused for further production items.

The unchanged `commit_items` (`src/row_checkpoint.rs:702`) first charges row admission, then commits that item's recorded span. It uses the whole-item shortcut only when all possible charges fit; a possibly refusing item replays Fuel/Scratch/Growth/Transient in their original sequence. Refused charges count owner mints through their recorded mark. `count_worker_mint` stores uncounted identities as ghosts, and later intern consumes the ghost without adding its bytes twice (`src/scratch.rs:599`, `src/scratch.rs:627`). Because the cache omits only zero growth, it does not move a real mint's charge past a refusal.

## Superseded zero-computed snapshot shortcut, source review before adoption

**Design disposition: charge/refusal equivalence established for the existing clone, with a concrete retained-index allocation guard needed. No implementation or acceptance PASS yet.** As read on 2026-10-07, `loop_snapshot` still creates the shared snapshot for a sufficiently large governed loop. The proposal omits it when computed_count is zero, letting `fork_for_loop_worker(None)` use the existing `fork_for_worker` clone.

The initial concern that Clone carries parent ghosts is resolved by current source: `ScratchInterner::clone` already clears ghosts and ghost_index (`src/scratch.rs:171–188`), and scratch.rs is unchanged by this task. Direct clone(parent) and over(clone(parent)) both preserve minted_bytes, blank-label reservations and their tracking flag; both reset charged_bytes to zero and leave local ghosts empty. A zero computed_count forces shared_len and values.len to zero. An immutable shared ancestor's count was captured as shared_len by over; therefore a zero-count chain cannot conceal stored computed terms.

The extra zero-term shared layer is behaviorally inert: find never finds a pre-fork computed value; value_at resolves new ids locally; take_ghost sees the same empty local state; next ids start at zero. Blank-label reservation/dedup therefore adds the same bytes. WorkerLedger::defer claims the same inherited minted baseline before recording new growth, so later growth/fuel/transient marks and local refusal are identical. Harvest takes the same newly minted values from base zero, and ordered parent commit reconciles them against the parent's own retained ghosts. Zero computed_count can coexist with ghost/minted-byte retention, but that does not require a minted_bytes=0 or ghosts-empty guard for charge equivalence under this existing Clone.

There is a separate concrete allocation edge. ExecutionWorkspace::check_in clears ScratchInterner while deliberately retaining its index capacity (`src/execution.rs:244–256`, `src/scratch.rs:321–343`); a later check_out can thus hand evaluation a zero-count arena with a large empty local index. ScratchInterner::Clone clones that index, while over(snapshot) creates each worker with a default empty index. The local hashbrown 0.17.1 implementation confirms HashTable::clone delegates to RawTable::clone, which allocates the original bucket count whenever the table is not the allocation-free empty singleton, even at length zero (registry `hashbrown-0.17.1/src/table.rs:1627–1635`, `src/raw.rs:3292–3322`). A count-only shortcut would copy that retained table per worker/block instead of once into the snapshot. This leaves charges equivalent but defeats the shared-snapshot physical purpose on a real prepared-workspace path.

The recommended bounded shortcut requires zero computed_count **and zero local index capacity**, keeping a shared snapshot for retained-empty-index arenas. A small ScratchInterner predicate can state that allocation condition at the arena's home. Empty Vec cloning does not retain its allocation, and blank-label cloning already occurs for each worker on both paths, so this finding does not justify broader invented zero-retention restrictions.

The source writer received both traces before adopting the shortcut. Proposed focused fixtures compare frozen-over and direct-copy next intern, exact id/minted/charged growth and harvest with zero-count ghost retention and activated default-scope blank-label reservations; retain a nonempty snapshot control and a cleared retained-index control. These are concrete neighbors of the changed path. This reviewer ran no fixture or build; final adopted source, the writer's affected receipts and final performance remain to be checked.
