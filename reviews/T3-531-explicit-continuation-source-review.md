# #531 explicit continuation: narrow source review (2026-10-13)

**Verdict: coherent as a design, but the two named interface slices are real prerequisites. No depth, byte or semantic pass follows from this review.** I found no need for a raw self-pointer or a second evaluator if the existing VM and guard homes own the conversions below.

`PreparedPattern` (`expr.rs` around 14465) holds a shared admitted `CorrelatedPattern`, so it can keep a copied tree alive while a frame stores a root handle and structural node path. It does not itself solve `Linked<'e>`: `vm/mod.rs::Linked::link_admitted` currently builds `Vec<&GraphPattern>` from an expression, and `Op::Exists(site)` returns `Suspend::Exists(&GraphPattern)` from that vector. The existing compiler emits `Op::Exists(u32)` and the linker assembles matching pre-order sites. A safe suspended frame must keep the expression/tree owner separately, replace the borrowed link sites with owner-relative site ordinals/paths in the same VM home, and resolve a borrowed node only for one non-suspending step. It must cover both externally borrowed prepared-query trees and per-row copied trees; a path into one copied tree cannot be resolved against another clone. The current `PreparedPattern` is a usable owner for copied trees, not proof that every expression link has one. Preserve the existing ordinal traversal and address of the resolved node for deferred placeholder, ledger and memo lookups; do not reconstruct the subtree on resume. The `link_without_exists_admitted` internal-error behavior remains a distinct case.

`eval.rs::EvalScopeGuard` currently owns `&mut EvalCtx`, while `ScopeRestore` owns previous flag/deferred/positive-shape values and whether one correlated map was pushed. `enter_substituted_exists` admits and pushes the map **before** setting the flag and replacing deferred state; its `Drop` restores the flag, restores previous deferred state, then pops the map. A detached token is feasible only if the same restoration body is shared by recursive guard and loop, installed after all fallible growth, and consumed once in strict nested LIFO order on success, typed error and unwind. The continuation runner must retain exclusive context access and restore tokens before dropping copied AST owners or any map/placeholder indexed by their addresses. `enter_positive_shape` needs the same stack discipline when nested with substitution. A plain frame-vector destructor is insufficient unless its drop order and access to `EvalCtx` enforce this explicitly.

Source-backed blocker before implementing the loop: neither borrowed `Linked.exists` nor guard scope ownership can be moved directly into a self-contained frame. Converting just `Suspend::Exists` without the linker's site storage leaves the borrow; detaching `ScopeRestore` without a runner-owned unwind path loses the guard's current error guarantee. The design correctly lists these as its first slice. I did not review delivery/operator coverage or run tests/builds.
