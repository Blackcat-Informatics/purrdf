VERDICT: PASS for the complete implementation boundary and preimplementation design, with the concrete checks below remaining required during source review. This is not a production, performance, corpus or delivery PASS. No build, source edit or forge refresh was performed.

The plan preserves the entire issue and approved comment rather than staging a partial foundation PR. Its 12/8/12-byte carrier, SPO physical order plus POS/OSP lazy ordinals, original-home frozen term extraction, zero-clone owned conversion, and quad-preserving public API are coherent with the current `RdfDataset`/builder layout. The specified term-only builder control is necessary: reusing `RdfDatasetBuilder` unchanged would retain quad and graph accumulation and defeat the physical contract. The existing validation body first checks absolute IRIs and triple-term structure, then positional rows; factor that one validation home around a term-only input and projected default `QuadIds` without weakening its first diagnostic or allocating a quad mirror. Inspect declaration and all three row tables before moving ownership so named content cannot disappear on refusal.

The operation-local `TripleRead` decision is sound in principle. `DatasetView::named_graphs()` cannot itself return a typed error, so support must be a separate capability/preflight called by actual engine GRAPH and dataset-spec routes, including variable, constant, prepared and nested forms, before empty/missing-term shortcuts. Direct `GraphMatch::Named` reads still latch the same session cause; `checked_read` before/after and every typed term/reservation door must report it even for an empty iterator. `Shared` control admission precedes publication; child guards hold it until their final release. A fresh session over the same immutable payload must answer a healthy default request. Distinguish support from the existing `caps.named_graphs` observed-content bit.

The closed triple/quad compile-time Datalog shape is required across the actual `[PositionPlan;4]` waist, `(predicate,graph)` relation keys, SIPS, semi-naive/chase/proof and public entail model. Reusing only the store while leaving a default-graph fourth plan slot would fail. The plan explicitly forbids that and requires actual three-position/one-key controls. Flat RDFC is correctly selected: the overlay presentation can carry an annotation graph sentinel, so equality must compare `try_canonicalize_flat_view` and `try_flat_digest_view` on both carriers under the same presentation. The text plan likewise requires a distinct graph-free profile and physically absent graph component in document/partition keys and fingerprint, while preserving the graph-language profile.

Before implementation qualification, pin the concrete error type/code and named-capability propagation through each wrapper view; prove builder rollback and owner/admission accounting at refusal; and measure actual layout/index bytes and unchanged default query/rule answers on the public routes. These are source and acceptance decisions already inside Tasks 1–2, not reasons to narrow the contract or defer any constituent.
