# #531 FILTER fork extraction: source-only review (2026-10-13)

**Verdict: coherent as a bounded, one-home source candidate; no stack saving or floor correction is established.** I reviewed clean checkout `330c55f8c2d99300b8375a545ef255095e23a830`, chiefly `crates/sparql-eval/src/expr.rs::eval_filter_sequence`, `row_checkpoint.rs::RowCheckpoint`, `eval.rs::may_fork_row_loop`, `vm::Linked`, and `solution::RowsBuilder`. I made no production edit or build. The previously verified unnamed release frames do not prove that forked locals occupy the recurring sequential frame.

`eval_filter_sequence` currently computes the fork decision, constructs one row checkpoint, compiles/links the expression, and then chooses the forked or sequential path. The **whole existing forked arm** can be moved into one private function at this home returning the existing row-bag type. Its call should occur only under `if forked`; the `else` should retain the sole ordinary sequential `for row in seq.rows` body, using the same checkpoint and linked VM. Keep `RowCheckpoint::for_rows`, `program_at`, and `Linked::link_admitted` at their current pre-branch positions so error/admission order and program-cache behavior do not move. Keep the common `expression_barrier.observed()` and `lift.finish` after the two paths, in their current order. This introduces no alternate FILTER evaluator or duplicate `eval_filter_sequence`.

The extracted arm must carry its current borrowed input slice through `forked_len`, worker snapshot/deferral, `linked.fresh()` per worker, and source-ordered `checkpoint.commit_rows`. It must harvest worker witnesses and call `ctx.absorb_worker_witnesses` **after** that commit, then resume on the original context at the returned row index using a new sequential checkpoint. The resume loop's `checkpoint.pass` must remain before `linked.filter`, with `row.clone_admitted` and optional evidence attachment on kept rows. Finally it must transfer the scheduler's row buffer through `AdmittedVec::from_parts` and `RowsBuilder::from_storage` rather than copying cells or losing its attachment proof. These operations already exist in the fork arm; moving them as one block preserves their relative order and ownership. A helper that only moves worker execution while leaving commit/resume or buffer conversion in the caller is not this candidate.

The default path must borrow or move only existing values into the fork call. It must not clone `seq`, call `linked.fresh`, create an adapter/closure allocation, or construct the worker snapshot before branch selection. A borrowed `seq.rows` in the fork arm and consuming `seq.rows` in the ordinary arm are distinct control-flow alternatives. Keeping the ordinary branch's `RowsBuilder::new`, `row.with_optional_evidence`, `push_row`, and `finish` unchanged preserves its current row ownership and first failure. The helper's result should be the existing row bag, leaving common truncation and lift handling where they are.

This is a **weak performance hypothesis** for the WASM failures: `EvalCtx::may_fork_row_loop` returns false immediately on wasm32, and an optimizer can already eliminate the fork branch and its locals. The observed 7 KB/level NOT EXISTS slope is on the sequential `linked.filter` recursion, not a demonstrated cost of native worker state. Source review supports measuring a minimal extraction against the unchanged optimized package and original 281/180 depth floors; it does not predict a byte reduction. If the final release artifact shows no reduced live stack and the floors still fail, reject/revert the extraction rather than keep a complexity-only change or soften acceptance. Any implementation that adds another sequential loop, default-path allocation, altered checkpoint/evidence order, or new wrapper body fails this review before measurement.
