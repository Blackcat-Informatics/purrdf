# Graph-free text slice source review — 2026-10-13

VERDICT: PASS for the bounded source shape. The two added physical/query controls have only compiled at this cutoff; #492 text runtime, portable acceptance and the whole issue remain OPEN.

The closed `CorpusProfile` has `GraphLanguage` (the default type parameter on the established public index/config/key/document/relation/filter APIs) and explicit `GraphFree`. `GraphFree::Graph` and `GraphFree::Selector` are unit types. Thus source rows, document keys, stored documents and partition keys contain no graph coordinate or sentinel; a graph-free index still reads only the default graph. `collect_rows` refuses a graph-capable source before scanning, and `GraphFree::retain_graph` refuses any named row. The existing `GraphSelector` resolver now calls `require_named_graphs` before a missing-IRI shortcut, so a graph-language named request against `TripleRead` preserves its typed, sticky first cause even on an empty source. A graph-capable quad source retains its established missing-name-as-empty behavior. The profile is selected by `TextIndexConfig::<GraphFree>::for_triples`, not by a runtime feature/default.

Index and source fingerprints choose distinct graph-free domains and skip the graph selector/row/document/partition fields under the graph-free profile. The default `GraphLanguage` path retains the old digest domains and the same field sequence, including default/named graph tags, so this source change does not intentionally alter quad identities. Document/partition ordering uses the generic key with a unit graph in GraphFree and the original `Option<TermValue>` graph in GraphLanguage. Language grouping, analysis, posting construction, exact scorer, dictionary matching, occurrence matching and both property-function cursor bodies remain shared generic homes. No graph-free scorer or query interpreter was copied.

The added first `physical_shapes` control compares physical `PartitionKey`/`Document` widths, separate fingerprints, rank selection and three full SPARQL answers between an all-default quad fixture and its compact carrier. The second builds RDF 1.2 assertion/reifier/annotation text with scoped blanks and two languages, checks language partition statistics and source binding, then checks named refusal on nonempty and empty triple sources and unchanged absent-named behavior on a quad source. These are meaningful actual-consumer controls, but metadata compilation does not prove their assertions. Existing graph-language goldens and full text/property-function/portable suites must run on the final source before identity or performance acceptance.

Public generic implications: existing unparameterized uses resolve to `GraphLanguage`; `TextIndexConfig::new`, `PartitionKey::new`/`graph` and associated relation argument-position constants stay on that concrete profile. GraphFree callers use the explicit configuration and language-only key; its relation invocation uses the same physical row positions. Check warning-denied all-target compilation and host consumer type inference before publication, then record the API extension in migration/docs if required by the final #492 contract. No source or build was changed for this review.
