# Boolean, String and binary parse ownership

This is a Stage-only proposal, not applied source or tested acceptance. The patch preserves the existing resident entry points and places lexical algorithms at their current XSD/hash homes. Operational caller-owned destinations use native checked layouts before allocation. Shared parsed payloads use the root's selected fallible `purrdf_core::small::Shared` control block.

The binary plan retains only borrowed lexical bytes, datatype, checked Layout and inline group shape. Hex validation and slice decoding use the existing hash decoder. Base64 structural scanning counts significant bytes and trailing padding without constructing stripped text; one native group body validates and decodes, preserving length/padding/internal-padding/alphabet/unused-bit ordering. Only HT/LF/CR/SP are skipped. The byte destination is exactly groups*3-padding. Boolean classification and malformed reasons are allocation-free; xsd:string copies its unchanged UTF-8 lexical into a pre-reserved native destination.

The supplemental parsed-value hunk targets the postimage of `numeric-parse-cache-draft.patch`, which has not been applied by this task. It switches that carrier's control block to Shared and adds `parse_simple` for Boolean/String/HexBinary/Base64Binary. The factory prices checked destination Layout plus `Shared::<ParsedPayload>::allocation_layout`, then uses fallible String/Vec reserve and Shared construction. It settles surviving actual capacity under the same immutable owner. The current shared account's first typed admission error propagates before allocation and must never become cached None.

Production dispatch must resolve the datatype IRI once under the existing borrowed lexical/datatype guards. Numeric branches call parse_numeric with the actual XSD version; Boolean/String/binary branches call parse_simple. Temporal, duration and Gregorian branches must use their own admitted native path before this is a complete XSD dispatcher. Unknown IRI/nonliteral is opaque None; known malformed lexical is the existing value-space None; OtherDatatype is a dispatch obligation. No raw parse_by_iri/parse_xsd10 fallback is permitted in bounded execution. Cache carriers, sorting keys, scalar and aggregate consumers retain/borrow the same ownership-carrying ParsedValue. The numeric owner's checked native parse and the root Shared proposal remain required dependencies, not claimed applied here.

Resident parse_hex/parse_base64/parse_boolean return the same XsdError datatype, original lexical and static reason. Operational classifiers do not copy the lexical merely to discard an error. Layout overflow, insufficient destination, try_reserve refusal and Shared allocation refusal are separate operational/invariant failures. BinaryPlan decode does not grow its supplied slice; string copying refuses insufficient capacity before clear/write. No runtime dependency or feature is added.

Focused qualification after source integration: RFC base64 vectors plus whitespace at every group/padding position; empty and whitespace-only forms; bad length, internal/over-padding, invalid alphabet, forbidden Unicode/ASCII whitespace and nonzero unused bits, including combined errors that pin existing reason precedence; all hex lengths/cases/first invalid byte offsets and undersized unchanged destination; exact UTF-8 string copying and insufficient unchanged destination; Boolean four accepted lexicals and whitespace/case rejection; each output/header reserve denial before allocation; large String/binary carrier clone and cache eviction/drop preserve the grant until the final owner; valid empty payloads stay inline with no Shared allocation. Existing canonical bytes/value relations stay identical. No compiler, build, tests, Git or forge operations were run.
