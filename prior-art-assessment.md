# Issue 508 prior-art assessment

Issue authority: the selected `issue.md`, including every acceptance row. Assessment is based on read-only inspection of the existing production implementation at the assigned base `3b6ec4d9f`. No builds, tests, new forge retrieval, source changes, or historical qualification claims were made for this assessment.

## Decision

Reuse the existing native evaluator, its operational publication boundary, and its shared direct/prepared/governed/EXPLAIN bodies. The missing work is comprehensive allocation admission and retained ownership across those bodies. An additional evaluator, unbounded resident replay, no-op operational reservation, or suppressed storage budget cannot satisfy the issue.

Existing first-party code supplies useful components and failure laws, but it does **not** already establish complete bounded execution. In particular, removing the current query-shape refusal without replacing its accounting proof would admit unpriced execution. Issue 481's output-allocation work and issue 486's broader physical memory work are related; neither is a substitute for completing 508's actual production behavior and result ownership.

## Gaps that the design must explicitly resolve

1. **Retained publication is an ownership problem.** `fallible.rs` makes `CompleteSparqlResult` clonable, exposes its public `SparqlResult`, and returns raw result/evidence through `into_parts`. `rdf-core/src/backend.rs:151` makes `SparqlResult` clonable and exposes/extracts raw row vectors; graph and auxiliary carriers use `Arc<RdfDataset>`. `governed.rs:351` similarly permits partial-result extraction, while `governor/ledger.rs:329` makes EXPLAIN an owned clonable value. A guard in an ingress local variable currently disappears on return. Attaching a lease only to the outer complete wrapper cannot cover field moves, `into_parts`, `into_solutions`, graph/auxiliary `Arc` clones, or independently cloned row storage. All supported escape paths must retain or acquire admission. Shared ownership must share the covered allocation, and a deep copy needs an additional charge. No leak, global side table, no-op guard, or unsafe lifetime extension is an acceptable replacement.

2. **The current context has no growth capability.** `engine.rs:2478` accepts `_workspace` but sets only `WorkspaceAdmission::Admitted` on `EvalCtx`; `eval.rs:432` stores a two-state marker. The existing static BGP reservation is therefore the entire memory proof. A generalized implementation needs actual pre-allocation pricing at its allocation owners, or certified bounds covering those owners and their simultaneous capacity. It must include scratch interning, row buffers and their capacities, grouping/order/distinct/paths, nested execution, metadata, diagnostics, governors, witnesses, preparation/substitution copies, and output staging. Allocation failure and checked-size overflow must remain actionable typed outcomes.

3. **Stored terms do not bound computed terms.** `max_owned_term_bytes` certifies fully expanded terms already held by the storage view. It cannot bound repeated concatenation/replacement, arithmetic limb growth, aggregate string output, minted labels, custom/UDF results, native relation output, or formatted EXPLAIN/reporting data. Constants/substitutions supplied by the caller also need their own sizes when copied. Price these before growth, without substituting a fixed multiplier for a proof. Term guards/pins and newly owned copies can coexist and both count against the shared live ceiling.

4. **Cost cardinality is not automatically the evaluator's full row domain.** `DatasetView::cardinality_estimate` is an upper bound for its ordinary `quads_for_pattern` stream. The evaluator additionally visits virtual reifier and annotation rows through `bgp.rs:1780`/`statement_layer`. Resident `ir/dataset.rs:1252` and paged `ir/paged/query.rs:912` estimate ordinary indexed rows. Segmented `session.rs:1242` already counts all three tables, so blindly adding virtual rows everywhere would double-count that backend. Establish a clear certificate for the complete relevant stream per adapter and active dataset, including empty named-graph enumeration, merged default graphs, and nested triple patterns. Overflow must refuse soundly; a saturated cost heuristic cannot silently become a byte-size proof.

5. **Native text must price internal work, not just emitted rows.** `TextSearchRelation::open` analyzes the needle, ranks, and collects `Vec<Hit>` before it constructs `SearchCursor`. A bound document/score/matched position can require full ranking before post-ranking filtering even when the query has LIMIT. Cursor state owns needle and bound-term copies; `SearchCursor::build` clones indexed subjects and renders score strings. `PropertyFunction::rows_per_invocation` bounds emitted rows only, and `open` currently receives no workspace capability. Pricing must cover those real allocations before open/rank/copy, and distinguish the pre-existing caller-owned index from fresh execution-owned state. Preserve the existing filtering/truncation law and generation witness.

6. **Configured behavior must remain actual behavior.** The current bounded allowlist rejects substitution and extension/focus contexts. In addition, `engine::eval_ctx` skips configured standpoint/loss-vocabulary tables when storage is bounded. Complete healthy parity requires auditing and pricing configured behavior, not disabling it to admit a query. Focus-graph input is caller supplied; do not build an unbounded resident copy of operational storage to synthesize one. The same registries and admitted settings must reach preparation, execution, governed receipts, and EXPLAIN.

7. **Error and cancellation precedence is already a production law.** `finish_fallible_read` and `finish_governed_fallible_query` certify only after final `operation_status`. A source failure outranks a derived query diagnostic, cancellation, or governor trip and publishes no rows/ledger. Direct reservation refusal remains typed even when a custom adapter has not latched it. The new allocation paths must enter those same boundaries and release their admissions on every refused/failed outcome; genuine governor partial answers still need retained publication accounting.

## Acceptance reuse and limits

Use the existing shared allocation probe (`purrdf_alloc_probe`) and deterministic native fixtures. Extend the existing route table in `tests/query_completion.rs` for typed admission, iterator/materialization/final-checkpoint failure and visitor refusal; retain the prepared-governed registry/substitution/error cases in `tests/prepared_operations.rs` and the resident semantics oracle. Existing graph-cap tests in `tests/governed_query.rs` exercise real CONSTRUCT/DESCRIBE output rather than SELECT-only row counts.

`tests/segmented_query.rs` already compares measured peak working bytes with the shared ledger and exercises cache pressure, scoped consumption, reporting refusal, EXPLAIN, cancellation, and operational failure. It is useful prior art for the measurement mechanism, but its sort/input refusal expectations must change for supported healthy bounded runs. Its EXPLAIN tests currently assert that publication returns with guards released while the explanation remains owned; that expectation does not prove 508's retained-output law. Replace or refine those expectations deliberately, and add lifetime evidence after return, extraction, clone, repeated execution, and final drop. Preserve failure-release assertions.

Qualification must cover every selected-issue row: all four forms and existing algebra with bags/RDF 1.2 terms, explicit/default/named/empty-graph semantics, direct/prepared/governed and EXPLAIN parity, substitutions and admitted text/focus contexts, low-capacity/overflow/cancellation/governor/allocation refusals, operational-error precedence, measured simultaneous execution/result capacity, and retained result ownership. Include virtual-row-heavy and growing-computed-value cases so a quads-only or stored-term-only bound cannot pass accidentally. One settled coherent focused acceptance and proportional independent review precede the intended full gate; the delivery ceiling remains three complete `make check` invocations including failures, with an aim of one and mandatory hooks unchanged.
