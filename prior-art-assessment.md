`CompositeDatasetView` is a resident-source set union, including native/delta/selection sources. It is not a ready-made lazy operationally fallible paged stack. ## Recommended composition

Use an immutable stack snapshot, with an ordered list of independently sealed paged generations and their net removal sets, plus an immutable snapshot of the mutable head. Each generation keeps its original dictionary, provider generation and page-local identity. A source generation's `GlobalTermId` is meaningful only with that source. Build a fresh logical snapshot dictionary by resolving source dictionaries and interning values, and remap each page translation's global side into that new dictionary. This is a real new dictionary generation, not an offset or a claimed extension of a source's ID range. Source IDs and snapshot IDs must cross only explicit by-value maps. Source-local G10 summaries then remain exact without remapping.

At construction, concatenate sealed **metadata**, not materialized RDF, into a private physical-page composition whose provider routes dense snapshot page ordinals to `(layer, source PageId)`. Preserve each part's original byte charge, term layout, capabilities, quad count and summary. This enables one ordinary `PagedQueryView` over all physical pages, so one operation has one budget, one cache and one first-error latch. Do not run `from_provider` over the concatenation: its G3 refusal correctly rejects cross-generation overlaps which the stack must accept as time-ordered updates. The private constructor must receive previously checked within-generation parts and explicitly document that the internal physical view is never exposed as a disjoint logical RDF view. All public logical reads pass through the stack overlay.

The routing provider must verify the entire captured vector of source generations **and source page counts** on every status checkpoint, including a query that reads zero pages. Compare those vectors directly, rather than hashing them into a `u64` and assuming no collision. If the existing single-generation trait is retained internally, return the pinned routing token only while every source still matches and a guaranteed unequal token after mismatch. Validate the source-returned generation before rewriting the materialization's generation to the routing token, and translate source faults back to the snapshot page ordinal. A mismatch must remain typed and sticky. The public stack evidence should retain the captured source identities, head/removal snapshot identity, depth and route mapping; a bare synthetic generation number cannot tell the consumer which stack was read.

Publish snapshots through immutable owned/`Arc` state. Later inserts, removals, head sealing, stack replacement or consumer publication must leave an already-created query view unchanged. Purrdf should return the folded generation; the consumer owns durable atomic publication. No filesystem, log, clock or compaction scheduling belongs in this mechanism.

## Removal and shadow semantics

Attach removals to the generation/head whose batch produced them. One unqualified final removal set loses the distinction between `insert -> remove -> insert` and `insert -> insert -> remove`. The snapshot can derive cumulative higher-layer masks as an implementation detail, but source chronology is authoritative.

Treat a sealed batch as net additions and net removals with a specified precedence for multiple operations within that batch; preferably require those net sets to be disjoint after the head's mutation normalization. A removal hides matching value-quads in every older layer and does not hide a later insertion. A newer occurrence shadows an older identical row, ensuring a logical set rather than duplicate SPARQL input rows. Within each independently sealed paged generation, retain the existing G3 hard refusal on overlap.

Avoid building a base-sized live-quad hash table merely to publish a snapshot. A lower row can be checked against newer removals in memory and newer additions through their existing indexed/admitted reads; those reads must use the same operation-local accessor and therefore contribute to the same exact receipt. Any metadata optimization used to skip such checks must be proved sound. Lazy means construction and head sealing do not read/reseal the entire frozen base; a full unbound query and explicit compaction may legitimately read all effective candidate pages.

The mutable head API must define `insert`, `remove` and `contains` against the whole effective stack, including new terms. If determining prior presence needs fallible storage, expose a typed failure rather than report a false no-op/absence. Internally mutating only a resident head is not sufficient to satisfy C4's effective-set semantics.

## RDF 1.2 classification and G10

The delta overlay already proves that removals are not just per-table filters. Its `base_annotation_is_ordinary` demotes a surviving annotation when no effective reifier declaration remains for that subject **in that graph**; its `base_quad_is_annotation` promotes an ordinary row when a new declaration exists there. A stack must apply the same law across any number of generations, including a declaration introduced in one layer, annotations inserted in another, and deletion/reinsertion in still later layers. Multiple surviving declarations for a subject/graph must prevent premature demotion.

Extract one small shared classification decision, parameterized by visibility and effective reifier presence, into the IR mutation/statement-layer home. Migrate `DeltaDatasetView` to consume it without changing its optimized native probes. The stack supplies presence through scoped, admitted reifier probes over its physical view. A large generic framework for every source type is not justified; sharing the actual decision and preserving source-specific cursor/index paths is enough.

For logical ordinary-row reads, raw candidates may come from both physical base rows and physical annotation rows after reifier removal. For logical annotation reads, candidates may come from both physical annotations and physical base rows after reifier insertion. Calling only the current base `quads_for_pattern` cannot find an annotation-only page that becomes ordinary: its exact base graph/axis count is zero, so G10 correctly skips it. Add a stream-aware candidate/probe helper inside the existing paged read implementation; use physical summaries for each stream and apply logical classification after validated admission. Reuse the page accessor rather than creating another admission/accounting path. Current annotation summaries contain subject/reifier and graph counts, so unsupported predicate/object narrowing may be a sound upper-bound probe followed by row filtering, not fabricated exact counts.

Tombstones do not make the **physical** summary inexact. They can reduce visible matches and therefore make physical cardinality estimates upper bounds for the effective stream. Label that distinction; never claim an exact effective count from an unadjusted raw count. Reclassification can move rows across streams, so an ordinary-stream estimate must include eligible physical annotation counts when demotion is possible. Rebuild derived graph postings for the physical composition, and implement the logical `named_graphs`/`has_named_graph` semantics with explicit empty-graph policy. A union of original physical graph names can falsely retain an implicitly withdrawn graph after every effective row is removed. Empty declared graphs must still survive under the chosen declaration policy.

## Canonical compaction

Provide one deterministic eager-seal/fold path parameterized by the canonical page-size rule. It consumes the complete effective RDF 1.2 surface under guarded operation checkpoints, discards tombstones and duplicate older occurrences, resolves surviving terms by value, sorts canonical value-row identities and partitions them deterministically. Both eager sealing of an effective set and stack compaction must call that same partitioner. Arbitrary prior page boundaries or input order cannot participate in the output.

Reconstruct each page through the existing typed importer/builder path and encode with `PackBuilder`; the existing encoder already canonicalizes the term dictionary, closes nested/datatype dependencies, and retains side tables and declaration-only graphs. Build the resulting `PagedDataset` through its checked seal and canonical global remap. A zero-row/declaration-only input needs a specified deterministic page representation. Caller-owned vocabulary/configuration and source locations/non-RDF sidecars must not be fabricated; the latter are outside `DatasetView` and remain consumer-owned.

Compare actual ordered page byte vectors (and canonical dictionary/value IDs where relevant), rather than only canonical RDF digests or logical quad sets. An RDF digest omits declaration-only empty graphs, and byte identity is stronger than isomorphism. `PagedDataset::compact`'s existing unchanged local page tables do not meet this new compaction criterion.

## Depth and acceptance evidence

Keep depth policy with the consumer. Report sealed depth and head presence in snapshot evidence; refuse allocation/count overflow with actionable typed failures. Do not add a hidden arbitrary depth ceiling or recursive per-layer call chain whose machine-stack usage grows with depth. Iterative cursors/work lists are compatible with the repository's portability goals. If an explicit resource ceiling is added, its caller ownership and typed refusal belong in the public contract.

Required tests should exercise real guarded SPARQL entry points and compare against a independently constructed eager effective-set seal: joins on terms assigned conflicting numeric IDs by independent generation dictionaries; directional literals; scoped blanks and nested triple terms; delta-only graphs; duplicate insertion; lower removal and later reinsertion; same-batch mutation order; query isolation after head mutations/sealing; multiple reifiers and graph-scoped promotion/demotion; declaration-only and removed implicit graphs. Compare result multiplicities, not only sets.

For G7-G10, instrument provider calls to prove metadata-only construction, narrowed page reads, one global page/byte ceiling (equality and zero), duplicate cache accesses charged once, deterministic route-qualified first-request order, partial-page removals, annotation-only demotion candidates, provider faults, changed charges/layout/summary, drift in an otherwise skipped source, and a zero-page query detecting source drift. A failed read yields no complete result or compacted artifact. Compaction tests must permute source history, page boundaries, insertion order and layer arrangement while holding the effective set/page rule fixed, then compare every output page byte against the eager seal.
