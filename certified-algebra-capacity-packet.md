# Certified algebra and expression capacity packet

Engineering support for the complete bounded evaluator delivery. This is a source-derived implementation packet, not a validation receipt or a review verdict. No builds or tests were run for it. Paths below are relative to the selected worktree; the source writer may move line numbers.

## Implementation decisions

1. Separate a **row certificate**, a **schema certificate**, and the **live allocation admission**. A cost estimate or a row count is not a heap bound. Prefer checked local capacity growth where a whole-query bound is uselessly large or an extension supplies values dynamically.
2. Use one operational `QueryWorkspace` shared by nested evaluations and all simultaneous owners. Admit before every allocation/growth; hold that charge until the allocation disappears. Retained result, partial result, evidence and EXPLAIN carriers keep the same account through clone/extraction. Resident instantiations keep the no-op path.
3. Attach the calculus to the existing iterative AST/plan walk (`sparql-algebra/src/walk.rs`, `plan/mod.rs`) and actual schema builder (`eval.rs::syntactic_schema`). Cover `Apply`, `Unfold`, embedded `Exists`, aggregate arguments/order and nested triple terms explicitly. A second graph-only recursive visitor misses supported shapes.
4. Obtain a certified **three-stream** input bound, not an ordinary-quad cost estimate. `max_owned_term_bytes()` bounds values read from storage only. It does not bound values produced by `CONCAT`, exact arithmetic, UDFs, regex replacement, aggregates, list minting or reports.
5. Keep query-governor semantics separate. A workspace/storage admission failure is a hard operational failure. It must stop allocation and survive to the typed final boundary; do not turn it into a SPARQL domain error (`None`), a governor truncation, an empty bag or a successful partial result.

## Checked quantities and full input streams

All row, cell, capacity and byte arithmetic below uses `checked_add`, `checked_mul`, checked subtraction with explicit ordering, and fallible `usize`/`u64`/layout conversions. Never saturate an admission calculation. An unrepresentable planned allocation yields the existing actionable overflow/allocation error before constructing it. An unrepresentable *optional whole-query row bound* can instead be `Unknown` and use checked local admission; it does not prove that the actual selective execution cannot fit. Preserve exact zero: an empty operand is not one row.

For scope `g`, use separate certified counts:

```text
Q(g) = ordinary quad rows in the scope
R(g) = reifier declaration rows in the scope
A(g) = annotation rows in the scope
E(g) = checked(Q(g) + R(g) + A(g))
N(g) = distinct subject/object endpoints of the stream the path actually reads
G    = named graph declarations, including declared empty graphs
```

The partition is an explicit `DatasetView` contract (`rdf-core/src/dataset_view.rs`, snapshot-ingestion obligations). A complete BGP candidate certificate may use `E(g)` for each pattern, or a tighter certified pattern bound that includes every eligible stream. For a merged default scope, `sum E(g)` is a safe bound before RDF-merge deduplication. Multiple `FROM` occurrences do not multiply the same graph again: `dataset_spec.rs` resolves, sorts and deduplicates the graph list. `FROM NAMED` alone leaves an empty active default graph. Resolve/read failures in these probes remain sticky and must be checked before using the certificate.

Concrete source cautions:

- `DatasetView::cardinality_estimate` is documented for **cost ranking only**. Resident and paged implementations count ordinary candidates; paged `ir/paged/query.rs` adds page estimates with saturation. That value alone is not the required full-stream checked admission certificate.
- Segmented `ir/segmented/session.rs::cardinality_estimate` currently counts all three tables for a bound subject and uses three-table summaries otherwise. Do not add virtual rows again to that combined number. Expose/use a clearly certified stream-aware bound, preserving its checked error handling.
- `bgp.rs::emit_virtual_candidates` calls `statement_layer::visit_quads`. Reifier rows are conditional on predicate/object shape; annotations are a separate stream. Structural quoted-triple variables do not multiply one candidate into many rows: matching one stored term supplies at most one binding for each nested position.
- Core `path.rs::node_universe` and its step functions currently consume `GraphScope::for_each_quad`, the ordinary indexed stream. A full `E` certificate is a safe superset bound for those scans, but does not itself change path semantics or prove that paths consume the virtual stream. Count the stream actually used; any existing virtual path production route needs its own included owner.
- Named graph enumeration is independent of `E`: declaration-only graphs are legitimate. `GRAPH ?g {}` can produce a row for an empty graph.

If an adapter lacks cheap certified metadata, a checked streamed count through the existing three accessors is sound and requires no materialized bag. It still pays that adapter's storage admission and must finish with its read checkpoint. A guessed `len_hint`, `term_bytes_hint`, fingerprint or warm-cache-dependent count is not a substitute.

## Complete graph-pattern row/schema calculus

Let `r(P,g,mu)` be a certified output-row bound for pattern `P` under active scope and substitution `mu`. `V(P)` is its **visible output schema set**; `w=|V|`. Keep the physical BGP schema separately, since shared blank-node columns and incoming driver columns can exceed visible width. Use the actual first-seen schema order, not sorted identities. For unknown producer sizes, retain `Unknown` and admit actual buffers locally.

| Actual `GraphPattern` variant | Sound row bound | Width and simultaneous owner obligations |
|---|---|---|
| `Bgp` | With `k` patterns, `p0=1`, `pi=checked(p(i-1)*Ci)`; `r=pk`. Empty BGP is **one unit row**, even at width zero. If any `Ci=0`, later prefixes are zero. | Physical width comes from compiled variables, nested triple positions, joined blanks and incoming bindings. Keep actual live prefix bags, compiled pattern/probe metadata and output. `max pi` bounds a single prefix, not the sum of retained prefixes. Do not replace every `Ci` with `max(1,Ci)`. |
| `Path` | See path calculus below; fixed paths can have bag multiplicities beyond `N²`. | At most the distinct visible subject/object variables (same variable once); ground/blank endpoints expose no column. Program, traversal stack, frontier/memo and output coexist. |
| `Join` | Independent operands: checked `rL*rR`. Correlated production route: `sum_mu rR(mu)` over left rows, bounded by `rL*sup_mu rR(mu)` only when that supremum is certified. | `V=VL union VR`. Left/right bags, hash index/postings, column maps and output can coexist. Bound compatibility and duplicates do not justify lowering an unaudited product. |
| `LeftJoin` | `sum_mu max(1,rR(mu))`; independent safe form `rL*max(1,rR)`. Zero left gives zero. | Schema union, merged-condition expression owners, match flags/index, both operands and result. Padding appears only for a left row with no accepted match; matched rows and padding do not both appear for that row. |
| `Lateral` | `sum_mu rR(mu)`. A reusable RHS bound must be uniform over substitutions; a bound for the unbound original query alone is insufficient for a UDF/producer driven by values. | Driver bag, substituted AST/deferred-site metadata, copied bindings, all per-row RHS bags currently retained in `binop.rs::eval_application`, schema union and merged output. Admit each real per-driver block before growing it. |
| `Apply` | Same driver sum for ordinary application. With `policy.optional`, emitted count per driver is at most `max(1, first_rhs_bound)`: retry is a witness probe, not a second emitted bag. | Honor `inputs`, `retry_inputs`, `group_domain`, row-pipeline and adjacent-REDUCED policy. Current `evaluate_application_row_with` emits first results; if first is empty it runs retry, and pads one row only if retry is also empty. Charge both attempts' real transient ownership; do not multiply output by two. |
| `Filter` | `r(inner)`; filtering may retain every row. | Same schema. Expression VM, computed scratch, embedded EXISTS and predicate buffers coexist with input/output according to the actual move/clone path. |
| `Union` | Checked sum of every arm, including zero arms/empty arms according to constructed algebra. | Union schema; arm results, alignments and concatenated result. Preserve bag duplicates and source arm order. |
| `Graph` | Ground allowed graph: `r(inner,g)`; absent/disallowed graph: zero. Graph variable: checked `sum_g r(inner,g)` over allowed **declared** graphs. | `Vinner` plus graph variable if not already present. Empty named graphs and reflexive/unit patterns count. Named-graph/active-dataset vectors/sets and per-graph bags are separate owners. |
| `Extend` | `r(inner)`; ordinary expression error leaves its output unbound and retains the row. | Inner schema plus target according to actual collision rules. Row enlargement and computed value construction both need admission; row count does not bound lexical size. |
| `Minus` | `rL`, including a zero-width RHS whose presence may not remove any left rows. | Left schema only. RHS evaluation, shared-column map, index/postings and flags still cost memory even though RHS never publishes columns. |
| `Service` | Resolver response bound; no bound follows from the local dataset. `SILENT` failed invocation contributes its identity behavior; use a bound including that one-row case. | Returned schema, request/response/decoder buffers, forwarded engine and relation/error evidence. Propagate the shared owner/admission capability through the actual resolver; an already-returned unpriced `SolutionSeq` cannot be retroactively admitted. |
| `Values` | Exactly `bindings.len()` before downstream joins, including duplicate/all-UNDEF bindings and zero-column rows. | Variables deduplicated by actual schema. Authored constants are borrowed input; converted/copied/interner values, row cells and schema allocations are owned execution memory. |
| `OrderBy` | `r(inner)`; neither ordering nor LIMIT above it normally permits skipping the input. | Input bag + `r*number_of_keys` value array + equally shaped projected `SortKey` array + permutation + linked VMs + actual sort scratch + numeric parsed values. All products checked before capacity allocation. |
| `Project` | `r(inner)` even when output width is zero: projecting a bag does not remove duplicates. | Width is distinct requested variables in actual order, including requested unbound variables. Input, selection map and projected rows may coexist. Hidden subquery variables must not leak into output width. |
| `Distinct` | `r(inner)`; zero input stays zero, nonempty zero-column input reduces to one. | Same schema; dedup table plus retained rows and, where cloned, row-key allocations. |
| `Reduced` | `r(inner)`; no universal reduction ratio. | Same schema; account actual global/adjacent state selected by contextual policy. |
| `Slice` | `min(max(r(inner)-start,0), length)` when length is present; otherwise `max(r(inner)-start,0)`. | Same schema. This caps **output only** unless existing semantic ceiling analysis certifies pushdown through a given child. ORDER/GROUP/DISTINCT/opaque edges still need their true inputs. |
| `Group` | With group keys: at most `r(inner)`. No keys + at least one aggregate: at most `max(1,r(inner))`, with exactly one empty group for zero input. No keys and no aggregates: current implementation does **not** manufacture an empty group. | Distinct grouping keys plus aggregate aliases only. Input rows, group-key rows, hash table, row-index vectors, ordered groups, argument survivors, accumulator states, FOLD sort keys and outputs coexist. |
| `PropertyFunction` | Honest `rows_per_invocation(mode)` for the actual invocation mode, or dynamic cursor growth when genuinely unbounded. Driven calls sum per-driver bounds. | Width from call's output variables, respecting repeated/previously bound positions. Native cursor/workspace/output-value owners require actual pricing/admission. A row-count declaration alone does not price cursor scratch or term text. |
| `Unfold` | For each input row: valid list/map contributes its entry count; valid empty composite contributes zero; unbound/invalid/non-composite expression contributes **one unchanged row**. Sum these checked. | Inner schema plus element/optional companion. Computed composite cardinality is unknown until evaluation/parse; admit parser/entry vectors before growth, then emitted rows. Prebound targets can filter expansion; no shadowing. Nested composite re-render and counter/key terms require their own charge. |

For subqueries, these laws apply to the actual nested `Project`/`Group`/`Slice` algebra. Do not count every variable anywhere in the subtree as the subquery's output. For request substitutions, validate and price actual copied values, synthetic one-row probes and substituted ASTs. Bound a correlated query in the selected binding environment, including values larger than anything in storage.

### Property paths, all actual variants

`path.rs::eval_path` deliberately uses **bag** reach when the entire path contains no `ZeroOrMore`, `OneOrMore`, `ZeroOrOne` or `Range`; any repetition anywhere switches the evaluation to set reach.

For nonrepeating paths, define a per-source, per-direction bound `d(path)`:

```text
NamedNode/Wildcard:       d <= matching edge stream bound
NegatedPropertySet:      d <= forward eligible bound + inverse eligible bound
Reverse(p):              use p's opposite-direction bound
Sequence(p1,...,pk):      d <= product d(pi)          (empty sequence identity if constructible)
Alternative(p1,...,pk):   d <= sum d(pi)
```

Duplicate alternatives and different intermediate derivations remain duplicate answers. For both free endpoints, `r <= N*d(root)`; one fixed endpoint uses `d(root)`; both fixed endpoints still use `d(root)` as a membership multiplicity bound. A same-variable endpoint filters to diagonal pairs and cannot increase the bound. Degree bounds may safely fall back to `E` (or two certified eligible arm counts for a forward-and-inverse negated set); they need not guess a tighter branching factor.

For repetition-containing paths, reachable destinations are sets: both free endpoints `r <= N*N`; one bound endpoint `r <= N+1` is a safe uniform bound including a ground value absent from storage whose zero-length identity is legal; both bound endpoints `r <= 1`. With source-certified membership of the bound endpoint, the tighter `N` bound is available. At zero edges, a variable-variable `*` has no universe rows, while a bound absent IRI can still match its required reflexive pair. This is explicit in `path.rs::Endpoint::BoundAbsent` handling.

Memory is independent of emitted rows. Define `S` as the scoped endpoint universe plus any resolved bound endpoint IDs outside it (at most the two actual endpoints, deduplicated). A bound term can exist in the dictionary only as a predicate or in another graph, yet still seed reflexive reach in this scope. The set reach cache key is `(op, node, forward)` (`path.rs::ReachKey`), so a conservative entry bound is checked `path_ops*S*2`, with each destination set at most `S`; the two directions come from the actual bool key. Absent-ground identity is handled separately without an invented storage node. Cache table, `Rc` control blocks, BTree nodes, current/suspended frontiers and traversal frames all need real layout/local growth admission. Range's power memo is a separate owner: its 32 bit levels derive from the actual `u32` exponent representation, not from a tuned multiplier. A large `{n}` must not allocate `n` rows/frames when the existing binary-power algorithm does not. In bag mode, suspended `frontier`, `next`, returned child bag and alternative `out` coexist; locally charge append/extend before allocation rather than bounding everything by the final result.

## Query forms and publication

| `Query` variant | Output certificate and additional owners |
|---|---|
| `Select` | Materialized row count is pattern count; output width is actual final schema. Own variable-name strings, outer row vector, each row's term cells and **every copied term tree/string**, including computed terms. `eval.rs::materialize_solutions` must obtain/admit term size while storage guards remain held, before copying. |
| `Ask` | Public output is one bool; the current engine still evaluates the pattern and may retain its rows. Do not give ASK a one-row workspace unless the actual production evaluator has a certified existence short-circuit. |
| `Construct` | Plain template statement emissions are at most checked `pattern_rows*template.len()`, before dedup. Reifier/annotation rows count as statements too. Configured projection-loss declarations, minted RDF-list cells and auxiliary graph production add their **actual generated** rows/terms; admit at their existing emitting owners. Builder dictionaries/indices, template ordinal trees, graph slots/masks, per-row blank map, freeze sorting/dedup and rebuild-for-answer-cap must be included. Never infer full graph bytes from template cardinality alone. |
| `Describe` | Result statements are a subset of the stored three-stream dataset under the existing SCBD law. However `rdf-core/src/describe.rs::Describer::try_new/build` constructs **whole-view** ordinary endpoint adjacency, reifier endpoint adjacency and annotation adjacency before walking. Ordinary and reifier records can be indexed under two endpoints; annotations once. Admit those real BTreeMap/vector owners, subject strings, seed/frontier/visited sets and builder/freeze/output. Concrete-only DESCRIBE can skip WHERE; variable/star DESCRIBE materializes WHERE first. |

The current `Solution<I>` is `SmallVec<[Option<SolutionTerm<I>>;4]>` (`solution.rs:241`): four cells are inline in each outer row element, not four extra allocations. Width above four spills. `VarSchema` owns its column vector and only builds its deterministic hash index above eight columns. Price `size_of`/layout for the actual generic ID/term/row types and actual capacities; do not assume all backends have native `TermId` width.

Immutable result sharing does not eliminate the initial owned-copy allocation. A shallow clone carries the charge once through the shared payload; a raw deep copy, if exposed anywhere, must obtain a new allocation charge. Result, evidence, partial, and explanation payload must drop **before** its last charge/account handle. Final reporting may retain partial rows, soundness certificates, relation witnesses, parameter provenance, governor data and the full EXPLAIN tree; its size is driven by the actual plan/receipt, not a fixed 8192-byte reporting allowance.

## Expression calculus and actual before-allocation changes

Expressions do not independently multiply a solution bag, except that `Exists` evaluates a child bag and `Unfold` consumes composite entries. They can create unbounded-size terms with fixed output row/column counts. VM evaluation order/liveness matters: operand values, converted argument values and result may coexist.

| All actual `Expression` variants | Bound/owner rule |
|---|---|
| `NamedNode`, `Literal` | Authored input is borrowed; conversion/interning copies admit the actual lexical/datatype/language bytes and nested layout first. |
| `Variable` | Existing stored/computed identity is small; `value_of`/VM argument conversion can deep-copy its value and must acquire its own live charge. An unbound variable costs no payload. |
| `Bound` | Bool result with actual bool/interner layout; no source-term-size multiplier. |
| `Or`, `And` | Preserve actual short-circuit/error semantics. Charge VM instruction/value stacks and each evaluated operand's live owner; sum simultaneous owners, not a count of all operands assumed executed. |
| `Equal`, `SameTerm`, `Greater`, `GreaterOrEqual`, `Less`, `LessOrEqual` | Bool output. Term conversion, exact numeric parsing/alignment, temporal/string comparisons and native regex/type checks may allocate scratch before that bool; same-term identity fast paths need no invented payload. |
| `Arithmetic` | Strict left fold; each step prices both actual operand parses, live operands, native exact operation scratch/result and subsequent rendering. No reassociation. Use native exact Shape/Cost sizing home as discussed below. |
| `UnaryPlus`, `UnaryMinus` | Numeric parse, actual unary result/limbs and rendering; ordinary F&O domain failures remain expression errors, workspace failures do not. |
| `Not` | Bool output; child transient owners still count. |
| `In` | Bool output; preserve search/evaluation semantics and actual live argument values. No row product. |
| `If` | Only chosen branch is evaluated under the condition; charge its result and still-live condition/VM state. Static result bound can be max of branch bounds when both are certified. |
| `Coalesce` | Evaluate candidates in order until a successful value; discarded candidate payload releases its live charge. Scratch interned terms may remain until query end and therefore cannot be treated as released expression temporaries. |
| `FunctionCall` | Price actual argument conversion, implementation scratch and output at the function's allocation home; families below cover the enum and extension seams. |
| `Exists` | Bool output; child graph-pattern row/schema certificate in the actual correlated environment. Price substitution copies, prepared EXISTS caches/OnceLock owner, correlation-key vectors/maps, child evaluation and its result while live. Do not add its variables to the parent visible schema. |

Relevant homes: `expr.rs::value_of`, `xsd_of_term`, `arithmetic_step`, `numeric_step_admitted`, `governed_xsd_to_term`; `vm/compile.rs::ExprProgram`; `vm/mod.rs::Linked`, `pop_values`, linked regex slots, stack and reusable args; `scratch.rs::ScratchInterner::intern_value` and worker/ghost reconciliation. `scratch::value_bytes` explicitly calls itself a **deterministic proxy** and uses saturation. Its scratch-governor charge is not actual operational heap admission, and interning sees a `TermValue` only after its producer already allocated it.

### Function families and required allocation boundaries

- **Strings:** `Str`, `Lang`, `LangDir`, `Datatype`, `Iri`/`Uri`, `BNode`, `Concat`, `SubStr`, `Replace`, `UCase`/`LCase`, `EncodeForUri`, `StrBefore`/`StrAfter`, `StrLang`, `StrLangDir`, `StrDt` all copy or construct data. `CONCAT` admits checked sum of actual argument UTF-8 lengths **before** creating/appending the destination; copied language facets are additional allocations. SUBSTR/BEFORE/AFTER admit the actual selected byte slice before `to_owned`. Unicode case mapping and percent encoding can count their exact encoded byte length in a nonallocating pass, then admit/reserve/write, or grow a charged sink before each append. No character-to-byte multiplier guessed from a stored literal maximum.
- **Predicates/scalar strings:** `LangMatches`, `StrLen`, `Contains`, `StrStarts`, `StrEnds`, `IsIri`/`IsUri`, `IsBlank`, `IsLiteral`, `IsNumeric`, `IsTriple`, `HasLang`, `HasLangDir` yield bounded bool/integer values but may still copy arguments in the current VM. Avoid those copies where borrowed guards suffice; otherwise charge them before construction. Decimal digit length of an actual count is measured from that count, not from stored values.
- **Numbers/temporal:** `Abs`, `Ceil`, `Floor`, `Round`, `Year`, `Month`, `Day`, `Hours`, `Minutes`, `Seconds`, `Timezone`, `Tz`, `Adjust`, numeric datatype casts and exact operations use the current one XSD home. Admission belongs before lexical parse, limb operation, scale alignment and canonical rendering, including result/operand overlap. `Now`, `Rand`, `Uuid`, `StrUuid`, `BNode` must price the actual configured mint-prefix/counter/result layout and existing deterministic law; a caller prefix can exceed every stored term.
- **Hashes:** `Md5`, `Sha1`, `Sha256`, `Sha384`, `Sha512`, `Sha3_224/256/384/512` have fixed digest output lengths (twice their byte digest lengths for hex), plus actual algorithm state. The potentially large input ownership/argument conversion remains charged; streaming borrowed text avoids an unnecessary copy. Reuse current hash/hex homes.
- **Triple terms:** `Triple`, `Subject`, `Predicate`, `Object` use actual structural term children, boxes and any deep copies. A new triple can contain computed children larger/deeper than stored bounds. Charge the iterative conversion/traversal work list and each owned box/string before constructing it. Accessors that copy children need their own payload owner.
- **Regex:** Both compatibility and selected native XPath paths must be covered. `xpath_regex.rs::cached/resolve`, `expr.rs::cached_regex`, VM link-time constants and core regex compile/match/replace own programs, caches, matcher frontiers/capture buffers and result text. Native XPath already has finite-work/live-storage/output admission; compose that existing owner with the shared operational workspace, including retained program/cache ownership. Compatibility `regex` internals need a certified implementation sizing/admission seam at the core regex home; pattern length alone is not a compiled/cache heap bound. Replacement can count exact expanded chunks using the existing replacement cursor/capture spans or use an admitted append sink. `Cow::Borrowed(...).into_owned()` is a separate allocation and must be admitted even when regex reported no new output bytes. Selected XPath `replace.rs::append` already charges logical output before reserve; connect actual capacity admission there, preserving all existing flags/capture/error semantics.
- **Configured native `Purrdf`:** `HeldIn`, `ListLength`, `ListGet`, `ListIndexOf`, `ListContains`, `ListSlice`, `ListConcat` use their actual collection/frontier/cycle-detection owners and, for minting, blank labels and `rdf:first`/`rdf:rest` auxiliary graph builder. Admit actual list length and emitted structures locally; list concatenation can produce more than one stored term ever contained.
- **`Cdt`:** Include the closed `purrdf_cdt::CdtFn` dispatch in `cdt_fn.rs`, composite parser/constructor vectors, nested escaping/rendering, merging/append and maps. Count or grow at the actual CDT owner before allocation. Neither stored lexical size nor output row width bounds a computed CDT value. `cdt_unfold.rs` and `cdt_agg.rs` consume the same owners, preserving null/last-binding/order/distinct laws.
- **`Custom`:** SPARQL-bodied UDFs use the same workspace in the real child context, with argument/substitution/registry/result ownership and nested admission, then transfer surviving values into the parent without releasing live payload charges early. `NativeFnBody` is currently an opaque host closure returning an already-allocated `TermValue`; its signature has no scratch/result bound. Full bounded invocation therefore requires an honest argument-dependent **before-invocation** peak/output declaration or a callback allocation grant used by the actual native owner. Post-return `value_bytes` cannot establish that the callback respected the budget. The same obligation applies to expression-backed callbacks and custom aggregate factories. Wire actual supported native production implementations through that seam; blanket refusal of configured native contexts would leave required support unfinished.

### Exact numeric sizing: reuse, but do not confuse dimensions

`crates/xsd/src/exact/cost.rs` is the reusable source for `Cost`, `Shape`, lexical parse, add/multiply/divide, render, `sum_chain`, `compare_chain` and sort-round sizing. Kernel coefficients there describe the actual native exact implementation; do not reproduce a second arithmetic estimator in the evaluator.

However `Cost::saturating_add`, `Cost::then` and several `Shape` calculations saturate today. `Cost::then` takes maximum bytes because its documentation assumes the preceding value is released. The evaluator often retains operands, parsed sort keys, aggregate survivors or interned prior results. Add/use checked sizing at the exact sizing home (or a checked certified adapter with the same home-supplied shapes); combine **live** operands/results by sum, and only sequential disjoint scratch by max. Reject an impossible operation layout before parse/compute/render. Existing numeric governor work counters stay unchanged. `PlanEstimate::peak_cells` is also saturating and cannot be repurposed as a workspace certificate.

### Aggregates, all actual variants

- `Count`: no surviving value payload for COUNT-star's zero-sized units; DISTINCT-star may own projected row keys. Count result bytes follow the actual count's digits.
- `Sum`/`Avg`: argument value copies, survivor vector, parsed operands, running total/scale and division/render scratch are all live owners. Admit each actual step with native exact sizing, including the previous total until the new total is ready.
- `Min`/`Max`/`Sample`: output is a selected value, possibly copied. Comparisons can parse/align numbers even though the answer value existed already; charge those transient owners.
- `GroupConcat`: before rendering, exact output length is checked sum of surviving lexical byte lengths plus `separator.len()*(survivors-1)` for nonempty survivors. DISTINCT may reduce survivors but does not justify reducing the input buffer. Charge separator/argument copies, output capacity and final intern/materialization copies at their real lifetimes.
- `Fold`: `cdt_agg.rs` retains list/map terms, RDF-term identity dedup, per-aggregate ordering keys/permutation, then canonical composite rendering. Null elements are retained; null map keys drop entries; duplicate map keys follow existing last-binding law. Price actual retained items and encoded output, not row count times a stored-term cap.
- `Custom`: existing `CustomAggregate::state_bound` prices retained state but excludes factory box layout, simultaneous chunk/group states, transient `step/combine/finish` work and result text unless its contract is explicitly extended to include them. Admit actual supported factories before invocation; keep their declared honest state bound and price all other owners separately.

## Allocation implementation rules

`workspace.rs` provides checked `charge`/`set_base` and drop-bound `WorkspaceCharge`; use it at owners. A static base can cover certified fixed/control allocations once; child charges cover dynamic owners not already in that base. Do not double charge, and do not uncharge memory merely because its owning function returned.

- Vector/String reserve: checked target element count and layout size **before** reserve/clone/collect/push that can grow. Count existing capacity, new capacity and any replacement allocation overlap required by the actual growth path. Do not silently use `len` as allocated `capacity` or assume `try_reserve` only allocates the additional number of elements.
- Inline small vectors need no separate heap before their inline threshold; their containing row/vector already owns that inline layout. Charge spilling/replacement and copied payload independently.
- Deterministic hash tables need actual bucket/control-byte layout and growth overlap, not `entries*size_of(entry)`. Reuse the actual table owner's allocation calculation. BTreeMap/Set need their actual node-allocation admission; their total is not certified by `len*size_of(key)`.
- Arc/Rc/Box, schema/value strings, nested terms, iterator/cursor objects, plan caches, reporting tree/vector storage and cloned payloads each have real allocated layouts. Control/account creation also needs initial admission before allocating its Arc/Mutex owner.
- `parallel.rs`, `row_checkpoint.rs`, VM `fresh`, scratch sharing/ghosts and aggregate chunks can create simultaneous workers/results. Bounded operational execution's existing sequential-operation route avoids geometry-dependent claims where supported, but a shared admission account must still cover any real worker owner. Disabling semantic features or dropping supported relation evidence is not a solution.
- Native property functions/remote adapters/opaque callbacks need their genuine resource seam. A return-value measurement is too late for their scratch. Native text pricing is in the sibling engineering packet; incorporate that packet rather than a fabricated universal native multiplier.
- On resize refusal, do **not** allocate the refused buffer and continue until publication. Stop the affected production path immediately; the workspace's first typed failure remains available for final source-error precedence. Final publication validates both account and read-session status, discarding all partial data after a source/storage failure.

## Executable boundary cases for focused acceptance

These are inputs/expectations for existing real direct/prepared/governed/EXPLAIN entries, not a request for a per-case full build loop. Use current allocation probe and operational storage evidence after the coherent implementation is complete.

| Boundary | Expected behavior/proof |
|---|---|
