# PurRDF 列式模式

[English](COLUMNAR.md) | 简体中文

`purrdf-columnar` 用一组固定的五个 Parquet 文件表示一个 RDF 1.2 数据集和一个内容寻址的 blob 存储。`ParquetFiles` 值始终包含这五个文件；空表也有对应的有效零行文件。

所有表都是扁平的。Parquet 物理类型只有 `INT64` 和 `BYTE_ARRAY`；表示文本的字节数组带有标准 UTF8 注解。必需列每行恰有一个值。可选列的定义层级为 0 时表示 null，为 1 时表示有值。

## 投影失败

原生完整性错误通过 `ColumnarError::ContentStore` 或 `BlobContent { row, cause }` 保留原始 `ContentStoreError`，其中行号从零开始。结构化错误协议直接借用两个 SHA-256 摘要的原始字节。`Reconstruction` 保留完整的原始 `RdfDiagnostic`，包括存储错误和原生原因附件。标准错误链直接借用这些原因；传递时不格式化、克隆或分配替代原因。既有的人类可读消息前缀和冻结字节保持不变。

`project` 和 `write` 返回 `ColumnarWriteError<D::ReadError>`。`SourceRead` 变体按值保留原始 `DatasetView` 错误，`Codec` 变体保留原有的 `ColumnarError`。传递源错误时不会格式化或克隆它，标准错误链直接借用原始原因。源错误实现结构化错误协议时，检查会报告其原始嵌套字段。`read` 和已准备投影的 `to_parquet` 仍返回 `ColumnarError`。

## 表

### `terms.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `id` | INT64 | 必需 | 稠密的列式项 ID，从零开始。 |
| `kind` | INT64 | 必需 | `0` 表示 IRI，`1` 表示字面量，`2` 表示空节点，`3` 表示三元组项。 |
| `lex` | UTF8 | 可选 | IRI、字面量的词法形式或空节点标签；三元组项为 null。 |
| `datatype` | INT64 | 可选 | 字面量数据类型 IRI 的项 ID。 |
| `lang` | UTF8 | 可选 | 小写语言标签。 |
| `direction` | INT64 | 可选 | `0` 表示从左到右，`1` 表示从右到左。 |
| `scope` | INT64 | 可选 | 空节点作用域的序号。 |
| `triple_s` | INT64 | 可选 | 三元组项的主体 ID。 |
| `triple_p` | INT64 | 可选 | 三元组项的谓词 ID。 |
| `triple_o` | INT64 | 可选 | 三元组项的客体 ID。 |
| `named_graph` | INT64 | 必需 | 该项是已声明图的名称时为 `1`，否则为 `0`。 |

项字典包含从基础四元组、具体化节点绑定、注解和命名图声明可达的所有项及其递归依赖。行按项值的规范编码排序，而不按后端内部的 ID 排序。这样既保留了显式声明的空命名图，也使输出字节不受 `DatasetView` 实现的 ID 分配方式影响。

### `quads.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `s` | INT64 | 必需 | 主体项 ID。 |
| `p` | INT64 | 必需 | 谓词项 ID。 |
| `o` | INT64 | 必需 | 客体项 ID。 |
| `g` | INT64 | 可选 | 命名图的项 ID；null 表示默认图。 |

行不重复，并按 `(s, p, o, g)` 排序，默认图排在命名图之前。

### `reifiers.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `reifier` | INT64 | 必需 | 具体化节点资源的项 ID。 |
| `s` | INT64 | 必需 | 被具体化陈述的主体 ID。 |
| `p` | INT64 | 必需 | 被具体化陈述的谓词 ID。 |
| `o` | INT64 | 必需 | 被具体化陈述的客体 ID。 |
| `g` | INT64 | 可选 | 绑定所属的图；null 表示默认图。 |

行不重复，并按 `(reifier, s, p, o, g)` 排序。

### `annotations.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `reifier` | INT64 | 必需 | 被注解的具体化节点的项 ID。 |
| `predicate` | INT64 | 必需 | 注解谓词的项 ID。 |
| `value` | INT64 | 必需 | 注解客体的项 ID。 |
| `g` | INT64 | 可选 | 注解所属的图；null 表示默认图。 |

行不重复，并按 `(reifier, predicate, value, g)` 排序。

### `blobs.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `digest` | UTF8 | 必需 | 小写 SHA-256 摘要，共 64 个十六进制字符。 |
| `bytes` | BYTE_ARRAY | 必需 | 内容寻址的载荷字节。 |

行按原始摘要字节排序。读取器重新计算每个载荷的散列，摘要不匹配时拒绝读取；它不会修复损坏内容，也不会通过更改索引来接受这些内容。

## Parquet profile

每个非空表包含一个或多个连续行组，每个行组的每列只含一个 `Data Page V2`。空表不含行组。值采用 PLAIN 编码。可选列的定义层级使用 Parquet RLE 混合编码中的游程长度形式；模式是扁平的，因此没有重复层级。一次写入为所有值体选择同一种编解码器：UNCOMPRESSED 或 ZSTD。Zstd 是运行时选项，由始终存在的纯 Rust 依赖 `structured-zstd` 提供，不由 Cargo feature 控制。

页头和文件元数据使用 Thrift Compact Protocol。文件携带稳定的键值元数据，标明列式模式版本 `1` 及对应的逻辑表。写出器不输出时钟、RNG、文件系统信息或环境中的生产者信息。

读取器针对这一确切的模式和编码 profile。结构偏离、不支持的功能、格式错误的引用、无效的 RDF 位置、解压大小不匹配或尾随数据都会导致拒绝读取。

## 物理边界与行组流式处理

写出器按规范顺序消费行，并取下一个最长前缀，使每列的 PLAIN 值字节与精确的 RLE 定义层级字节之和不超出页大小字段的有符号 32 位表示范围，同时使行数不超出页计数字段的有符号 32 位范围。字节数组单元本身必须能用 PLAIN 的有符号 32 位长度表示。候选组编码后再测量压缩结果；若压缩页超出物理字段范围，则从候选组的中点拆成两半，按相同规则依次编码。单行本身无法表示时明确报错。

这些切分位置只取决于数据和所选编解码器，不取决于人为调节的行数常量或主机可用内存。全部行可放入一个组时，保持原有编码。文件偏移量和表行数使用有符号 64 位字段，页脚长度使用无符号 32 位字段。模式版本仍为 `1`。

读取器接受任意自洽且受支持的行组序列，无须复现写出器的切分位置或压缩字节。它在创建位图等大块解码内存或解压之前，核验列和页的大小、偏移量、行数总和、空值计数及 PLAIN 值计数。元数据集合项数以所在页脚的实际字节为界，不设任意固定项数上限。行的唯一性和规范顺序同时适用于组内和组间；后续行组发生错误时，整个转换失败。

不再设置人为选择的表字节上限。一个解码行组被消费并释放后，才处理下一个行组。项字典跨组保留扁平记录，以解析向前引用的数据类型和三元组项；语义行随后逐组写入数据集构建器。载荷通过摘要校验后，移入最终的内容存储。实际可寻址范围和经过检查的大小运算仍然适用。可表示的行组可能很大：页字段允许每列接近 2 GiB。

API 仍拥有输入或输出文件缓冲区，RDF 数据集和内容存储也保持常驻。写入还保留实现独立的项 ID 和排序所需的规范字典与已排序行元数据；读取保留项解析状态和构建器。页脚元数据随行组数量增长。行组流式处理移除了整表解码列和中间陈述表，不会消除这些必要的持有者。`project()` 仍是明确的急切求值关系表示；直接 `write()` 借用规范单元和载荷，无须先构造该表示。
