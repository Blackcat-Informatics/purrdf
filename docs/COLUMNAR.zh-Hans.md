# PurRDF 列式模式

[English](COLUMNAR.md) | 简体中文

`purrdf-columnar` 用一组固定的五个 Parquet 文件表示一个 RDF 1.2 数据集和一个内容寻址的 blob 存储。`ParquetFiles` 值始终包含这五个文件；空表也有对应的有效零行文件。

所有表都是扁平的。Parquet 物理类型只有 `INT64` 和 `BYTE_ARRAY`；表示文本的字节数组带有标准 UTF8 注解。必需列每行恰有一个值。可选列的定义层级为 0 时表示 null，为 1 时表示有值。

## 精确文件来源清单

PURREMB `source_format = 2` 通过以下规范二进制清单绑定实际的五文件模式 v1 集合。所有整数均为无符号小端序。

| 字段 | 编码 |
| --- | --- |
| 魔数 | 八个 ASCII 字节 `PURRCOLM` |
| 清单版本 | `u32`，值为 `1` |
| 表数量 | `u32`，值为 `5` |
| 每个文件记录 | `u64` 文件名字节长度、UTF-8 文件名字节、`u64` 实际文件字节长度、全部实际文件字节的原始 32 字节 SHA-256 |

记录严格采用 `Table::ALL` 顺序：`terms.parquet`、`quads.parquet`、`reifiers.parquet`、`annotations.parquet`、`blobs.parquet`。文件名使用 `purrdf_hash::frame::frame_le` 定界，无填充及尾随数据。所有文件均须包含，包括有效的零行 Parquet 文件；缺失文件不是空表。

`source_manifest` 从 `ParquetFiles` 计算这些字节，但不验证 Parquet 或认证 RDF。认证先完成严格的原生读取，包括每个 blob 摘要，再使用 `purrdf-rdfc12` 对重建的 RDF 数据集独立规范化。PURREMB 保存清单的字节长度和 `SHA256(manifest bytes)`，与认证的 RDF 摘要分开。

`read_with_ordinals` 完成与 `read` 相同的严格读取，仅保留请求的原始项、四元组、具体化绑定及注释行，行号从零开始。证据使用读取器显式的来源字典到内核映射，始终绑定实际重建的数据集。内核 ID 和最终迭代次序不是来源序号。空请求不保留陈述行证据；完成请求不能跳过后续行、表或 blob 的验证。

## 投影失败

原生完整性错误通过 `ColumnarError::ContentStore` 或 `BlobContent { row, cause }` 保留原始 `ContentStoreError`，其中行号从零开始。结构化错误协议直接借用两个 SHA-256 摘要的原始字节。`Reconstruction` 保留完整的原始 `RdfDiagnostic`，包括存储错误和原生原因附件。标准错误链直接借用这些原因；传递时不格式化、克隆或分配替代原因。既有的人类可读消息前缀和冻结字节保持不变。

`project` 和 `write` 返回 `ColumnarWriteError<D::ReadError>`。`SourceRead` 变体按值保留原始 `DatasetView` 错误，`Codec` 变体保留原有的 `ColumnarError`。传递源错误时不会格式化或克隆它，标准错误链直接借用原始原因。源错误实现结构化错误协议时，检查会报告其原始嵌套字段。`read` 和已准备投影的 `to_parquet` 仍返回 `ColumnarError`。

## 表

### `terms.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `id` | `INT64` | 必需 | 稠密的列式项 ID，从零开始。 |
| `kind` | `INT64` | 必需 | `0` 表示 IRI，`1` 表示字面量，`2` 表示空节点，`3` 表示三元组项。 |
| `lex` | UTF8 | 可选 | IRI、字面量的词法形式或空节点标签；三元组项为 null。 |
| `datatype` | `INT64` | 可选 | 字面量数据类型 IRI 的项 ID。 |
| `lang` | UTF8 | 可选 | 小写语言标签。 |
| `direction` | `INT64` | 可选 | `0` 表示从左到右，`1` 表示从右到左。 |
| `scope` | `INT64` | 可选 | 空节点作用域的序号。 |
| `triple_s` | `INT64` | 可选 | 三元组项的主体 ID。 |
| `triple_p` | `INT64` | 可选 | 三元组项的谓词 ID。 |
| `triple_o` | `INT64` | 可选 | 三元组项的客体 ID。 |
| `named_graph` | `INT64` | 必需 | 该项是已声明图的名称时为 `1`，否则为 `0`。 |

项字典包含从基础四元组、具体化节点绑定、注解和命名图声明可达的所有项及其递归依赖。行按项值的规范编码排序，而不按后端内部的 ID 排序。这样既保留了显式声明的空命名图，也使输出字节不受 `DatasetView` 实现的 ID 分配方式影响。

### `quads.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `s` | `INT64` | 必需 | 主体项 ID。 |
| `p` | `INT64` | 必需 | 谓词项 ID。 |
| `o` | `INT64` | 必需 | 客体项 ID。 |
| `g` | `INT64` | 可选 | 命名图的项 ID；null 表示默认图。 |

行不重复，并按 `(s, p, o, g)` 排序，默认图排在命名图之前。

### `reifiers.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `reifier` | `INT64` | 必需 | 具体化节点资源的项 ID。 |
| `s` | `INT64` | 必需 | 被具体化陈述的主体 ID。 |
| `p` | `INT64` | 必需 | 被具体化陈述的谓词 ID。 |
| `o` | `INT64` | 必需 | 被具体化陈述的客体 ID。 |
| `g` | `INT64` | 可选 | 绑定所属的图；null 表示默认图。 |

行不重复，并按 `(reifier, s, p, o, g)` 排序。

### `annotations.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `reifier` | `INT64` | 必需 | 被注解的具体化节点的项 ID。 |
| `predicate` | `INT64` | 必需 | 注解谓词的项 ID。 |
| `value` | `INT64` | 必需 | 注解客体的项 ID。 |
| `g` | `INT64` | 可选 | 注解所属的图；null 表示默认图。 |

行不重复，并按 `(reifier, predicate, value, g)` 排序。

### `blobs.parquet`

| 列 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| `digest` | UTF8 | 必需 | 小写 SHA-256 摘要，共 64 个十六进制字符。 |
| `bytes` | BYTE_ARRAY | 必需 | 内容寻址的载荷字节。 |

行按原始摘要字节排序。读取器重新计算每个载荷的散列，摘要不匹配时拒绝读取；它不会修复损坏内容，也不会通过更改索引来接受这些内容。

## Parquet profile

每个非空表包含一个或多个行组；每个列块含一个或多个 `Data Page V2`，选用字典时另有一个前置字典页。空表不含行组。原生读取器支持写出器发出的全部编码：`INT64` 使用 `PLAIN`、`RLE_DICTIONARY` 或 `DELTA_BINARY_PACKED`；`BYTE_ARRAY` 使用 `PLAIN`、`RLE_DICTIONARY`、`DELTA_LENGTH_BYTE_ARRAY` 或 `DELTA_BYTE_ARRAY`。可选列的定义层级使用 Parquet RLE 混合编码的游程形式；扁平模式不需要重复层级。

`Compression` 在运行时选择不压缩、默认级别为 3 的 Zstandard，或 `ZstdLevel(i32)`。数值级别范围为 -131072 至 22，零采用原生默认级别；越界值在准备源数据和输出前拒绝。`ColumnOptions` 可按表和从零起的列序号覆盖压缩或编码策略。底层实现是始终存在的原生 `purrdf-zstd`，不使用语义 Cargo feature。

`EncodingPolicy::Adaptive` 比较实际编码和压缩后的成本，平局选择 PLAIN。物理字典与 RDF 项字典分开；只有字典页与所有索引页的总成本更小时才选用。默认物理字典最多 4,096 个值和 1 MiB，预算包含载荷、索引、控制结构及替换分配的峰值。任一上限设为零即禁用物理字典。超出候选限制时确定性退回 PLAIN，实际分配失败仍作为错误传播。`Plain`、`Dictionary` 和 `Delta` 策略限制参与比较的候选。

页头和文件元数据使用 Thrift Compact Protocol。文件携带稳定的键值元数据，标明列式模式版本 `1` 及对应的逻辑表。写出器不输出时钟、RNG、文件系统信息或环境中的生产者信息。

读取器针对这一确切的模式和编码 profile。结构偏离、不支持的功能、格式错误的引用、无效的 RDF 位置、解压大小不匹配或尾随数据都会导致拒绝读取。

## 物理边界与行组流式处理

`write_with_options` 和 `write_to` 接受 `WriteOptions`。默认页目标为每列 1 MiB 或 65,536 行；行组目标为所有列合计 128 MiB 或 1,048,576 行。字节目标计算 PLAIN 值及各页重新开始的 RLE 定义层级，不含页头、压缩、索引和页脚。目标是工作偏好；较大的单值可以独占更大的页与行组，但仍须满足物理字段范围。页体、值长度和页行数使用有符号 32 位字段，索引记录的页头加压缩页体也须能用有符号 32 位长度表示。

压缩候选超出物理范围时，从行中点拆分并按顺序重新编码；不可拆的过大单行明确失败。切分位置只取决于输入和配置。字典与候选引用使用固定宽度预算，较小的主机指针不会改变编码选择。组目标、文件偏移量和表行数使用有符号 64 位字段，页脚长度使用无符号 32 位字段。模式版本仍为 `1`。

待写行组保留各列 PLAIN 缓冲区、可空列位图和每个非空字节数组值的主机宽度结束偏移量；单元借用规范准备结果。整数列不需要逐行偏移量。压缩和拆分借用缓冲区范围，每个子页重新生成定义层级。缓冲区跨组复用，其容量由最大已接纳行组约束；候选编码、字典、统计信息和输出另有存储。辅助元数据在每组连续列块之后发出，增长的页脚只保留其位置。

`write_to` 按 `Table::ALL` 顺序逐块回调 `(Table, &[u8])`。配置验证和经过检查的源准备在首次回调之前完成。`write` 与 `write_with_options` 收集同一输出到常驻文件缓冲区。`ColumnarSinkError<S, E>` 保留原始源或目标错误，不要求克隆或格式化。目标错误记录表、此前完整确认的字节数和尝试写入的块大小。失败回调可能已写入部分或全部块，甚至最终文件标记；之后不再回调、不回滚，也不认证输出。调用方负责临时文件与重命名事务。

## 剪枝元数据

每个列块和数据页提供最小值、最大值和精确空值计数；整数按有符号顺序，字节按 `TypeDefinedOrder` 的无符号字典序比较。文本边界保持精确且保留有效 UTF-8。二进制边界采用 64 字节软目标：下界是前缀，上界是严格后继；不存在有限短后继时保留完整精确最大值。精确性标志区分实际极值和保守边界。全空页没有极值，列索引使用空占位值及空页标志。

每列块发出标准列索引和偏移索引。位置覆盖数据页头及压缩页体，不含字典页；首行序号包含空行，边界顺序保守标为无序。辅助数据不计入列块的页字节总数。原生读取器验证配对偏移与长度以及连续范围，再进入下一组或页脚。

Bloom 过滤器通过 `WriteOptions::bloom` 或列覆盖显式启用。全局选择适用于整数和文本，列覆盖也可启用二进制载荷。`BloomOptions` 默认为每个存在值 10 位、位图上限 64 KiB。上限须为 32 字节的倍数，范围为 32 字节至 128 MiB；每值目标为 1 至 64 位。重复值计入数量，因此这只是不同值数目的上界。过滤器采用标准不压缩分块布局及零种子的 `XXH64`，对物理值字节散列，不含字节数组长度前缀。忽略空值，但空字节串是存在值。存储由上限及小型头部约束；饱和可能增加假阳性，绝不允许假阴性。

## 原生读取与内存限制

读取器接受任意自洽且受支持的行组序列，无须复现写出器的切分位置或压缩字节。它在创建位图等大块解码内存或解压之前，核验列和页的大小、偏移量、行数总和、空值计数及 PLAIN 值计数。元数据集合项数以所在页脚的实际字节为界，不设任意固定项数上限。行的唯一性和规范顺序同时适用于组内和组间；后续行组发生错误时，整个转换失败。

对于 ZSTD 页，原生帧检查会在分配位图或 PLAIN 缓冲区之前核验每个串联帧及可跳过帧的完整范围。已知的帧内容大小不能超出 Parquet 声明；全部帧均声明大小时，其总和必须完全匹配。未知大小由实际解压结果核验，帧校验和也在解压时验证。拒绝诊断区分帧头声明与解码器实际输出。

不再设置人为选择的表字节上限。一个解码行组被消费并释放后，才处理下一个行组。项字典跨组保留扁平记录，以解析向前引用的数据类型和三元组项；语义行随后逐组写入数据集构建器。载荷通过摘要校验后，移入最终的内容存储。实际可寻址范围和经过检查的大小运算仍然适用。可表示的行组可能很大：页字段允许每列接近 2 GiB。

在拒绝损坏的压缩内容之前，原生编解码器工作区和页体仍可能依据相互匹配的元数据分配内存。这些结构检查不构成独立的调用方资源准入策略。

API 仍拥有输入或输出文件缓冲区，RDF 数据集和内容存储也保持常驻。写入还保留实现独立的项 ID 和排序所需的规范字典与已排序行元数据；读取保留项解析状态和构建器。页脚元数据随行组数量的增加而增长。行组流式处理移除了整表解码列和中间陈述表，不会消除这些必要的持有者。`project()` 仍是明确的急切求值关系表示；直接 `write()` 将借用的规范单元和载荷消费到待写列中，无须先构造该表示。

## 测量与限制

原生 `codec` 基准使用共享确定性输入：500 个基础行生成 1,500 条陈述，覆盖重复谓词、高低基数字符串、排序及不规则标识符、可空列和小型载荷。`Reifiers` 另含 500 个重述绑定和 500 个注解；`LargeBlobs` 另含一个重复及一个不规则的 1 MiB 载荷。同一投影值经过独立比较，全部使用 Zstandard 级别 3。

| 工作负载 | PLAIN profile 字节数 | 自适应原生字节数 | Arrow 参考字节数 |
| --- | ---: | ---: | ---: |
| Mixed | 10,338 | 8,012 | 21,479 |
| Reifiers | 17,522 | 12,634 | 32,687 |
| LargeBlobs | 1,059,167 | 1,057,560 | 1,070,548 |

快速计时使用默认分配器、十个样本和 10,000 次重采样。完整 RDF 写入的 PLAIN profile 中位数分别为 1.954、3.564、7.571 毫秒，最终自适应写入为 5.687、10.70、15.14 毫秒；仅投影编码分别为 0.830、1.854、5.823 毫秒和 3.080、5.948、11.01 毫秒。Arrow 投影编码为 0.328、1.124、6.566 毫秒。候选比较在这些观察中增加了 CPU 成本；`EncodingPolicy::Plain` 可限制候选工作。共享主机、分时运行和宽区间限制了速度比较，不能宣称普遍加速。完整区间与方法见[英文测量表](COLUMNAR.md#measurements)。

候选比较以额外分配流量换取较小文件及剪枝能力。Mixed 的写入请求字节从 4,279,456 增至 6,312,632，峰值从 1,025,903 增至 1,013,897 字节。三个输入的目标回调写入完成后均不保留输出，但峰值仍包含规范准备和编码工作区，不能称为总内存有界。

独立的 1 MiB 载荷探针测得源准备峰值 7,357 字节，字典及已排序行常驻 5,596 字节，含输出和页脚工作区的编码峰值 5,245,000 字节；最大输出块为 1,048,746 字节。这些窗口不含原已常驻的输入，输出块和编码峰值有重叠，不能直接相加或相减。

三种负载的完整测量进程峰值 RSS 分别为 PLAIN profile 16,868 KiB、自适应原生 21,208 KiB、Arrow 20,380 KiB，含输入、验证、报告和文件输出，并非独立编码器大小。Arrow 的 Rust 分配计数不含 C Zstandard 工作区；整个进程 RSS 才包含该部分，不能据 Rust 计数推断总内存比例。

另一项五行组、1,025 行的等值剪枝测量恰有一个匹配。每值 4、10、16 位的过滤器分别选出 2、1、1 组，1,280 个已确认不存在的探针分别出现 94、7、0 次假阳性，过滤阶段实际文件读取请求分别为 890,494、447,284、448,054 字节，包含过滤器读取及缓冲造成的重复请求。全部存在值均通过过滤器检查。10 位默认值在此样本中平衡空间与收益，过滤器仍须显式启用；16 位的零次观察值不代表普遍无假阳性。

独立页索引选择还从 34 个候选行找回全部 11 个匹配，在仍含候选页的行组内留下 11 个完全未读取的排除页。这是带缓冲和缓存影响的实际读取请求证据，不是磁盘流量。运行 `cargo bench --locked -p purrdf-columnar --bench codec -- --quick columnar_codec` 可重现原生输入族；共享主机的快速样本需结合中位数和区间解释。RDF 准备与重构、Arrow 载体编码与导入是不同阶段，不能混为同一吞吐量。完整方法和限制见[英文测量说明](COLUMNAR.md#measurements)。
