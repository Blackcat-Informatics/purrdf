# PURREMB v1：PurRDF 数据集的确定性嵌入向量伴随工件

本中文读者指南对应[英文规范](PURREMB.md)的读者入口与访问、安全章节（§1、§2、§18、§21、§23）。数值编码和字节布局等规范性章节仍以英文原文为准；本指南不是完整的第二份格式规范。

## 1. 范围与符合性

PURREMB 是惯用扩展名为 `.purremb` 的文件所承载的二进制格式。一个 PURREMB 工件是针对某个确切 `.purrpck` 或五文件 Columnar 来源的确定性、便于内存映射的嵌入向量投影。它将向量行绑定到稳定主体，记录完整的向量生成契约，并携带完整性证据；它不改变来源 RDF 数据集、其 RDFC 身份或原生来源线格式。

精确存储的向量矩阵是嵌入向量投影的权威内容。近似索引只是派生的加速结构。矩阵和索引都不属于 RDF 规范身份。

关键词 **MUST**、**MUST NOT**、**REQUIRED**、**SHALL**、**SHALL NOT**、**SHOULD**、**SHOULD NOT**、**MAY** 具有规范性含义。

符合 v1 的写出器 MUST 输出本文规定的唯一规范表示。符合 v1 的读取器 MUST 拒绝所有明确列为错误的违反情况；对于格式不良的输入，它 MUST NOT 进行修复、重排、重新解释或无声截断。

PURREMB 不预设词汇表。本文的数字标签是二进制格式代码，不是 RDF 词汇表项。写入工件的每个 IRI、角色、媒体类型、算法标识、策略引用和扩展标识均由调用方提供。PurRDF 不提供特定本体的标识或默认词汇表。

## 2. 设计边界

PURREMB v1 提供：

- 与一个 pack 或 Columnar 来源的全部字节及其独立认证的 RDFC 摘要精确绑定；
- 语料、文档和块主体，其文本保存在外部并以内容寻址；
- RDF 1.2 数据集、图、陈述、具体化节点（reifier）、注释和项主体，包括带方向的字面量与递归三元组项；
- 确定性层级关系和依赖分词器的跨度；
- 完整的模型、引擎、分词器、执行、投影、预处理、分块、池化、规范化、截断、数值和距离度量契约；
- 按行密集存储、有限值 IEEE-754 `f32` 和 `f64` 矩阵；
- 固定维度和 Matryoshka 前缀向量族；
- 精确的外部工件绑定与不透明 ANN 防护；
- 从任何不可变字节切片（包括由调用方拥有的内存映射）借用数据；`purrdf-core` 无须依赖文件系统或 mmap。

PURREMB v1 不存储语料文本，不选择或训练模型，不定义领域语义，不执行 ANN 搜索，不重建来源内容，不对字节签名或加密，也不生成策略词汇表。量化、压缩、稀疏、跨步及非小端的权威矩阵均不属于 v1 编码。

## 18. 借用式读取器与访问语义

### 18.1 结构化打开

对不可变 `&[u8]` 进行结构化打开时，必须完成足够的验证，使其后每个访问器都不会越界或恐慌：

1. 文件头魔数、版本、固定长度、标志、数量上限、算术和文件精确长度；
1. 目录顺序、已知节的基数与标志、扩展规则、规范偏移、对齐、不重叠、零填充和文件尾封装；
1. 每个固定节头、记录大小、数量乘积、表跨度、池跨度、保留字段、内部顺序、唯一性与交叉引用；
1. 规范 TLV 封装、类型长度、标签顺序、关键性、UTF-8、填充、嵌套与大小上限；
1. 目标集合及矩阵形状算术、数据类型、空间、前缀与数据节之间的关系。

结构化打开并不声明密码学完整性、矩阵值有限性、投影摘要有效性、来源可用性或外部工件有效性。这些检查有下述明确操作。结构化打开的视图可以暴露精确的借用字节并安全解码标量，同时准确报告尚未验证的状态。

### 18.2 完整工件验证

完整工件验证还包括：

- 每一节的 SHA-256 与工件根；
- 可从已包含字节重新计算的每个类型化 ID 和内容摘要；
- 所有矩阵标量的有限性及保留零符号的解码；
- 所有原始投影与确定性 L2 投影的内容摘要；
- 全部目标身份块、关系、词元跨度、矩阵投影、外部绑定记录和索引防护之间的交叉检查；
- 规范文件尾及精确文件终点。

完整验证返回与确切字节切片、其长度及工件根关联的不透明驻留证书。只有库能构造证书。证书不能反序列化，也不能用于另一次分配、另一个切片范围或不同的工件根。对已验证驻留工件重新打开时可以使用证书跳过节哈希、标量扫描和投影重算，但仍须从被认证的切片构造边界安全的借用视图。

证书假定借用字节始终不可变。映射文件的调用方 MUST 在每个视图与证书的完整生命周期内，防止进程内或外部修改、截断、替换或打孔。

### 18.3 来源附着验证

来源附着验证接收完整 pack 或实际封闭的五文件 Columnar 集合，执行一次完整检查：来源或清单的长度及普通 SHA-256、声明的原生格式、RDF 数据集的独立验证、已认证的 RDF 摘要、数据集目标，以及全部已识别的来源内局部序号。Columnar 来源格式 `2` 使用 [COLUMNAR.md](COLUMNAR.md#exact-file-source-manifest) 定义的规范清单，覆盖五个实际文件，包括有效的零行 Parquet 文件。认证必须完成严格读取和全部 blob 摘要校验，再以 `purrdf-rdfc12` 规范化实际重建的数据集。精确匹配失败可在解码前停止，不得改用 RDF 比较代替。RDF 或序号不匹配有各自的错误。

Columnar 项、陈述、具体化绑定及注释的序号均为原始表内从零开始的行号。读取器通过显式的来源字典到内核 ID 映射，仅保留请求的行证据；完成请求后仍必须校验其余行、表及 blob。内核 ID、重建后的迭代次序、重新投影及 pack 序列化均不能替代来源行号。空节点标签来自对同一个实际数据集的规范化。

来源验证不改变矩阵访问，也不创建访问状态类型。报告记录独立验证的 RDF 摘要和检查的序号数量，避免调用方混淆已存储的声明、结构安全、完整工件的完整性，以及完整验证的来源附着。

### 18.4 必须提供的访问行为

符合要求的 Rust 接口提供 `EmbeddingBuilder`、`EmbeddingStreamWriter<W: Write + Seek>`、`EmbeddingView<'a>`、完整验证证书／报告、类型化身份 newtype 和结构化 `EmbeddingError` 所代表的行为。

结构化打开后，借用视图提供：

- 遍历向量族、有效空间、目标集合、矩阵、外部绑定和索引防护；
- 按行号以 O(1) 访问目标和矩阵行；
- 从 `TargetId` 到行号的无分配二分查找；
- 关系和向量族词元跨度的范围查找；
- 查找 `(TargetSetId, VectorSpaceId)` 唯一的投影；
- 对原始行与前缀字节零拷贝访问；
- 可移植的小端标量遍历；
- 在条件满足时取得对齐的原生标量切片；
- 无分配的确定性 L2 前缀遍历。

一个 `(TargetSetId, VectorSpaceId)` 对最多只能有一个有效矩阵投影。如果两条记录都满足同一次查找，工件就是格式不良。兼容性或距离辅助函数要求 `VectorSpaceId` 相等；仅维度相等不能证明兼容。

核心 API 不拥有文件、映射、线程池、墙钟、随机数生成器、模型运行时或 ANN 引擎。堆字节、mmap 字节、WebAssembly 线性内存及其他稳定的借用字节存储必须产生相同的逻辑结果。

## 21. 错误分类

错误是结构化的，保留可得的最具体上下文，例如文件偏移、节种类和实例、记录下标、类型化 ID、目标行、矩阵行和列、预期摘要及计算出的摘要。至少应区分以下类别：

- 错误的文件或文件尾魔数、不受支持的版本、固定长度错误、截断和尾随字节；
- 未知的关键节或 TLV、无效扩展范围、不受支持的代码、非零标志及非零保留字节；
- 整数转换或算术溢出、数量超限、越界跨度、重叠、未对齐、非最小偏移、非零填充及错误表大小；
- 未排序或重复的目录项、记录、目标 ID、目标集合行、关系、跨度、向量族前缀、矩阵对及索引 ID；
- 格式不良的 TLV、字段重复或缺失、线类型或长度错误、无效 UTF-8、嵌套过深及元数据块过大；
- 目标身份、种类、父级、RDF 位置、空节点作用域、递归三元组项、关系、词元跨度或来源局部序号不一致；
- 节摘要、工件根、目标 ID、向量族 ID、向量空间 ID、目标集合 ID、矩阵摘要／ID、投影摘要／ID、绑定 ID、防护摘要或索引 ID 不匹配；
- 行数为零、维度为零、矩阵字节长度错误、NaN、无穷值、零范数、无效范数、不可用前缀、数据类型不匹配及向量空间不兼容；
- 精确来源、已认证 RDF、外部工件、已认证外部 RDF 不匹配，以及索引防护组件已过期；
- 驻留证书的可变使用或不匹配使用。

不可信输入 MUST NOT 引发恐慌、越界访问、由数量控制的大规模分配、无界递归、整数回绕或部分受信任的视图。验证必须以错误终止，绝不无声省略必需的检查。

## 23. 隐私与安全考虑

嵌入向量可通过反演、成员推断、属性推断、相似性探测及与公开模型的关联暴露来源属性。近似索引可能额外包含图结构、量化质心、标签或搜索统计量，造成更多信息泄露。即使格式本身不提供也不保证从向量重建来源的能力，也应把向量和索引视为敏感的派生内容。

保留的规范目标身份字节可能直接暴露 RDF IRI、字面量词法形式、数据类型、语言标签和结构关系。语料目标块不含来源文本，但文档和块的内容摘要仍可能受到针对可预测文本的词典攻击。只保留摘要的目标记录会减少直接泄露，但不会使身份成为秘密。

外部标识、角色、策略引用、模型标识及 ANN 元数据也可能泄露部署信息。调用方必须避免把凭据、本地路径、个人数据和秘密策略值放入规范契约。

SHA-256 节检查、类型化身份和工件根提供损坏及不匹配检测。它们不认证作者、不建立信任、不保证时效、不执行授权，也不加密内容。真实性与保密性由 PURREMB 之外、受调用方控制的传输、存储、签名和加密系统提供。

内存映射不会使可变的底层存储变安全。借用视图所使用的映射，必须在整个借用期间保持不可变。映射前，使用者应实施常规不可信文件控制，包括稳定的文件所有权、有界元数据解析，以及防止并发替换或截断。

权威精确矩阵与 ANN 载荷及 RDF 规范身份保持分离。使用者可以丢弃所有派生索引，从经验证的矩阵重新构建，并得到相同的来源、向量族、目标、矩阵和投影证据。
