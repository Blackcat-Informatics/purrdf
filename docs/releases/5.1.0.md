# PurRDF 5.1.0

This release brings second-generation Graph Transport Substrate (GTS) to the
RDF dataset APIs and command line. It also exposes bounded recursive SHACL
validation on more hosts, expands native hashing and query execution, and
adds a checksummed source archive to the release workflow.

## Graph transport and C ABI

The dataset loaders accept GTS v1 and v2. Rust callers can write a committed
v2 segment with `purrdf_rdf::gts_write::write_gts_v2`. Python adds
`RdfDataset.to_gts_v2()` beside `RdfDataset.from_gts()`. JavaScript's
WebAssembly `Dataset` exposes `fromGts()` and `toGtsV2()`. The CLI writes
v2 with `purrdf convert --to gts` and accepts both generations on input.
For untrusted CLI inputs, use `--gts-safe-read`. Rust callers can use
`purrdf_gts::v2::read_with_limits` for bounded detection and reading across
both generations.

The v2 engine resolves references and suppression records and reports
unreadable content with its location. Signature verification uses keys and
trust supplied by the caller. Without them, signatures can be reported as
unverified. Rust callers can read indexed segments by byte range, which
verifies the fetched frames rather than the whole file, and stream blobs
from bounded sources. Dataset loaders require complete RDF inputs and return
the visible dataset. Use the Rust container APIs for recovery, the full
fold, reference records, or read evidence.

**C ABI 0.21.0** adds `purrdf_to_gts_v2` and extends `purrdf_from_gts` to
read both generations. `purrdf_to_gts` remains the profiled v1 writer, and
`purrdf_from_gts_with_limits` remains the caller-limited v1 reader. Existing
GTS function signatures and handle ownership are unchanged. The C header
also exposes explicit fixed-point requests for SHACL text and change
validation and for prepared shape products.

**GTS v1 anonymous blank nodes.** An absent or empty stored blank label
identifies a fresh node for each source entry. Native materialization,
events, and N-Quads now keep these nodes distinct from authored labels, even
when an authored label resembles a synthesized token. The raw lexical
accessor still returns the stored label. If you compare or cache projected
labels, treat them as local identifiers and compare RDF datasets up to
blank-node renaming rather than expecting the same synthesized spelling.

## Validation, querying, and hashing

- Recursive SHACL callers can explicitly select least or greatest fixed-point
  evaluation in the CLI, C, and WebAssembly surfaces. Supply both work limits
  with the recursion mode. Omitting the request still refuses recursion by
  default. Prepared products carry the shapes, and callers supply the
  recursion request when they admit or rebuild a product.
- SPARQL evaluates more DISTINCT and COUNT patterns without building
  disconnected products, streams more joins over segmented datasets, and
  retains native failure details for governed SELECT and ASK results. Python
  retrieval sessions reuse prepared producer indexes over an immutable
  dataset for repeated requests.
- BLAKE3 processes batches of independent messages through selected vector
  backends without changing digest bytes. PurRDF replaces the external
  `sha2` dependency with native SHA-256, SHA-384, and SHA-512 implementations.
- The English and Simplified Chinese books include a worked Chinese full-text
  example showing token positions and ranked results with and without a
  caller-supplied lexicon. The playground also supports Simplified Chinese.

## Packages and verification

Upgrade PurRDF packages together. Install the matching C header and library
when using the new ABI. Python's `purrdf` and `purrdf-rdflib` distributions
share the same suite version. The native wheel matrix covers x86-64 and
64-bit Arm on Linux, macOS, and Windows, with GNU and musl variants on Linux.

The GitHub release recipe includes the Linux x86-64 GNU C SDK and a distinct
source archive of the tagged tree. `SHA256SUMS` covers the attached archives,
license receipts, text lexicon bundle, and SHACL EARL reports. Verify the
checksums and the source archive's build provenance using the release guide.
