# PurRDF 5.0.0

PurRDF 5.0.0 changes what its canonical output is, replaces the additive row-set
identities with collision-resistant ones, and gives `SERVICE` and `LOAD` one
caller-supplied HTTP exchange. Upgrade the PurRDF crates together, and read the
migration guide before opening a 4.x artifact.

- The default canonical form is the nested-refinement labelling. The canonical
  document is the line sequence spelled as N-Quads 1.2 with decimal blank-node
  labels, and the canonical digest is its 32-byte BLAKE3 digest. Every digest
  moves, and the documents of datasets with blank nodes, reifiers, annotations or
  declared empty graphs change. RDFC-1.0 and the 4.x algorithm stay callable
  under `purrdf_core::rdfc12`, so stored 4.x digests still recompute, except for a dataset holding U+FFFE or
  U+FFFF in a literal, or U+007F or U+0080 to U+009F in an IRI that skipped the
  IRI parser. PACK,
  PURREMB and compaction certificates carry the version of the function that
  recorded their digests, and the readers accept both generations.
- Identities and fingerprints of a set of rows are BLAKE3 over the sorted row
  digests. Content identities, execution receipts, source version fingerprints
  and text index generations recorded by 4.x stop matching. Segmented images
  move to format version 8.
- A content identity is computed only when a caller asks for it, through
  `ContentIdentified`, so the first governed query on a fresh dataset no longer
  hashes every row. Execution receipts bind a view that has that capability.
- `HttpExchange` replaces `HttpTransport`. `LOAD` follows redirects through
  `HttpGraphResolver`, authorizing and admitting every hop.
- `GeoIndex::source_fingerprint` is a 32-byte digest. An unreadable stack floor
  refuses instead of disabling the stack guard. `Iri::normalize` keeps an encoded
  dot segment. An unsupported signing algorithm verifies as `Unverified`. The
  Python GTS fold view refuses a damaged file.
