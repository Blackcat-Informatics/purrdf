# Expression / VM transient payload owner proposal

`expr-vm-string-owner-draft.patch` is a standard source diff against the selected worktree. Read-only dry-run application passed `expr.rs`, `vm/mod.rs`, and `vm/tests.rs`. It has not been compiled or run. `expr-vm-owner-postimage/` is the reviewable postimage, not shipping source. The writer remains the sole shipping editor.

The actual native resolution door is `ScratchInterner::try_owned_value_of(dataset, term, &growth, source_error) -> WorkspaceTerm`; the new `expr::owned_value_of` maps source errors through `ctx.workspace.source_error`, preserving the original bounded source error owner. Production materializations in comparisons, IN, and nested constructor values retain this carrier. The old raw `expr::value_of` and `triple_value` become resident test-interpreter adapters.

Runtime `OwnedStringArg` stores the original `WorkspaceTerm` and a string/STR/LANG projection. It publishes only borrowed slices. Authored `ExprProgram::strs` remains the existing constant tuple pool; VM `StrArg` distinguishes borrowed constants and owned runtime views, so `pop_str` no longer clones or detaches String payloads. The accepted kinds are classified on a borrowed view before payload materialization, preserving STR/LANG's original early type refusal and avoiding nested reads for rejected triples.

The actual built-in/custom dispatch still consumes its original borrowed `[Option<TermValue>]`. `Arguments` owns two `AdmittedVec` metadata buffers: the value slots and their original grants. It admits both empty metadata slots while the `WorkspaceTerm` is still intact; only after both succeed does it transfer a raw value and its grant into the declared value-before-grant owner fields. `clear` drops values before grants. A SPARQL-bodied suspension moves this whole owner instead of `vals.to_vec()`. The link's static byte certificate no longer separately charges raw argument metadata; the real `Arguments` arrays own that charge.

IN needles and nested TRIPLE stack values now carry `WorkspaceTerm`. Native triple construction acquires a checked grant for actual moved payload capacities and three `TermValue` boxes before calling the sole `small::try_boxed` home. Input grants survive construction; the completed carrier retains the replacement grant. SUBJECT/PREDICATE/OBJECT clones only the selected borrowed component through `growth.clone_term`, then transfers that grant into the real scratch interner. Existing pre-admitted copy/case/CONCAT result helpers likewise transfer their original grant through `intern_workspace_term` instead of adding a second payload admission.

`expr-vm-string-owner-fixtures.rs` is an external-test proposal using existing segmented support. It pins the four actual direct/prepared/governed/prepared-governed entries for string-view semantics, plain/tagged/directional results, numeric type errors, exact duplicates, and nested constructor/component lifetimes. It is uncompiled and unrun, and cannot be used as a completed acceptance receipt.

## Exact other owner seams requiring their assigned units

This proposal is scoped to transient term/string views, VM argument ownership, nested constructor copies, and already-pre-admitted output transfer. It does not claim that every expression allocation is now covered. The root owns native regex compile/match/replacement and its ownership-carrying publication adapter. REPLACE input extraction is borrowed here; the remaining raw native replacement output and `make_string_dir` facet copy must be replaced by that adapter rather than treated as admitted by this unit. The root and writer must also retain ownership for the authored `Constant::value` CDT-blank binding path, native custom/SPARQL-body result production, persistent BNODE memo keys/table, URI resolution/percent output, STRLANG/STRLANGDIR facet construction, native partial CDT relation/NaN work lists, and std's lower-case allocator behavior where no fallible destination is provided. These are concrete source seams, not accepted exclusions from #508; complete #508 remains unqualified until they are implemented and tested in the writer's combined batch. Numeric promotion/arithmetic/render and aggregate survivor owners remain the numeric helper/writer's disjoint work.
