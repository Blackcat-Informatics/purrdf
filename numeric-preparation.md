## Settled architecture

1. **One big-limb engine at `purrdf_xsd::bigint::BigInt`.** Change its magnitude to little-endian binary u64 limbs using the donor's specialized storage. Preserve three inline limbs, owned spill, immutable shared ownership and admitted pooled destinations. Canonical zero has no limbs and is nonnegative. Equality/hash inspect canonical value, not storage kind. `exact::Integer` remains the domain/error facade with its checked i128 fast path and Small/Big canonicalization; it delegates every spilled arithmetic body to BigInt. This preserves constants and machine arithmetic without keeping a second big-number engine.
2. **One algorithm body with explicit storage policy.** Unbounded and admitted `_in` entry points use the same arithmetic body. Construct a LimbScratch pool only after its complete retained bytes and destination count are admitted. Exhausted/capacity/retained/size-overflow outcomes remain typed and actionable; admitted operations never allocate a fallback. A returned pooled immutable value may outlive the pool handle, clone without a new allocation and return its destination on final drop.
3. **Schoolbook plus binary Karatsuba now.** Preserve main's balanced and lopsided Karatsuba behavior and exponentiation-by-squaring. Port it to binary storage and admit its recursion/temporaries through the same scratch policy. Keep donor normalized division, correction/add-back cases, single-limb/u128/power-of-two special cases, Stein GCD, shifts, floor square root, ratio root, fused multiply/divide/remainder and product comparison. Do not leave `mul` and `mul_fast` selecting different public algorithms. Retune the crossover in binary limbs; 64 old decimal limbs is not 64 binary limbs.
4. **Fast decimal edges without a decimal-limb arithmetic alternative.** Keep chunked machine parsing/rendering for small values. For large values add divide-and-conquer conversion and operation-local admitted powers; avoid the donor's quadratic repeated 10^19 rendering. Preserve powers 2/5/10, exact decimal digit/zero metadata APIs, signed scale formatting and `div_rem_pow10`. Huge scales with tiny coefficients must be handled through shape/width guards rather than constructing enormous powers before admission. An exact decimal-digit API may do admitted work; the constant-time governor shape cannot call an allocating decimal conversion to recover digits. Use binary width metadata and proved decimal-length bounds for preflight.
5. **One canonical rational arithmetic implementation.** `exact::Rational` remains the public exact/Error API and its canonical `0/1`, positive denominator and coprimality invariants. Salvage denominator-GCD addition and cross-cancelled multiplication from donor Rat. Preserve donor admitted comparison/construction/rounding/difference/modulo capabilities as kernel/domain methods for the later math consumers, without retaining a second general rational implementation. Any geographic carrier facade only translates its established boundary semantics.
6. **One IEEE ratio rounding kernel with explicit domain adapters.** Share pure binary-limb ratio rounding for binary32/binary64 and directed boundaries. Preserve XSD's direct single rounding to binary32, signed infinities, canonical integer zero +0, and negative nonzero underflow -0. Preserve the established geographic Rat carrier's explicit final normalization of rounded zero to +0. Normalizing zero in the shared kernel would break XSD; aliasing the two public facades would silently change one boundary. Keep declared rounding-direction adapters explicit; do not pull floating-environment/control or all certified-math modules into this unit merely because donor ratio code is under `ieee`.
7. **Exact-only v4 values and seconds.** `XsdValue::Integer` holds exact::Integer; Decimal holds exact::Decimal. Remove BigInteger/BigDecimal discriminants and the bounded decimal/rational types and their obsolete conversion paths as the explicitly authorized breaking change. Machine-word arithmetic survives inside exact types. Date/time fractional seconds and duration seconds must hold exact::Decimal throughout parse, normalization, comparison, arithmetic and render, with no private i128/18-scale ceiling. Existing checked calendar years/months and datatype validity rules remain deliberate bounds.
8. **One finite-first division default on every host.** Reduced denominators containing only factors 2 and 5 produce the exact terminating quotient at its required scale; otherwise round once to 18 fractional digits, half-even. Explicit `exact`, `N` and `N:ROUNDING` retain their documented semantics and typed errors. The donor's `ExactOrScale` representation/text is useful, but its implementation is not presumed complete. Only NonTerminating authorizes the default's rounded branch; division-by-zero, scale overflow, resource refusal and other errors must propagate.
9. **One cost-law core, host adapters.** Replace decimal-limb laws with complete bounds for the actual binary algorithms, radix conversion, normalization, reduction, transient products, output, retained shared/pool headers and scratch lifetime. Keep exact::Cost's existing work/bytes caller seam and the later math admission seam as adapters to the same laws. No profile change is required merely for wrapper renaming; the binary work/default-law change requires the next governor profile and generator-owned first-party vectors. The live issue proposed v14 after today's v13; use the actual integrated foundation version, then give geodesy its subsequent profile rather than hardcoding stale numbers.

No new runtime dependency or semantic Cargo feature is needed. XSD remains over lex/hash. ## Public compatibility and correctness edges

- BigInt `div_rem` returns Option for zero; exact::Integer maps the same failure to ExactError::DivisionByZero. Preserve truncation toward zero and dividend-signed remainder. BigInt `div_rem_u64` returns the *absolute* machine remainder, which aggregate AVG relies on. Preserve i128::MIN parsing, negation, abs, cast and spill behavior.
- Existing const ZERO/ONE and constant query-default construction are public uses. The new finite-first default must still be const-constructible. Storage variants cannot make equal values hash differently.
- Narrowing to primitive integers remains checked. Derived XSD datatypes retain their actual value-space bounds even though xsd:integer becomes unbounded. Float/double promotion and OWL decimal/rational identity remain their established, separate contracts.
- Exact scale is currently u32; huge finite scale must stay exact within that representation. Do not replace the removed scale-18 cap with another accidental internal cap. Overflow beyond the declared representation must be typed, and resource admission must precede materializing its digits.
- The entire scratch pool's retained allocation remains admitted while values survive. Shared values and ghost-mint deduplication must not hide memory or double-charge ownership. Inline output does not by itself prove no-allocation intermediates: the donor has temporary carry/result capacities exceeding three limbs, so preserve observed zero-allocation paths and test boundary cases rather than promising all sub-192-bit operations allocate zero.
- Existing `exact_governance.rs:33` allows peak <= 4 * cost.bytes + 4096 and slack for traffic. It is a useful regression test, but does not alone prove the new hard "never under-report" law. Add focused actual-bound checks where the allocation definition requires them; retain separate traffic/work and live-output/working-set accounting.
