# Modifier owner draft integration

`modifier-owner-draft.patch` proposes concrete owner changes in five source homes; it changes only this Stage artifact. It has not been applied, formatted, compiled or tested. The parent and sole source writer must integrate it with the ongoing row migration. Its native key/VM/comparator calls are explicit mandatory integration seams, not already implemented APIs or claims of complete bounded ORDER BY support.

The concrete unit supplies `DedupState`, stable fallible ordinal merge, before-allocation arrays, and caller-owned numeric estimator scratch. DISTINCT and REDUCED preserve exact `SolutionTerm` equality and first-seen row order. Adjacent reduction preserves a single previous row across delivered blocks. General yielding DISTINCT preserves its complete seen set across blocks. Both state and output retain cell owners even when a source block is dropped; a refusal, expression failure, delivery stop or unwind drops the state and its real table allocations.

The hash table certificate is `purrdf_core::hash::hash_table_allocation_bound::<RetainedRow<I>>(requested_capacity)` before `hashbrown::HashTable::try_reserve`. Replacement is allocated while old table admission stays live; keys move, then the old bucket/control allocation dies before its guard is replaced. Membership hits do not allocate. No entry-size multiplier or randomized hasher is used. `WorkspaceCapability::charge` also covers its actual concrete guard box in the current account implementation.

The writer's current `SolutionSeq.rows: RowBag<I>`, consuming iterator, immutable dereference, `RowsBuilder::{new,push_row,finish}` and `RetainedRow::from_cells` are the selected APIs. `RetainedRow` currently has both Shared and Resident storage: ordinary Clone of Resident can deep-copy a spill. The proposed `clone_admitted` closes that engine clone path: Shared clones keep their existing lease without new allocation; Resident copies go through `from_cells`, which admits the actual `shared_layout<RowPayload<I>>` plus `Layout::array<Option<SolutionTerm<I>>>(width)` only when width exceeds inline capacity four, before exact reserve and fill. The exact actual spilled capacity belongs to that one builder. No source/global term multiplier prices a row clone. All actual operational producers must build/admit their engine-owned bags rather than manufacture new uncharged Resident allocations.

ORDER BY checks `row_count*key_count`, then admits actual arrays of Linked headers, `Option<TermValue>`, `OwnedSortKey`, and input ordinals. Its bottom-up stable merge uses a second `usize` array of the same length for n>=2, never hidden standard stable-sort scratch. Equal keys choose the left ordinal, preserving stable ties and the current ceil(log2 n) moving-side numeric estimator law. It evaluates every real key before sorting, preserves ASC/DESC and expression barriers, and does not use a LIMIT above ORDER as an input bound. `RowBag::ordered_admitted` consumes this internally generated permutation. Resident unbounded bags move cells in place through cycles, marking visited slots in the existing ordinal array with one stack-held row; no resident spill is cloned and no new bag vector is allocated. Operational output uses `RowsBuilder` and admitted row clones; dropping input/output in either order cannot shed their shared cell leases. The permutation's uniqueness is guaranteed by its sole producer, the ordinal merge; this is not a public arbitrary-permutation API.

The current implemented `ScratchInterner::try_value_of_admitted` covers the actual owned term copy/fold or computed-term clone before materialization. It retains those payload bytes in the shared execution account until final publication settlement. This draft uses that actual API; it does not claim each temporary source value has a shorter detachable lifetime than the implementation currently provides.

The XSD proposal extracts the existing `compare_chain` body into `compare_keyed(&mut [(i32,i64,i64,Shape)], rounds)` and exposes allocation-free `comparison_keys`. Resident `compare_chain` and operational callers use the same algorithm. Operational shape and tuple buffers use `AdmittedVec` with their actual layouts before construction; the estimator no longer allocates a hidden keyed Vec before admission. Saturated `Cost::then` remains logical governor accounting and must never price actual physical numeric scratch.

Mandatory integration APIs are `blank_scope::without_joined_blanks_admitted(seq, &workspace) -> Result<SolutionSeq<I>, EvalError>`; `vm::Linked::link_admitted(program, expr, schema, ctx) -> Result<Linked<I>, EvalError>`; `project_admitted(value: Option<&TermValue>, &workspace) -> Result<OwnedSortKey, EvalError>`; and `total_order_admitted(&SortKey, &SortKey, &workspace) -> Result<Ordering, EvalError>`. Their bodies are intentionally not fabricated here. The writer owns the first two through the ongoing schema/projection and VM migration. Native projection/comparison must share the existing `project`/`total_order` semantics, pre-admit XSD and CDT parsing, operand promotion/alignment, nested triple boxes and build/compare/drop work lists, then keep surviving parsed payload admission in `OwnedSortKey._allocation` until the key dies. A fee based only on lexical length, `Cost::parse`, `Cost::ZERO`, or stored maximum term size cannot replace those native owner proofs. These remain required before bounded support or guard removal is claimed.

The patch adds `with_capacity` and mutable element-slice access at the existing workspace `AdmittedVec` home; it does not duplicate vector growth. Adapt field/type spelling at this home if the writer has since changed it. Keep declaration/drop order payload before guard. Existing MIN/MAX, FOLD/CDT and value-ordering callers still need the shared projection/numeric owner migration; their raw calls are not made complete by this modifier patch. This draft does not change general projection, slicing, aggregate outputs or native parser laws beyond the estimator scratch split.

Focused acceptance after integration: DISTINCT of wide spilled rows with lexical-distinct numeric terms, repeated/unbound/nested triple terms and joined blank columns; repeats and adjacent ties across delivered blocks; drop source block before output; denied replacement table reserve with old state intact; allocator denial in table, row-copy, bag and merge buffers; ASC/DESC mixed classes and stable equal keys; large parsed integer/decimal and CDT/nested triple keys, including invalid lexical fallback; operational refusal during parse/alignment/EXISTS outranks diagnostics/SERVICE SILENT; governed truncation yields the same prefix/certificate and ORDER barrier; LIMIT 1 still prices full key input; observer confirms all covered allocations stay admitted through drop. No such checks were run by this support task.
