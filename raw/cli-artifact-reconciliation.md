# CLI artifact identities and invocation order

All whole-file identities below are `git hash-object --no-filters PATH` from the assigned governor worktree. Independent review also reproduced current hashes from outside the repository, excluding attribute/filter ambiguity.

1. Normal `cargo build --locked --release -p purrdf-cli --bin purrdf` produced slot `c72a4367891ad6f8/out/purrdf`. It was copied to external `compiled/cli-normal-release-final` and hashed as **e3178ec8c6f027736ebad7b5e34d508bedb5c8b9**. `readelf -S` only read this file.
2. That pristine artifact executed plain, fuel, inclusive600000-cell, corrected explain, and599999-cell refusal invocations. All functional TSV/counter/prefix evidence therefore binds to the normal shipping artifact **e3178ec8...**. The incompatible explain+fuel invocation was rejected before execution and is preserved separately.
3. `cargo rustc --locked --release -p purrdf-cli --bin purrdf -- -C strip=none` produced slot `66f30fd934727153/out/purrdf`. It was copied externally and hashed as **55ba305fbe3c94dea97646df0a1da0e640aff1b3**.
4. The first extraction command was `objcopy --dump-section .text=SECTION --dump-section .rodata=SECTION INPUT`, without explicit OUTPUT. This rewrote the external INPUT ELF metadata in place. The normal external file became **30b842d257af62f5ee38566d7dd059e0e05c4c98**; symbolized became **9ba23f4c73742d53e59e6a338f9a93bca2276dff**. The initial whole-file identity receipts predate this rewrite and must not identify the subsequent profiling invocation. Code/data sections are unchanged.
5. The actual perf invocation used the rewritten symbolized artifact **9ba23f4c...**, at the then-current `compiled/cli-symbolized-release-final` path. Its profiled full TSV equals the pristine release output. Its `.text`/`.rodata` are byte-identical to pristine normal release. The symbolized original and rewrite retain Build ID `2b27d0f05cd37b1ee779e5f3cfd1b248c2de31fd`.
6. Independent review caught the whole-file mismatch. Both rewritten artifacts were preserved under `compiled/cli-normal-release-final-objcopy-rewritten` and `compiled/cli-symbolized-release-final-objcopy-rewritten`. Original paths were restored from the untouched Cargo slots; those slot and restored hashes still match **e3178ec8... /55ba305f...**. `raw/cli-release-final-artifact-identities-reconciled.txt` lists restored normal, restored symbolized, rewritten normal, rewritten symbolized in that order.
7. Re-extraction now uses explicit distinct OUTPUT files `compiled/cli-*-release-section-extraction-copy`, preserving original INPUT. Original code sections compare equal to each other and the earlier section captures. `raw/cli-release-final-originals-after-safe-extraction.txt` confirms original whole-file hashes unchanged afterward.
