`951-968`: **🚀 Performance & Scalability** | **🔵 Trivial** | **⚖️ Poor tradeoff**

**Cache the dated source occurrences separately from the existing occurrence cache.**

`sparql_sources` is a `OnceLock`. A case can occur where it already holds sources for another law. Example: a `LEGACY` parse warmed the cache, and the caller then applied `set_validation_options` with a dated profile. In that case `self.sparql_sources.set(...)` at Line 967 has no effect. The result is discarded silently. Each later `report_sources_with_profile(dated)` call then runs `source_occurrences` again, which walks the whole declaration graph. That means one full declaration parse per validation or inference request. The test `a_warm_other_law_cache_cannot_grant_rec_declaration_admission` requires the original cache to stay unchanged. So the fix is a second slot, not an overwrite. One option is a small `Mutex<Option<Arc<ConstraintSources>>>` keyed by the admission identity.

<summary>crates/shapes/src/rules.rs (1)</summary><blockquote>

`812-816`: **🚀 Performance & Scalability** | **🔵 Trivial** | **⚖️ Poor tradeoff**

**Stop cloning the whole `Shapes` model on every dated `infer_complete` call.**

`PreparedShapes::new(Arc::new(shapes.clone()))` deep-copies every node shape, rule and target on each inference. This happens whenever the profile is not `LEGACY` or an XPath regex is set. Only `Request::admit` uses the clone, and it reads `validation_options`, `report_sources_with_profile` and `xpath_configuration`. The clone also discards any occurrence cache warmed by `Request::admit`. The next call starts cold and parses the source occurrences again. On large shapes graphs, this adds clone and reparse work in proportion to the model size to every rules run. Let `Request::admit` take the borrowed `&Shapes` together with the XPath configuration source. As an alternative, accept an `Arc<Shapes>` in `infer_complete`.

`2275-2283`: **📐 Maintainability & Code Quality** | **🔵 Trivial** | **⚡ Quick win**

**Reuse `declared` for the query-law invocation instead of building `potential`.**

`potential` holds `this`, every scope binding name, and every `arg_key.variable_name()`, in that order. Lines 2334-2337 build `declared` from the same three sources in the same order. The code now has two lists that must stay equal. A later edit to one list can change the dated admission set without changing the grouping-check set.

Build `declared` once, before the argument loop, and pass it to `Invocation::with_declarations`. This also removes the duplicate `String` allocations on the dated path.
