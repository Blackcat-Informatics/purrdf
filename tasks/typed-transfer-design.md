## Native boundary and representation

Current mutable::added/suppressed membership is QuadKey(s,p,o,g), while base_occurrences counts the same value separately in ordinary/reifier/annotation tables. This is insufficient for an explicit physical ingress: a new annotation equal to an existing ordinary row is discarded; un-suppressing one flat key restores every base occurrence. Adding a kind field and immediately calling insert(QuadValues) would retain neither fact.

Add public types beside QuadValues, re-exported through the existing core IR facade; leave QuadValues and DatasetMut's associated Quad/signatures unchanged:

```rust
#[non_exhaustive]
pub enum RecordKind { Ordinary, Reifier, Annotation }
pub struct RecordValues { pub kind: RecordKind, pub quad: QuadValues }

impl MutableDataset {
    pub fn insert_record(&mut self, record: RecordValues)
        -> Result<bool, RdfDiagnostic>;
    pub fn remove_record(&mut self, record: &RecordValues) -> bool;
    pub fn records_for_pattern(/* same value/pattern/graph arguments */)
        -> Result<Vec<RecordValues>, RdfDiagnostic>;
}
```

These are additive native APIs. insert_record means the EXACT physical table, not a hint for inference. Its reifier representation has canonical rdf:reifies predicate and triple-term object; enforce these and ordinary subject/predicate/graph admission through the owning builder checks, extracting a shared private check there if necessary. Do not duplicate validation or reifier classification in update.rs. Wrong kind/position/IRI fails before a physical row is inserted. remove_record probes existing terms without minting, like existing remove. Owned records_for_pattern is a stable snapshot in existing table/call order; it refuses invalid unpublished delta positions through that same admission home. Term handles remain internal tagged MutTermId; public values never expose cross-dataset TermId.

Internal membership becomes RecordKey{kind,quad:QuadKey} for added/suppressed/ordinal identity. Equality is kind+s+p+o+g. Same-kind equal-value rows deduplicate; cross-kind equal-value rows coexist. Primary storage, term interner, source order and classification remain in mutable.rs. Use its existing indexed base probes for each role, not a base-wide flat set. Suppression refers to a physical base row, never a new delta row. Added and suppressed can contain equal QUAD values of different roles, but never the same physical RecordKey.

## Exact state transitions and counts

For one physical key K, typed insertion: visible base/added K returnsfalse; suppressed base K removes ONLY that suppression and returns true without adding a delta duplicate; absent K adds one delta record with a fresh insertion ordinal. Equal-value OTHER roles are neither un-suppressed nor deduplicated. Typed removal drops added K and its ordinal, or suppresses the one visible base K; repeated removal returnsfalse. Typed reinsertion of a removed delta record must use its RecordValues to restore that role; the value-only API cannot infer a discarded explicit role history.

Ordinary DatasetMut keeps its whole-value contract. insert(q) first restores ALL suppressed base physical occurrences for q, as today; it does not add another delta copy of those keys. If no base occurrence was restored and any physical q is already effective, insertion remains a no-op. Otherwise it routes q through the existing automatic RDF1.2 classification home. remove(q) removes EVERY effective physical occurrence of that value: all added roles are dropped and all matching visible base roles suppressed. The current early delta-return shortcut must be generalized because the new representation permits a delta role and different base role with equal values. Pure old-API programs retain their four-rule outcomes; explicit typed users have exact single-role mutation.

Concrete required regression: base ordinary(q)+annotation(q), no added rows. Ordinary remove(q) hides2, suppressed_rows=2. Typed insert_record(Annotation,q) restores EXACTLY1: ordinary still suppressed, no added duplicate, effective_count rises1 and graph count rises1. Typed repeated insert returnsfalse. Ordinary insert(q) then restores the remaining ordinary occurrence only: effective_count rises1, both roles present. Reversing requested role gives the symmetric result. The same scenario must cover a valid equal-value ordinary/reifier group. No value-key suppression fallback is allowed.

Ordinal is attached to each newly added RecordKey, not to q. Removing/readding that role gives a new ordinal; equal-value other roles keep theirs. Un-suppressed base rows retain original table order and never get a delta ordinal. Snapshot iteration groups ordinary/reifier/annotation as the existing importer requires, retaining call order within each added stream. Replay is independent of hash-map iteration and of annotation-before-reifier insertion order.

Maintain the physical cardinality law:

`effective_count = base.rdf_row_count + added_record_count - suppressed_physical_base_count`.

Each role-qualified base suppression contributes1, so there is no ambiguous base_occurrences subtraction. Every state transition computes before/after visible role membership and applies the EXACT net row change once to graph_rows. Do not decrement then increment graph lifetime during an internal role replacement: a net-zero transformation must not temporarily withdraw an Implicit slot. Seed untouched base counts through the existing named_graph_row_count home. First effective row restores withdrawn-base presence; last-row removal withdraws in Implicit and retains RememberEmpty unless explicitly withdrawn. Metadata declarations remain separate from physical row counts and mutation fuel. Clone, checkpoint and retained snapshots copy/share the same masks/ordinals/policy and cannot observe later mutation.

## Classification, delta views and freeze: one coherent path

Typed ingress is a PHYSICAL path: a typed ordinary row shaped like rdf:reifies remains ordinary; an orphan annotation remains annotation; explicit reifier/annotation/ordinary records with equal values stay distinct. It must not trigger the current append_delta heuristic or has_added_reifiers-based promotion of unrelated physical ordinary rows. Ordinary DatasetMut remains the classifying path, including declaration-shaped quad inference, graph-scoped annotation inference, subsequent ordinary reifier promotion and declaration-removal demotion. Existing classify_statement is the single rule home; extract its current append_delta declaration decision there rather than implement another classifier in importer/update.

The smallest coherent storage cut is to normalize automatic classification in the mutable owner when the relevant ordinary mutation changes a graph-scoped reifier relation. Exact typed operations do not perform that implicit recategorization. An ordinary row newly inserted while any effective reifier applies is still inferred as annotation. An ordinary declaration insertion can recategorize affected legacy rows as it does now; this is an intentional ordinary-API semantic mutation, not a typed transfer promise. Preserve original-reifier/orphan conditions from classify_statement and existing demotion tests. Keep origin/admission bookkeeping only as needed for delta automatic rows; frozen physical tables are the authoritative next base, not a persisted caller-policy sidecar.

Reclassification uses indexed affected(subject,graph) rows and the delta's local keys, not a full base materialization. For a base physical role change, suppress the old role and admit the new role through the SAME membership transition home; if the new same-kind key already exists, deduplicate and apply the real net cardinality. Preserve ordinal on a role conversion of a delta row; duplicate merges retain the earlier surviving ordinal. This also fixes the accounting hazard where lazy classification changes exposed cardinality without updating graph_rows/effective_count. Classification bookkeeping consumes no additional invented quad fuel; governors continue charging the requested operation's original physical snapshot attempts.

Then append_delta is typed dispatch only: intern terms once through existing memo/interner and push_quad/push_reifier_in_graph/push_annotation_in_graph according to stored kind. DeltaAdmission counts every actual typed row/term/payload and uses the correct larger role-qualified suppression/index byte charge. DeltaDatasetView must use role-aware masks and same-role duplicate indexes; cross-role values must never suppress/deduplicate each other. Remove its second lazy recategorization route once the owner has normalized ordinary mutations; do not classify exact transferred records again. changed_quads retains its existing surface-change contract, including repeated values for distinct physical additions/suppressions. Pattern reads/counts/view statistics must describe the same normalized physical set.

freeze stays snapshot_view → existing DatasetImporter::append → validated builder.freeze. No new flatten/replay freezer. DatasetImporter already appends three typed tables with one term memo; extend its record-value export/translation seam in ir/import.rs so both native frozen LOAD sources and MutableDataset transfer snapshots use the same typed traversal. Preserve ordinary base locations on surviving ordinary handles, declared graphs and sidecars under their existing owner; newly inserted transfer rows keep the current mutation location policy. Test after each mutation that exact typed tuples, effective_count, graph live count, snapshot streams and freeze tables agree, including duplicate-role collisions and classification transitions.

## ADD / COPY / MOVE and existing lifetime boundaries

Take an owned typed source snapshot BEFORE clearing or writing another graph. Preserve current admission/self-target order: Implicit ADD self remains no-op before admission; remembered ADD admits missing input first; COPY/MOVE self remain immediate no-op as written. Missing remembered source errors or SILENT no-op remain; absent Implicit source contributes no records. The source snapshot prevents aliasing/self-target corruption and retains original term identities (these transfers DO NOT freshen blanks).

- ADD charges N source physical attempts, rekeys and insert_record; source/destination prior records remain; success remembers named destination even for admitted empty source.
- COPY clears destination through its existing separately charged physical removal/declaration behavior, then charges N and inserts typed snapshot. A later insertion-budget trip must retain today's cleared-destination prefix behavior. It must not mutate source or invent new blank identity.
- MOVE clears destination, charges2N as today, inserts rekeyed typed records, removes original physical records with remove_record, remembers destination and withdraws source declarations. Removal is role-specific so equal-value source roles are neither restored nor accidentally dropped in another graph. Empty source still has its declaration withdrawn in remembered mode.

Keep charge_stop and physical snapshot cardinality rules for CLEAR/DROP. Declarations are metadata, cancellation-checked, not additional quad fuel. Implicit last-row behavior and RememberEmpty retention/explicit withdrawal remain exactly selected until the later default switch.
