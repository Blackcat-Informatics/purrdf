## Exact request/options and governor ordering

VERSION admission runs before counter initialization or any mutation. eval_update owns one counter initialized once per request; INSERT DATA and template/EvalCtx mints advance it, and delete_insert writes the context's counter back. LOAD must participate in that same sequence. Current apply_operation polls stop before each op, eval_update polls again after each successful op. `QueryOptions::EMPTY` and explicit `with_graph_existence` are existing options; Task2 must not switch Implicit default or drop current regex/function/remote configuration.

Current LOAD order is resolver presence -> stop -> RemoteRequestIssued fuel plus RemoteRequests1 -> resolver.resolve(GraphResolveRequest{iri,stop}) -> post-return stop. Absence/fetch/decode/denial/fault become ordinary typed diagnostic or recorded SILENT no-op; governed resolver errors are never silenced. Successful resolver return after cancellation is refused before ingestion. Preserve the nonsilent failure versus simultaneous stop ordering and SILENT surviving-stop branch. Do not mint, insert or declare a graph on absorbed failure.

After successful fetch and destination admission, collect the exact physical source records; a reifier and annotation equal to an ordinary row are separate attempts. Charge the ORIGINAL source count before first insertion, even if destination same-kind dedup later does nothing. Do not charge only normalized/deduplicated output or blank-map size. Successful empty LOAD has zero row charge and no mints, but remembers named destination only after success/stop admission. Graph declarations are metadata with stop polls, not invented UpdateMutatedQuad fuel.

ADD retains Implicit self no-op before admission, RememberEmpty source admission before self no-op; COPY/MOVE self remain unconditional no-op. Missing remembered source refuses unless SILENT; missing Implicit source contributes empty records. ADD chargesN attempts; COPY first clears destination (charged separately), then chargesN; MOVE first clears, then charges2N, writes destination and removes exact source roles, remembers destination and withdraws source declaration. Preserve saturating count-to-fuel conversion and existing typed governor reports. Source snapshot must survive clear and aliasing.

**Private prefix versus public atomicity:** update.rs changes its PRIVATE MutableDataset incrementally across operations; COPY/MOVE can clear destination before a later insertion charge refuses. Preserve that local order. `engine.rs::update_governed` drops the whole private branch on any trip/error, polls again before freeze and after freeze, and assigns the caller Arc only on complete success. Thus no governed partial prefix is externally published: original store and original Arc identity remain unchanged on refusal. Ungoverned failure also skips the final assignment. The existing baseline design's prefix wording must not be read as permission to publish a partially applied update or add private snapshot/restore machinery.

## Pair map, checked minting and CDT callback

Select destination with existing graph_target_value; discarded source graph names must not be preserved as LOAD declarations. Collect referenced blank pairs in S/P/O, nested triples and real CDT literals through TermValue::visit_blank_identities, using first-occurrence order (not hash iteration) for deterministic mints. Source labels with distinct scopes are distinct keys. A fresh map is required on EVERY successful resolution, including identical IRI and cached Arc. Repeated occurrences within that document share one pair; subsequent LOADs advance request counter and later requests use destination namespace inventory including unused/suppressed/CDT-only identities.

Preflight unique referenced-pair count with checked usize-to-u64 and counter.checked_add before minting/translating. A capacity refusal must become actionable UpdateAbort::Failed(RdfDiagnostic) through the actual error home, before insertion/declaration and without overflow or weakened counter test. Existing template::mint_blank and EvalCtx::try_mint_blank_label currently increment directly; do not assume they already establish a LOAD batch capacity refusal. Use existing eval::minted_label(prefix,"c",ordinal) spelling rather than another formatter/namespace algorithm. Destination BlankScope stays DEFAULT; freshly disjoint labels are sufficient identity.

The CDT helper accepts ALREADY-BOUND lexical forms and calls `FnMut(&str)->Option<String>` with the token label WITHOUT `_:`. Decode via `decode_blank_label(token,LabelAlphabet::BlankNodeLabel)` to recover its original `(label,scope)`. Look up the same map used by bare blank leaves. Encode the destination with `encode_blank_label(fresh_label,DEFAULT,BlankNodeLabel)` and return the FULL replacement string `_:<encoded>`, not a bare label. Nested CDT values/escaped literal content are handled by the existing scanner/splice owner. None means leave unchanged; it MUST NOT silently stand for capacity/missing-map failure.

Preparing and validating the complete map before folding makes normal callbacks infallible. If a lookup invariant can still fail, capture a typed failure and reject the containing fold/document immediately after the callback returns, BEFORE any insertion; unchanged temporary bytes must never become a successful fallback. Do not implement a new generic fallible CDT parser or scanner. A loaded resident builder already binds/validates real composite forms; non-CDT literal `_:` text is opaque and stays unchanged. Match literal fields intact except lexical replacement; reconstruct triples through iterative fold, not recursion. Poll existing stop boundaries and immediately before row/declaration publication so cancel-only requests remain refused even with unbounded fuel.
