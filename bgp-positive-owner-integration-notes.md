# Native BGP forecasting and retained positive-plan ownership

Shipping source is unchanged by this support lane. These are proposed standard patches, read against the current production bodies; no build, test, Git apply check or forge action was run here.

Apply the already integrated cost/depth/compiler prerequisites, then the following as one paired source unit:

1. `bgp-forecast-owner-draft.patch`: `SeedEstimate.bound` becomes an immutable admitted `VarSchema`; `from_rows_admitted` retains the real incoming binding law. Forecast compilation, masks, cost orders, replay domains and source-ordered real schemas use original grants before allocation. The actual survey keeps admitted step and driver tables and native named-graph terms, and receives the original `QueryWorkspace<D::ReadError>` for typed read-error precedence.
2. `positive-plan-owner-draft.patch`: same eligibility, bottom-up forecasts, shared certainty counts, deterministic driver scoring and selected-schedule replay. Actual pending tables/arrays and seed shared controls are admitted. Certainty/schema clones are shallow; unions/intersections use the native schema home. Width scoring computes the exact borrowed union count without constructing a schema solely to count it.
3. `positive-plan-production-callers-draft.patch`: wire real JOIN, OPTIONAL, correlated EXISTS and ordinary/refusal/EXPLAIN survey ingress through that same original account. The existing explicit resident test entries share the native bodies.

The common dependencies are `certainty-owner-draft.patch` (`collect_certainly_bound_admitted(pattern, cap) -> Result<VarSchema, EvalError>`) and `invocation-mode-owner-draft.patch` (`invocation_mode_with_memory(call, membership, Memory) -> Result<BindingPattern, StorageError>`). Neither certainty nor nullable scope is replaced by syntactic schema. Physical layouts are checked; the pre-existing saturating cardinality estimates stay estimates with their same mathematics.

`BgpOrder` is one shallow immutable selected-order carrier: caller-owned `Arc<[usize]>`, or originally admitted native array and shared control. Positive-plan unit orders use `BgpOrder::from_admitted`, and actual selected-order BGP parameters carry it through execution. No raw native array/control can escape by cloning the plan order.

Its current unselected-order route still returns a raw `Arc<[usize]>` from `plan_or_cached_order`, and its per-occurrence `initial: Vec<bool>` remains raw. The same actual owner must cover nested hash/constraint walks in that existing cache key body. This unit does not claim those producer obligations complete.

All typed failures still stop the supported computation; no supported path is refused as unpriced, no static multiplier prices growing computed terms, and no cap is introduced. Existing independent recursive/differential forecast and positive-UNION fixtures keep their original expected results; only carrier/access adaptations are proposed. The public operational tight-cap/healthy/parity fixtures remain the actual allocator and lifetime proof and must pass after the full paired owner closure.
