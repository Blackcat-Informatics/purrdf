## What current code establishes

1. `PagedDataset::from_provider` eagerly materializes every page once, builds its value dictionary and private local-space summary, and rejects overlap separately in primary/reifier/annotation streams. `from_parts` reconstructs from sealed metadata without content reads. G3 remains a hard invariant WITHIN each sealed generation; introducing a logical stack does not authorize weakening page overlap validation.
2. G0/G1 establish a separate `GlobalTermId` dictionary generation per paged dataset. Equal numeric IDs in different generations can name different terms. A new delta's values cannot be numerically translated into the base's dictionary.
3. `PagedQueryView` owns operation-local caches and G8 evidence. Each first-seen page is recorded before limit/provider refusal, successful admissions consume exact sealed byte charges, and cached rereads consume nothing. G9 validates generations before/after materialization and at checkpoints even with no page read. Faults are sticky. The guarded evaluator samples readiness before evaluation and after materialization.
4. G10 summaries describe PHYSICAL sealed tables, in each page's LOCAL id space. Graph postings are derived per physical stream. Summaries are exact for those physical counts, and cardinality estimates use metadata rather than residency. Per-axis exactness does not mean conjunctions or removal-adjusted logical counts are exact.
5. `MutableDataset` accepts only a frozen native `Arc<RdfDataset>` base, not an arbitrary paged base. Its `snapshot_view` freezes the head delta while borrowing the base and builds sparse aliases by value. `DeltaDatasetView` is a useful behavioral precedent, not a ready stack implementation.
6. `DeltaDatasetView` explicitly reclassifies RDF 1.2 rows: adding a reifier for `(subject, graph)` moves existing ordinary rows to annotations; removing the last surviving declaration moves surviving annotations back to ordinary rows. Its graph-scoped overrides preserve layer-local stream narrowing and deduplication. A plain concatenation/mask of page tables cannot inherit this behavior.
7. Existing `PagedDataset::compact` only canonicalizes global dictionary numbering and remaps translations. It preserves page contents/local layouts, provider generation, and page boundaries. It cannot fold removals or establish the requested stronger page-byte identity.
8. `tests/paged_backend.rs::compacted_paged_serializes_byte_identical_to_single` checks canonical Turtle after materialization, explicitly noting the absence of a standalone paged serializer. This is NOT page-byte compaction evidence. `PackBuilder::build_bytes` and `build_view_bytes` offer actual deterministic carrier bytes, with fallible checkpoints and RDF 1.2 side tables.
9. `DatasetMut` is sealed to `MutableDataset`; its remove/contains contract is an infallible boolean, and insert errors only for invalid IRI admission. A mutable paged facade cannot report unknown lower-layer membership as false. It needs an explicit operational error boundary if membership can touch fallible storage.

## Design risks that must be resolved in the plan

### Ordered removals, reinsertion, and duplicate fact identity

A single unordered `union(all additions) - union(all removals)` loses a newer reinsertion. The semantic fold is ordered: each layer applies its own removals to older data, and newer additions remain above old removals. Snapshot-wide storage is possible only if it retains equivalent sequence/version information. Define within-batch precedence, because insertion and removal of the same q cannot be read as two simultaneous unordered sets without a rule. Equal effective facts across layers are one dataset fact, while SPARQL solution multiplicity still follows normal bag semantics. G3 forbids overlaps inside one sealed generation; ordinary overlaps across successive generations must have explicit effective-set semantics. Rejecting every later generation that contains an earlier fact would prevent benign repeated ingest and must not substitute for the requested stack semantics.

### RDF 1.2 overlay classification and summary admission

The effective row classification depends on whether ANY surviving reifier declaration exists for `(subject, graph)` across the stack, not on the physical table where a page sealed the row. Removing one of several declarations must retain annotations; removing the last must expose ordinary quads. Adding a declaration after an older page sealed ordinary quads must expose annotations. Graph slots participate in classification: a declaration in g1 must not classify g2/default rows. Include declarations and annotations living in different pages AND layers, and declaration/annotation additions in either order.

G10's existing base subject/predicate/object counts must not prune demoted physical annotation rows that became logical base rows. Conversely, annotation graph/reifier admission must include relevant physical base rows promoted by an upper declaration. A trustworthy implementation either composes the appropriate physical stream admissions and post-read classification or maintains separately certified metadata with a clearly justified producer; it cannot relabel old physical counts as exact logical counts. Sealing/reading an ordinary-only fixture will miss this defect.

### Snapshot and evidence addressing

`PageGeneration` and `PageId` are only meaningful with their layer/provider. Two unrelated in-memory layers may have the same generation number and dense page ID. Evidence needs a layer-qualified page address and the ordered sealed snapshot descriptors, plus a head/removal publication identity; generation equality alone cannot distinguish changed logical stacks. Check every provider at checkpoints, even one with no candidate page. A fault in any layer gates ALL later data, including metadata-only named graph enumeration and head rows; independently sticky per-layer views cannot by themselves prevent another layer yielding after failure.

Limits are whole-operation limits. Granting each layer the same `PagedQueryLimits` independently permits depth-times-budget consumption. Aggregate receipts must count global first admission, include unsuccessful first requests, retain deterministic evaluation order, and guard overflow. No budget/probe may consult shared resident caches as proof that this operation already consumed a page.

### Mutation over fallible lower storage

C4 boolean mutation semantics require knowledge of effective membership. With a lazy fallible base, membership failure is neither absence nor a no-op. Use typed fallible operations/read sessions when membership is inspected; do not create a native flat base to reuse `MutableDataset` at every head publication. Such materialization would evade the incremental mechanism being requested. Freezing the HEAD alone is expected; draining the whole stack is explicitly paid compaction only.

### Canonical page bytes need a published construction law

The effective set does not uniquely determine arbitrary historical page partitions. Page-byte identity needs a deterministic page partition and canonical term/row construction law, with any caller page-size parameter applied identically to stack compaction and eager seal. State this concretely, then compare per-page bytes. A single output page can be a valid explicit reference policy if justified for this demonstrator, but tests cannot claim identity for arbitrary partitions from a flat serializer. Canonical IDs are a separate claim from canonical serialized bytes, since an encoder can canonicalize differing input IDs.

Compaction must walk surviving rows and recursive dependencies, not retain every term from every old translation: removed-only values are dead. RDF 1.2 side tables, literal datatypes, nested triple components and empty named-graph declarations all contribute live values. Fallible draining must use before/after checkpoints and publish no partial new base on failure. Caller-owned atomic publication does not excuse returning an incomplete fold.

### Cost, scope, and portability

Appending a delta may inspect sealed dictionaries/metadata to build aliases; it must not read/reseal existing page contents. Document the retained-memory/work cost of the chosen alias strategy rather than implying an O(delta) operation when it scans/clones all base terms. Query reads must remain lazy and graph/selective paths must preserve G10 narrowing. Depth/when to compact, durable layer storage, and consumer log are explicitly consumer-owned; no filesystem, threads, clocks, model actions, features, runtime dependencies, or persistence implementations are needed here.

Preserve capabilities honestly, especially named graph presence after removals and RDF 1.2 side table representation. Explicit declared-empty graphs are observable through `GRAPH ?g {}` and must survive the selected documented graph lifetime policy and compaction. Locations/non-RDF sidecars need an explicit ownership statement matching the existing seam rather than an unsupported losslessness claim.
