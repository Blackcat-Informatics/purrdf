## Required behavior and actual defect

The issue requires two connected repairs: fresh blank identity per resolved LOAD document, including nested triple terms and CDT-contained blank references; and additive typed record transfer preserving ordinary, reifier and annotation physical surfaces through ADD/COPY/MOVE in both existing graph-existence modes. Public API changes must remain purely additive. Required failing-first Rust tests, actual cargo semver-checks, make check and make wasm are binding acceptance, not optional follow-ups.

Current `crates/sparql-eval/src/update.rs` still has the defect. Its load function at935 has neither the request counter nor mint-prefix options. After resolver/stop admission it wraps the resolved Arc in MutableDataset, obtains value-only quads, charges their count and calls ordinary insert after graph rekeying. No source blank identity is rewritten. graph_op_add/copy/move at1129 onward similarly snapshot `quads_of_target` and call ordinary insert; MOVE removes by the same flattened values. Copying labels into another graph is appropriate for transfer, but retaining labels across independent LOADs is not.

Core `ir/mutable.rs` stores added/suppressed/ordinal membership using QuadKey with no physical role. base_occurrences at590 counts three distinct tables under that one key. insert_rows at651 restores every suppressed physical occurrence for equal values; remove_rows at718 can return after removing one delta row. append_delta at1078 reconstructs roles from rdf:reifies-shaped values and effective graph-scoped declarations. DeltaDatasetView also classifies exposed rows. Adding a role field at the public edge and discarding it through ordinary insert would therefore leave the central defect intact.

`ir/import.rs::DatasetImporter` already replays ordinary, reifier and annotation streams separately, with one iterative term memo and graph declarations. `ir/term_walk.rs::TermValue::try_fold[_owned]` and visit_blank_identities, `cdt_blank.rs::rewrite_cdt_blank_terms`, blank_label encoding and update::mutable_mint_prefix/destination_mint_prefix are existing homes to reuse. No second classifier, blank scanner, recursive term mapper or flattened freezer is needed.
