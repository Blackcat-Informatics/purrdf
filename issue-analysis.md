## Primary implementation evidence about the oracle

The repository lock pins rdflib 7.6.0 with exact wheel/source digests. Existing `conftest.py` imports genuine rdflib separately from `purrdf.compat.rdflib`, and `test_rdflib_version.py` checks shim/lock version agreement. Read-only inspection of the root environment's installed rdflib files supplied implementation evidence, not executed parity or a new installation. Their actual runtime version still needs a check in the executed oracle environment.

`rdflib/plugins/sparql/evaluate.py:124` evaluates Extend over its inner rows and merges `{target: evaluated_value}` into each row. Evaluation errors yield the old row rather than dropping it. `sparql.py:198` implements FrozenBindings.merge by chaining the old items and then incoming items, so later values replace earlier ones.

`evalLazyJoin` thaws a left mapping into the right context, then returns `b.merge(a)`: the left mapping can restore a target the right assigned. `evalLeftJoin` does the same and additionally retries the RHS under a remembered left scope before choosing the unmatched row. `evalMinus` evaluates both operands independently, then performs mapping subtraction. `FrozenBindings.forget` explicitly retains initBindings. `FrozenBindings.__getitem__` falls back to initBindings when a key is not in the local mapping. rdflib's algebra translator constructs Extend/Join/LeftJoin/Minus structurally from groups and extracts group filters.

Consequently a global name replacement, replacement of all variable reads with one COALESCE expression, indiscriminate constant propagation, or one unconditional override after all joins cannot establish the requested semantics. Assignment has a local mapping value and surrounding operators have incoming mapping/context behavior. SELECT projection, grouping, EXISTS expression scopes and repeated assignment have to compose with those rules. Differential execution must decide exact behavior; this analysis does not infer complete answers from source excerpts.
