# Fusion storage source review

Status: SOURCE REVIEW PASS for the reviewed delta after the failure-latch correction. Runtime acceptance remains NOT MET. This is a read-only review of the current storage, ordering, capability-routing, typed-failure and retained-contribution delta. It is not completion acceptance for the five-issue delivery. No build, lint, test, benchmark or portable check was run by this reviewer.

## Failure-state finding: resolved in source

The initial source review found that newly fallible operations in `crates/retrieval/src/fusion_stream.rs`, `pull`, `refile`, `observe_exclusions`, `next` and `trailer` could fail after the frontier and selection index had been changed without the public engine retaining a terminal native failure.

For example, `pull` removes an existing candidate's `RankKey` with `selection.take` before `seen_streams.insert`, admitted contribution growth, new signature construction and destination `selection.insert` can refuse. The candidate then remains in the frontier without its selection entry. Emission similarly removes the frontier candidate before fallible `unfile`, the wide tie bitset, emitted-table insertion and the returned contribution control are settled. A caller retrying the same public `FusionStream` after such an error can encounter the missing index, skip a previously removed candidate or request a successful trailer from an invalid run. Physical allocator refusal need not make the workspace's operational account sticky, so the workspace failure flag alone does not establish a terminal stream law.

The latest source introduces `terminal_failure: Option<EvalError>` and public `next`/`trailer` wrappers around their original inner bodies. Each wrapper checks the retained failure before initialization or any producer callback. On the first inline `FusionError::NativeFailure`, it retains that original cause; later calls return the retained cause without entering either inner body. Both wrappers share one latch, so a failure in either entry blocks both. A successful trailer leaves the latch empty and preserves the original subsequent `next` behavior. Actual layout/admission/allocator errors are inline markers or immutable retained native diagnostic handles, so this physical-failure path does not construct a fresh rendered diagnostic.

The new `original_native_refusal_stops_repeated_pulls_and_successful_trailers` fixture traverses the public engine and a producer's real `next` callback, asserts the original allocation-failure construct on the first/repeated `next` and on `trailer`, and checks that callback entry remains exactly one. This fixture was read, not executed. Consolidated qualification still needs the admitted array/index/result-control refusal and lifetime controls; the new producer fixture alone is not proof of every physical owner.

## Findings corrected during this source review

- `crates/retrieval/src/error.rs`, `From<ProtocolError> for FusionError`, previously always allocated `Box::new(error)`, including a native failure received through `fetch`, `exclusion`, `receipt` or `settle`. The latest source explicitly maps `ProtocolError::NativeFailure(error)` to inline `FusionError::NativeFailure(error)`. This removes that post-refusal allocation and preserves the original cause through `Error::source`.
- The original flat selection oracle indexed the newly admitted map through a missing `Index` implementation; it now uses its borrowed lookup. `assert_filed` now unwraps the resident signature result and uses `contains_key`. The independent oracle and filing assertion remain present.

## Source judgments

- `RankKey::Ord`, `RankProbe` and `Borrow<dyn RankOrder>` use the same `rank_order`: descending score, ascending best rank, ascending canonical term spelling. The shared `OrderedTable` seeks with that borrowed ordering. The inclusive `(score, 0, "")` lower bound in `has_final_rival_at` still finds a same-score rival before any lower score. `first_key_value`, member walking and the flat frontier walk therefore retain the original order. No ordering or range defect was found in these changes.
- `SelectionIndex::take` moves the original stored key through `remove_entry`; it does not manufacture a new candidate key. An emptied group is removed only after its stored key has been extracted. New groups and their member arenas use the same original `groups.workspace()`.
- `StreamSet::Ord` preserves the original enum discriminant order and lexicographic word order. `Wide` now retains an admitted word array; `signature`, `open_streams` and tie checks propagate its physical errors. Narrow sets remain inline. Every set within one fusion retains the same width.
- Candidate namer/asked/excluded sets and Allowed duplicate sets retain numeric or lexical key order through the same shared ordered home. Emitted records move the original candidate sets instead of cloning or rebuilding them. The emitted hash array uses the existing `AdmittedMap` and the selected original capability.
- `RankedStreamImpl` native materialized and on-demand constructors retain the actual execution capability. `RankedStreamAdapter::workspace` shallow-forwards it. First-party `execute_bound` establishes one `execution_workspace` and clones it into each native stream; `FusionStream::new` selects that original account even if preceding caller streams report `None`. Its resident choice is used only when no stream supplies a native account. The table/frame declaration order and intrinsic term owners preserve admitted storage until payload destruction. No capability-substitution or lifetime defect was found on this production route.
- Candidate contributions now grow in the existing `AdmittedVec` through its fallible `push` before mutation. Emission moves that same vector, sorts its admitted slice in place with the existing lexical stratum/rank comparator, and publishes it through `SharedWorkspace::new_admitted`. The vector buffer grant and each intrinsic IRI owner remain with the original payload; the separately admitted Shared control is destroyed after its value. `SharedWorkspace::Clone` copies only its immutable handle. The new `PartialEq` implementations compare payload values while ignoring ownership identities, and borrowed `IntoIterator` implementations return the original borrowed payload/slice iterator. None clones an array or detaches its grant. This judgment covers the contribution carrier, not the unfinished remainder of `FusedRow`/trailer payloads.

The still-changing constructor tables, trailer/report payloads, result collections, block witnesses and other fusion buffers were not certified by this focused judgment. Their eventual complete native owner migration and consolidated native/portable acceptance remain required by the delivery plan. In that qualification, retain the original selection differential and allocation controls; cover 64/65-stream behavior, borrowed equal-score range ties, duplicate and exclusion transitions, map growth/refusal, original account routing and retained output destruction.
